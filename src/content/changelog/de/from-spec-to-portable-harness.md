Bis jetzt war Deep Work Plan ein Plan-Loop, dem ein einzelner Agent innerhalb einer Sitzung folgte. Diese Reihe von Releases macht daraus etwas, das ein Repository sich zu eigen machen kann — die erste Version, die bewusst über einen einzelnen Agenten und eine einzelne Sitzung hinausgeht.

Der Skill erhält eine Vertrauenserklärung mit prüfsummengesichertem Herkunftsnachweis, sodass Entwickler genau sehen, was er liest und schreibt, bevor sie ihn installieren. Onboarding-Presets und unterstützte Agenten-Hosts wachsen deutlich, Testdisziplin wird zu einem festen Bestandteil jeder Aufgabe statt einer Nebensache, und ein Konformitätsprüfer lässt ein Repository objektiv überprüfen — statt es nur anzunehmen —, dass es dem Standard entspricht. Ein Zustands- und Fortsetzungsprotokoll sorgt dafür, dass ein unterbrochener Plan dort weitermacht, wo er aufgehört hat, statt von vorn zu beginnen. Im Hintergrund laufen die Kompatibilität von `.claude` und `.cursor` in einem einzigen kanonischen `.agents`-Verzeichnis zusammen, sodass jeder unterstützte Agent denselben Kit liest.

Zusammen legen diese Releases das Fundament für den nächsten Schritt: Das Repository ist nicht mehr nur der Ort, an dem der Plan gespeichert wird — es wird zum Arbeits-Harness des Agenten.
