# Loop engineering

**สเปกมาก่อน ปิดลูปในตัว: repository คือ harness และแผนจะเดินหน้าเองจนเสร็จ** บทนี้อธิบายกลไกเสริมที่ช่วยให้แผนเดินหน้าต่อหลังรอบการทำงานแรก แผนยังคงเป็นข้อกำหนดที่ถาวร ลูปให้ความต่อเนื่อง ไม่ได้ให้อำนาจใหม่

## ลงทะเบียนแผน

เมื่อเปิดใช้ส่วนเสริม Herdr โฟลว์ `execute` ของ pack จะอ้างสิทธิ์บันทึก lead ของแผน (และ `resume` จะอ้างสิทธิ์อีกครั้ง) โดยเพิ่มลำดับการสืบทอดเมื่อแผนระบุผู้สืบทอดไว้ การสลับไปยังผู้สืบทอดเมื่อเกิดความล้มเหลวทำได้เฉพาะเมื่อมีลำดับการสืบทอดที่บันทึกไว้ บันทึกนี้ระบุแผน lead ปัจจุบัน epoch และผู้สืบทอดตามลำดับให้ลูปติดตามได้อย่างแม่นยำ แผนที่ไม่มีบันทึก lead จะไม่ถูกเฝ้าดู ส่วนเสริมนี้เป็นตัวเลือก หากไม่มี วิธีการหลักยังทำงานได้ในเซสชันเดียวหรือผ่านการส่งต่องานที่มนุษย์ประสาน

การลงทะเบียนแผนไม่ใช่การอนุมัติงานและไม่ขยายการอนุญาตของแผน ใน v8 แผนที่อนุมัติแล้วจะทำงานจนจบภายในอำนาจที่บันทึกไว้ในแผนนั้น เกณฑ์การยอมรับและ gates ยังคงมีผลผูกพันตลอดการดำเนินงาน

## มนุษย์เริ่ม daemon

มนุษย์เริ่ม `herdr-peers autopilot --loop` ในสภาพแวดล้อม Herdr นี่คือ daemon เบื้องหลังในเครื่อง ไม่ใช่รายการเข้าสู่ระบบหรือบริการของระบบ daemon ติดตามแผนที่ลงทะเบียนไว้บนทุกเครื่องที่เปิดใช้งาน และเตือน lead ที่ว่างอยู่ให้ทำต่อเมื่อแผนยังเปิดอยู่ ไม่มี lane ใดกำลังทำงาน และไม่มีคำตอบที่รออยู่ ข้อความเตือนเป็นข้อความคงที่ คือให้ทำแผนที่อนุมัติแล้วจนจบโดยเคารพ gates และอำนาจที่บันทึกไว้

daemon ไม่แตะการเข้าสู่ระบบ การขอข้อมูลรับรอง หรือการยืนยัน bypass-permissions ของ Claude และจะไม่เลือกตัวเลือกปฏิเสธ ตัวเลือกข้อความอิสระ หรือแถวที่ขยายสิทธิ์ของ agent การเตือนเพียงขอให้ agent ทำต่อ ไม่ได้เพิ่มอำนาจ lead ยังคงบันทึกสิ่งกีดขวางและทำตาม gates ของแผน หลังเตือนสามครั้งโดยไม่มีความคืบหน้า daemon จะหยุดเตือนและรายงาน `plan_stalled`

## ควบคุมการนำแผนอย่างมีขอบเขต

หาก lead หายไป daemon จะขอให้ผู้สืบทอดในรายการคนแรกที่ติดต่อได้ทำขั้นตอน takeover บันทึก lead จะเลื่อน epoch และผู้รับจะบังคับใช้ลำดับการสืบทอด protocol 2 รองรับการแต่งตั้ง lead ด้วย แต่เฉพาะเมื่อมนุษย์บันทึกการอนุญาตไว้ในแผน (`lead claim --allow-appointment`) และเริ่ม daemon ด้วย `--appoint` แล้วเท่านั้น daemon ให้สิทธิ์นี้เองไม่ได้ ก่อน merge, tag หรือ release ทุกครั้ง lead ปัจจุบันจะรัน `herdr-peers lead verify --plan <id>` เพื่อตรวจบันทึกบนทุกเครื่องของแผน

ผู้สืบทอดรับช่วงแผนและ gates ของแผน ทั้งการสืบทอดและการแต่งตั้งไม่เปลี่ยนเกณฑ์การยอมรับ และไม่อนุญาตงานนอกอำนาจที่บันทึกไว้ หากแผนถึง gate ที่ต้องให้มนุษย์ดำเนินการตามกฎ C1–C7 ลูปจะรายงานความต้องการนั้นและหยุดที่ gate นั้น ข้อมูลรับรองและการเข้าสู่ระบบก็ยังเป็นหน้าที่ของมนุษย์ ความคืบหน้าอื่น ๆ จะแจ้งให้มนุษย์ทราบโดยไม่ต้องคอยเฝ้าทุกขั้น

## brain และคิวแบบเลือกได้

`--brain` แบบเลือกได้จะเริ่ม agent ตัดสินใจโดยเฉพาะ สำหรับกรณีที่กฎของ daemon ตัดสินไม่ได้ ต้องใช้ coding-agents-kit 1.3.0 ขึ้นไป หากไม่มี daemon ที่เริ่มด้วย `--brain` จะไม่ยอมเริ่มทำงาน brain เลือกได้เฉพาะจากรายการการกระทำแบบปิดที่ daemon กำหนดไว้สำหรับแต่ละกรณี ได้แก่ เตือนอีกหนึ่งครั้ง ส่งคำขอคงที่หนึ่งครั้งให้ lead แก้สิ่งกีดขวางที่แผนระบุว่า lead แก้ได้ แจ้งมนุษย์ หรือปล่อยไว้ daemon ยังคงเป็นผู้กระทำเพียงรายเดียว: ตรวจสอบตัวเลือกและดำเนินการที่เข้าเกณฑ์ โดยไม่เรียกใช้ข้อความอิสระของ brain เลย ใน v8 แผนยังบันทึกไว้ในบล็อก autonomy ด้วยว่า brain ทำการกับแผนนั้นได้หรือไม่

คิวของแผนใช้เอกสาร `dwp-queue-v1` ที่ `.dwp/queue.json` เครื่องมือของแผนเป็นผู้เขียน ส่วน daemon เป็นผู้ใช้แบบอ่านอย่างเดียวที่มีขอบเขต แผนในคิวจะพร้อมเมื่อ dependency `after` เสร็จแล้ว (หรือไม่มี) และการอนุมัติยังมีผล daemon เริ่มแผนได้ด้วยการส่งข้อความคงที่หนึ่งข้อความถึง lead ที่คิวระบุเท่านั้น: “Plan P is next in the queue of the repository at "R" and approved. In that repository, run the plan tool's execute flow for it (its start gate checks the approval again) and execute it to its end, respecting its gates.” ลูปนี้ไม่เริ่มรายการ `launch` สถานะคิวได้รับการดูแลโดย pack ระหว่างการดำเนินงานและการปิดงาน

## รายงานและสังเกตการณ์

เหตุการณ์ของแผนครอบคลุมแผนที่หยุดชะงัก ถูกบล็อก สูญเสีย lead หรือเสร็จสิ้น และแผนในคิวที่เริ่มหรือเริ่มไม่ได้ คำสั่ง `--notify` แบบเลือกได้จะรับออบเจ็กต์ `plan-event-v1` สำหรับเหตุการณ์ที่รองรับ และ notifier ของ Dailybot ใน pack จะแปลงเป็นอัปเดตสำหรับทีม การแจ้งเตือนรายงานความคืบหน้าหรือสิ่งกีดขวาง ไม่ได้อนุมัติการกระทำหรือแทนที่บันทึกของแผน

รายงาน fleet และ `herdr-peers fleet ui` แสดง agent และแผนบนหลายเครื่อง รวมถึงงานที่ต้องการความสนใจ UI เป็นแบบอ่านอย่างเดียว ไม่เขียนสถานะแผนและไม่ส่งข้อความเตือนถึง agent ใด ช่วยให้มนุษย์เห็นสถานะของลูปโดยไม่กลายเป็นระนาบควบคุมอีกชุดหนึ่ง

## ขอบเขต

Loop engineering ปิดลูปการทำงานรอบข้อกำหนดที่อนุมัติแล้ว ทำให้การทำต่อ การสืบทอด และการรายงานเป็นงานประจำ ขณะที่แผนยังคงเป็นแหล่งอำนาจและ daemon ยังอยู่ในขอบเขต มนุษย์เริ่ม daemon จัดการข้อมูลรับรองและการเข้าสู่ระบบ และแก้เฉพาะ gates C1–C7 ของแผนเองหรือความต้องการอื่นที่อำนาจที่บันทึกไว้รองรับไม่ได้ เป้าหมายของลูปคือให้แผนที่อนุมัติแล้วไปถึงจุดสิ้นสุดที่กำหนดโดยไม่ต้องมีมนุษย์คอยเฝ้า
