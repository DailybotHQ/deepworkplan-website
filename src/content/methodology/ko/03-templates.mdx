# 계획과 작업 템플릿

Deep Work Plan은 Markdown 파일들의 디렉터리입니다. 그 디렉터리의 형태 — 그리고 그 안의 각 파일의 형태 — 가 계획을 사람과 에이전트 모두에게 검토 가능하게 만듭니다.

## 계획 구조

<PlanTree lang="ko" class="not-prose my-10" />

계획은 `PLAN_<slug>/`라는 이름으로 `.dwp/plans/` 아래에 있는 디렉터리입니다. 다음을 담습니다.

- `README.md` — 계획 개요: 목표, 원천 자료, 작업 표, 상태.
- 작업당 하나의 파일, `<n>.task_<slug>.md` 형식의 이름.
- `PROGRESS.md` — 실행의 진행 로그.

## 작업 파일 구조

각 작업 파일은 `<n>.task_<slug>.md`라는 이름이며 열 절 구조를 따릅니다. 목표, 컨텍스트, 변경 표면(Touched Surface), 단계, 인수 기준, 검증, 파일, 의존성, 리스크, 완료 & 로그입니다. 이 절들은 언제나 그 순서로 나타나므로 어떤 독자든 어디를 봐야 할지 압니다. 각 작업은 행동하기 전에 계획의 목표에 다시 닻을 내리며, 이는 에이전트가 길고 여러 시간에 걸친 과정에서 방향을 잃지 않게 합니다.

## Final Review

모든 계획은 정확히 하나의 필수 작업으로 끝나야 합니다: **Final Review**입니다. 세 번의 순서 있는 패스로 계획을 닫습니다 — 보안 점검의 어떤 부분도 완화되지 않습니다:

1. **보안 점검** — 계획이 변경한 모든 것을 비밀 값, 인젝션 위험, 새로운 공격 표면에 대해 감사하고, `docs/SECURITY.md`를 최신 상태로 유지합니다. 보안은 마지막에 덧붙이는 별도의 작업 흐름이 아닙니다. 모든 계획은 자신의 변경을 감사된 상태로 남기며, 치명적인 발견은 완료를 차단합니다.
2. **최종 상태 검증** — 마지막 수정 이후의 최종 관련 상태에서 리포지토리의 전체 검증이 실행되어 통과합니다.
3. **스킬 조정** — 각 작업은 자신의 증거가 신선할 때 자신만의 스킬 처분을 기록했습니다; 리뷰가 원장을 조정합니다. 임원 보고서는 요청 시 여전히 이용 가능합니다.

## README와 PROGRESS 관례

계획 `README.md`는 제목(`# Deep Work Plan: <name>`), 산문 형태의 목표 진술, 선택적 원천 자료 절, 작업 표(번호, 작업 이름, 상태 체크박스), 그리고 `<n>/<total> tasks complete` 형식의 계획 상태 줄을 담아야 합니다.

`PROGRESS.md`는 추가 전용 실행 로그입니다. 각 항목은 ISO 8601 타임스탬프, 작업 번호와 이름, 수행한 일, 그리고 모든 이탈이나 건너뜀 이유를 기록합니다. 오직 늘어나기만 하므로, 계획이 실제로 어떻게 전개되었는지의 신뢰할 수 있는 이력입니다.

## 제목과 상호 참조

모든 제목은 문장형 대소문자(sentence case)를 사용하며, 문서는 마케팅 표현과 느낌표를 피합니다. 이 관례는 에이전트 전반에 걸쳐 그리고 시간이 지나도 계획을 일관되게 유지합니다.
