# 計画とタスクのテンプレート

Deep Work Plan は Markdown ファイルのディレクトリです。そのディレクトリの形、そしてその中の各ファイルの形こそが、計画を人とエージェントの双方にとってレビュー可能なものにします。

## 計画の構造

<PlanTree lang="ja" class="not-prose my-10" />

計画は `.dwp/plans/` 配下の `PLAN_001_<slug>/` という名前のディレクトリです。次のものを含みます。


- `manifest.json` — 計画のマニフェストとメタデータ。
- `contract.json` — 計画の仕様契約とスコープ。
- `journal.ndjson` — 追記専用のイベントジャーナル。
- `state.json` — 現在の実行状態とキャッシュ。
- `README.md` — 計画の概要、目標、タスク表、進捗状況。
- `PROGRESS.md` — 人間可読な時系列の実行ログ。
- `<n>.task_<slug>.md` — 各タスクの十の節からなる仕様ファイル。
- `analysis_results/` — 分析成果物、レポート、ゲートログの格納ディレクトリ。

現在の 7.x パックは v7 計画を既定で作成し、その slug は v6 と同様に 2〜5 語です。保存された v5 フローは 2〜4 語を使用します（凍結されたスキーマで数値 ID を1語としてカウントするため）。新しい計画には 3 桁以上の単調増加する数値 ID が付与されます（例：`PLAN_001_add_payment_webhooks/`）。既存の番号なし `PLAN_<slug>/` ディレクトリは引き続き読み取り可能で名前変更は行われません。既存の計画が暗黙的に移行されることはありません。番号付き計画が存在する場合、`latest` は最大の数値 ID を持つ計画を指します。

## タスクファイルの構造

各タスクファイルは `<n>.task_<slug>.md` という名前で、インストールされたスキルで定義された十の規範的セクションに従います（タスク構造の詳細は[中核ループ](/ja/methodology/02-core-loop)を参照）。各タスクは行動の前に計画の目標へと改めて立ち返り、これにより、長時間に及ぶ作業を通じてエージェントが逸脱するのを防ぎます。

## Final Review

すべての計画は、唯一の必須タスクで締めくくらなければなりません。すなわち **Final Review** です。五つの順序づけられた段階で計画を完結させます — セキュリティ監査と検証ゲートで緩められるものは何もありません：

1. **セキュリティパス** — 計画が変更したすべての内容をシークレット、インジェクションリスク、新たな攻撃面について監査し、`docs/SECURITY.md` を最新に保ちます。`.agents/skills/ai-diff-reviewer/` および拡張ファイルが存在する場合は、必須のローカルレビューを実行します。重大な発見事項は完了を阻止します。
2. **最終状態検証** — すべての適用可能なテスト、リント、型チェックのスイートが、最終状態に対して実行されて合格します。レビュー中の修正は影響を受けた結果を無効化し、再実行をトリガーします。
3. **スキルの突き合わせ** — 各タスクがタスク局所的なスキルの判断を記録していることを検証し、`analysis_results/SKILLS_CANDIDATES.md` で実用的なスキルの作成候補を照合します。
4. **ドキュメントの突き合わせ** — 動作を変更した各タスクの変更対象面を、その機能を記録するドキュメント（`docs/TESTING_GUIDE.md`、アーキテクチャドキュメント、`AGENTS.md`）と突き合わせて同期します。
5. **完了と終了** — 最終的な状態投影と生成された成果物の整合性を検証し、`analysis_results/FINALIZATION.json` 完了レシートを書き込んで正式に計画を終了します。

## README と PROGRESS の規約

計画の `README.md` は、タイトル（`# Deep Work Plan: <name>`）、散文での目標の記述、任意の出典資料の節、タスク表（番号、タスク名、状態のチェックボックス）、そして `<n>/<total> tasks complete` という形式の計画状態の行を含まなければなりません。

`PROGRESS.md` は追記専用の実行ログです。各エントリには、ISO 8601 のタイムスタンプ、タスクの番号と名前、行ったこと、そしてあらゆる逸脱やスキップの理由を記録します。常に増えるだけなので、計画が実際にどう展開したかの信頼できる履歴になります。

## 見出しと相互参照

すべての見出しはセンテンスケースを用い、ドキュメントはマーケティング的な言い回しや感嘆符を避けます。これらの規約は、エージェントをまたいでも時間が経っても、計画を一貫したものに保ちます。
