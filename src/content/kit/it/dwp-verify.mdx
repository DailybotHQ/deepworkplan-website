# dwp-verify

Verifica in modo oggettivo la conformità di repository e piani — sola lettura.

<CmdVerify lang="it" class="not-prose my-8" />

## Cosa fa

`dwp-verify` verifica, in modo meccanico, se un repository è AI-first (conforme a DeepWorkPlan) e se i suoi piani sono ben formati, poi riferisce l’esito positivo/negativo. Non cambia nulla.

## Uso

```
/dwp-verify            # verifica il repository
/dwp-verify plan auth  # verifica anche un piano specifico
/dwp-verify all        # repository + ogni piano
```

## Comportamento

1. Verifica il repository: `AGENTS.md` con comandi reali ed eseguibili; risoluzione di `CLAUDE.md`; categorie `docs/`; catalogo `.agents/` che corrisponde al disco; sottili delegatori `dwp-*`; `.dwp/` e `tmp/` esclusi da git; una skill risolvibile.
2. Verifica un piano (quando richiesto): ogni attività ha criteri di accettazione e un validation gate, i progressi sono persistiti, il Final Review registrato è presente (il suo passaggio di sicurezza incluso) e le attività si riancorano all’obiettivo.
3. Riferisce **CONFORMANT** o **NOT CONFORMANT** con ogni fallimento elencato.
4. Propone di catturare le lacune come un Deep Work Plan; non corregge mai in silenzio.

**Convalida dei piani per generazione.** Il controllo di provenienza del repository accetta lo standard DWP attuale 7.0.0, ma i controlli sui piani restano specifici per generazione. Un piano v6 o v7 si identifica tramite puntatore al contract, `contract.json` o catena di revisioni `contracts/` ed è verificato con i validatori v6 di contract, journal e ledger. Il validatore mantenuto `plan_contract.py` supporta solo v5 e NON DEVE essere usato per convalidare piani v6. In v6 `state.json` è una proiezione snapshot generata; una differenza rispetto al journal è un rilievo. Le due generazioni coesistono e la verifica non ne migra nessuna.
