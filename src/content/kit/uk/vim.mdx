# DeepWorkPlan Vim

**DeepWorkPlan Vim** — термінальний редактор для Deep Work Plan: конфігурація Neovim для людей і для програмувальних агентів, які працюють у терміналі. Ваші плани, документація та індекс усіх команд — на відстані одного натискання клавіші.

Це окремий необовʼязковий продукт. Він не встановлює навичку Deep Work Plan і не вимагає її та не входить в онбординг DWP v6. Ви додаєте його на машину окремо, і він працює як редактор незалежно від того, чи є план.

## Навіщо термінальний редактор для Deep Work Plan

Deep Work Plan — це тека з Markdown у `.dwp/plans/`: мета, атомарні завдання, validation gates та журнал, що постійно ведеться. Люди переглядають його, агенти виконують, і ті й інші часто роблять це з терміналу. Редактор, створений для такої роботи, тримає поруч три речі: сам план, документацію навколо нього та клавіші, що переміщують вас між ними.

DeepWorkPlan Vim — саме такий редактор. Це дбайливо підготовлена конфігурація Neovim — мовні сервери, автодоповнення, лінтинг, форматування, нечіткий пошук, дерево файлів і дібрані кольорові теми з відкладеним завантаженням — плюс кілька інтерфейсів, що роблять її редактором для Deep Work Plan.

## Огляд: індекс команд, який не може застаріти

Натисніть `SPC h h` (Пробіл — це лідер-клавіша) або виконайте `:DwpCommands`, і редактор виведе кожну свою привʼязку з однорядковим описом. Список створюється з актуальних розкладок клавіш, тож привʼязка, визначена будь-де, зʼявляється в індексі без реєстрації, а сам індекс не може застаріти.

Ось і весь огляд: запустіть `nvim`, потім натисніть Пробіл, `h`, `h`.

## Що ви отримуєте

Пʼять можливостей, кожна — на відстані одного натискання клавіші.

| Можливість | Клавіші | Що робить |
|---|---|---|
| Згенерований індекс команд | `SPC h h` | Кожна привʼязка конфігурації, створена з актуальних розкладок клавіш. |
| Жести у стилі VS Code | `<C-a>`, `SPC y` | Виділення всього файлу однією клавішею та копіювання до системного буфера обміну. Звичайна `y` теж копіює туди, бо буфер обміну спільний для всієї системи. |
| Оглядач планів Deep Work Plan | `SPC P` | Бічна панель за планами вашого репозиторію, згрупованими за станом і з індикаторами прогресу, та режим читання для одного плану. |
| Переглядач Markdown | `SPC m p`, `SPC m r` | Попередній перегляд Markdown у браузері або відтворення в буфері. |
| Встановлення одним рядком | — | Самодостатній інсталятор для macOS, Linux і WSL із задокументованим ручним шляхом для Windows. |

## Плани, не виходячи з редактора

`SPC P`, `:DwpPlans` або клацання по сегменту рядка стану відкриває бічну панель планів. Вона охоплює кожну теку `.dwp/plans/` у поточному каталозі та в каталозі конфігурації Neovim і групує плани, починаючи з тих, що потребують найбільше уваги. У редакторі мітки такі: `Working`, `Needs attention`, `Ready`, `Not started` і `Done`. Для кожного плану показано індикатор прогресу.

Натисніть Enter на плані, щоб відкрити режим читання: мету одним реченням, стан і прогрес, список завдань із позначеним поточним завданням і зрозумілі переходи до файлів самого плану. Рядок стану показує поточний активний план, а стартовий екран перелічує перші три. Ці інтерфейси пояснюють плани й ніколи нічого не записують у `.dwp/`.

Щоб читати Markdown-файли плану на місці, `SPC m p` показує поточний буфер у браузері, а `SPC m r` відтворює його всередині буфера. Обидва працюють лише в буферах Markdown.

## Встановлення

Усе встановлення — це один рядок. Його виконання встановлює те, що репозиторій зараз постачає в гілці `main`.

<VimInstall lang="uk">

```bash
curl -fsSL https://deepworkplan.com/vim/install.sh | bash
```

</VimInstall>

По порядку інсталятор:

1. Перевіряє вашу ОС і менеджер пакетів та встановлює git, curl і інтерпретатор Lua, якщо чогось бракує.
2. Питає, перш ніж торкатися наявної конфігурації Neovim. Якщо запущений через конвеєр без терміналу, зупиняється й нічого не змінює.
3. Клонує репозиторій у `~/.config/nvim` або оновлює його, якщо він уже там.
4. Запускає власний `lua install.lua` репозиторію.
5. Встановлює плагіни у фоновому режимі, тож виходити й відкривати заново не потрібно.

Щоб спершу прочитати скрипт, завантажте його командою `curl -fsSL https://deepworkplan.com/vim/install.sh -o install.sh`, порівняйте його SHA-256 зі значенням вище, прочитайте та лише потім виконайте `bash install.sh`.

## Вимоги та платформи

- Neovim 0.12 або новіший. Спершу встановіть Neovim: інсталятор його не встановлює.
- Lua: `lua`, `lua5.4` або `luajit`. Якщо його немає, інсталятор додасть.
- На macOS, Linux і WSL працює однорядкова команда. Для Windows у README репозиторію описано ручний шлях: встановіть Neovim через winget, клонуйте репозиторій у `%LOCALAPPDATA%\nvim` і запустіть `lua install.lua` з Git Bash.
- Ліцензія GPL-3.0: вільно використовувати, вивчати й змінювати.

## Оновлення, фіксація версії та видалення

Щоб оновити, запустіть інсталятор знову. Він ідемпотентний: наявний клон DeepWorkPlan Vim оновлюється через fast-forward, а локальні зміни ніколи не скидаються.

Щоб встановити певну гілку, тег або коміт, задайте `DWP_VIM_REF`. Старі теги можуть не містити всіх можливостей, описаних на цій сторінці.

```bash
curl -fsSL https://deepworkplan.com/vim/install.sh | DWP_VIM_REF=<branch-tag-or-commit> bash
```

Щоб видалити, виконайте `lua delete.lua` у каталозі конфігурації. Він видаляє конфігурацію, плагіни, дані Mason, кеш і стан, а також копію шрифту, зроблену інсталятором, і не чіпає виконуваний файл Neovim та ваші системні пакети.

```bash
cd ~/.config/nvim && lua delete.lua
```

## Запитання

### Чи перезапише він мою конфігурацію Neovim?

Ні, не без вашого схвалення. Коли він знаходить конфігурацію, що не належить DeepWorkPlan Vim, інтерактивний запуск питає, перш ніж перемістити її до `~/.config/previous-deepworkplan-vim`. Без терміналу або якщо цей шлях резервної копії вже існує, він зупиняється й нічого не змінює.

### Чи працює він у Windows?

Однорядкова команда в Windows не застосовується. Скористайтеся ручним шляхом із README репозиторію або запустіть цю команду всередині WSL.

### Чи потрібен мені Deep Work Plan, щоб ним користуватися?

Ні. Це передусім редактор. Він не встановлює навичку Deep Work Plan і не вимагає її; оглядачу планів просто нічого показувати, доки не зʼявиться тека `.dwp/plans/`.

### Як ним користуються програмувальні агенти?

Його створено для людей і для програмувальних агентів, що живуть у терміналі. Його привʼязки клавіш зафіксовано контрактними тестами, тому мʼязова памʼять і очікування агента переживають оновлення.

### Яку версію я отримаю?

Інсталятор встановлює `main`, якщо ви не задали `DWP_VIM_REF`. Ця сторінка описує те, що він встановлює; вона не привʼязує жодну можливість до номера версії.

### Під якою ліцензією він і звідки походить?

GPL-3.0. Він походить від mu-vim Andrés M Prieto, а вказівка авторства залишається в репозиторії.
