# Аддон Agentkit

Кожен термінальний агент для програмування має власні прапорці для продовження сесії, власний спосіб відокремити другий обліковий запис, власний headless-режим і власний перемикач для пропуску запитів дозволів. **[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** накладає на всіх них одну командну поверхню: `ak <kind> [@profile]`.

Цей аддон інтегрує kit у **DWP v7** (пакет `v7.6.1`) як **headless**-транспорт делегування. Він опційний: без нього кожне завдання виконується в поточній сесії, як і раніше. Сам kit — це продукт за ліцензією MIT, який працює без Deep Work Plan.

## Що дає kit

- **Одна граматика для кожного CLI.** `ak claude`, `ak codex`, `ak cursor`, `ak opencode`, `ak pi`, `ak cline` і `ak grok`, а також варіанти провайдерів (GLM, Azure, xAI), з тими самими прапорцями сесії: `-c` продовжує, `-r <id>` відновлює.
- **Профілі.** `ak claude @work` запускає другий обліковий запис у власному домашньому каталозі, відокремленому від першого.
- **Headless-запуски.** `ak run <kind> -- "<prompt>"` виконує один промпт неінтерактивно й повертає задокументований код виходу, за бажанням як один JSON-об’єкт.
- **Doctor.** `ak doctor --json` повідомляє, які CLI встановлено, профілі та назви заданих ключів — ніколи їхні значення.
- **Перевірене встановлення.** `ak install <cli>` встановлює відсутній CLI з офіційного каналу його постачальника в закріпленій версії, звіряючи її із закріпленим sha256 або з integrity з реєстру npm.
- **Звичні назви.** Два пресети псевдонімів, вимкнені, доки ви їх не ввімкнете: `classic` (`claudex`, `codexx`, `cursorx`, `opencodex`, `pix`, `clinex`, `grokx`) і `providers` (`claude-glm`, `codex-azure`, `codex-xai`, `pi-glm`, …), кожен із яких — це `ak <kind>`.

## Облікові записи, квоти та вибір облікового запису

Kit вважає кожен ваш вхід або ключ **обліковим записом**: один CLI × один профіль. `@default` (або `@1`) — власний home CLI; `@2`, `@work` чи `@client-x` — окремі входи, кожен у власному каталозі під коренем профілів, що працюють паралельно. `ak profiles` показує їх зі станом входу та назвами їхніх ключів; `ak profiles --json` віддає той самий список інструментам (схема `profiles-v1`).

`ak usage` показує квоту й використання кожного облікового запису, який бачить kit, — по рядку на обліковий запис і профіль: у реальному часі для підписок Claude Code (вікна 5 годин, тиждень і за моделлю), входів Codex через ChatGPT і ключів тарифу Z.AI для програмування; Cursor, Grok, xAI та Azure OpenAI показують `n/d` із причиною. Команда лише читає: вона ніколи не оновлює вхід, ніколи не виводить токен і ніколи нічого не записує в профіль. `--json` віддає той самий список інструментам (схема `usage-v1`). Ендпоінти використання — внутрішні й неофіційні API постачальників.

`ak pick <kind>` читає ті самі рядки й називає обліковий запис із найбільшим запасом. `--count N` повертає до N облікових записів, починаючи з найкращого; `--exclude @<profile>` виключає зайнятий; `--model` рахує тижневе вікно однієї моделі; `--need 5h:40` відмовляється обирати без такого запасу. `--json` віддає схему `pick-v1`.

```bash
ak usage                   # квота кожного облікового запису й профілю
ak pick claude --count 3   # три облікові записи Claude з найбільшим запасом
ak claude @work --trust-cwd  # другий обліковий запис, тека заздалегідь довірена
ak profiles --json         # profiles-v1, для інструментів
ak setup verify            # упорядковані перевірки, кожна з командою виправлення
```

`--trust-cwd` (або `AGENTKIT_TRUST_CWD=1`) заздалегідь робить довіреною теку, у якій стартує агент, тож Claude Code і Codex відкриваються без екрана довіри до теки. `ak setup probe | verify | docker` — помічник лише для читання, яким керує skill `agentkit-setup`: він оглядає машину, перевіряє встановлення й генерує закріплений за тегом і перевірений рецепт контейнера.

## Кілька агентів, кілька облікових записів

Skill `agentkit-orchestrate` (`ak --skill orchestrate`) навчає агента розподіляти роботу між кількома агентами, обліковими записами й постачальниками: один `ak usage` перед пакетом, `ak pick --count N` для вибору облікових записів, один делегат на обліковий запис, власний gate репозиторію для кожного результату та перемикання на наступний обліковий запис, коли один досягає ліміту. Kit спостерігає, обчислює й запускає; він ніколи не планує. Рішення ухвалює провідний агент — ви або агент, якого ви попросили, — використовуючи лише ваші власні облікові записи та в межах умов кожного постачальника.

Для довгих інтерактивних ліній кожна лінія працює в панелі [Herdr](/kit/herdr) на власному обліковому записі. Розділ методології [Запуск багатьох агентів](/methodology/06-orchestration) описує всю модель: провідний агент і його лінії, облікові записи, обрані за запасом, координація через herdr-peers, а також одна гілка й один реліз на репозиторій.

## Встановлення

```bash
git clone --branch v0.5.0 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

Вимоги: `bash` на macOS або Linux і `python3` 3.9 або новіший; більше нічого. Windows використовує `install.ps1`. Закріпіть `v0.5.0`: `v0.2.0` і `v0.2.1` не підтримуються. Перевірте реліз за його ресурсом `SHA256SUMS`.

| Елемент | Значення |
|---|---|
| Продукт | `DailybotHQ/coding-agents-kit`, тег `v0.5.0`, інтерфейс 1 |
| Ключ реєстру | `agentkit` у `.dwp/config.json` |
| Транспорт | headless: один `ak run` на делегата в окремому git worktree |
| Надає | `subagents`, `cancel_children`, `model_routing` |
| Потребує | дозволу `agent_delegation` у контракті плану |

## Автономія за замовчуванням із відмовою, яка завжди перемагає

Починаючи з `v0.2.0`, `ak <kind>` запускає кожного агента в **автономії**: він додає власний прапорець автономії CLI, який зберігається лише в `providers.toml` kit. Автономія призначена для одноразових або ізольованих середовищ, як-от контейнер для розробки.

**Відмова завжди перемагає**: `--ask` для однієї команди або `AGENTKIT_PERMISSIONS=ask` у середовищі чи в env-файлі kit пригнічує прапорець, навіть коли та сама команда вказує `--auto`. Сесія з відмовою передає відмову агентам, яких вона запускає. На хості встановіть відмову.

Аддон не прописує жодного прапорця автономії й ніколи не передає `--auto`. Він передає `--ask`, коли план фіксує відмову. План, який надає `agent_delegation` на хості, приймає автономних делегатів, обмежених власним worktree, а worktree не є пісочницею.

## Що він додає до плану

У плані v7, контракт якого надає `agent_delegation`, `execute` може передати завдання `parallel_safe` іншому CLI: він створює окремий git worktree, запускає там `ak run` з тайм-аутом і збирає результат у `analysis_results/delegations/` плану. Результат є доказом `asserted`, доки власний gate runner плану його не зафіксує. Скасування делегата зупиняє все його дерево процесів.

## Agentkit чи Herdr

| Ситуація | Використовуйте |
|---|---|
| Обмежене завдання `parallel_safe` із задекларованим результатом | Agentkit (headless) |
| Завдання потребує взаємодії, виконується довго або розташоване на іншій машині | [Herdr](/kit/herdr) (peer-агент у панелі) |

Обидва поєднуються: herdr-peers може запустити peer-агента в панелі із середовищем, яке виводить `ak env <kind> @profile`. Для багатьох ліній одночасно див. [Запуск багатьох агентів](/methodology/06-orchestration).

## Примітки

Опційний і ніколи не обов’язковий. Значення API-ключів ніколи не виводяться, не журналюються й не записуються у файл конфігурації; задокументованим винятком є Cline, який отримує свій ключ у командному рядку. Видобування результатів для OpenCode, Pi, Cline і Grok побудовано на документації постачальників і ще не перевірялося на реальних облікових записах; нерозпізнаний вивід повертається як сирий текст.
