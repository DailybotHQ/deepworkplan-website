# dwp-status

Звітує про стан Deep Work Plan без його виконання.

<CmdStatus lang="uk" class="not-prose my-8" />

## Що це робить

`dwp-status` за контрактом працює суворо лише на читання. Він підсумовує прогрес, активні блокери, контрольні точки й ресурсні конверти, не змінюючи жодного файлу.

## Використання

```
/dwp-status                      # list and summarize all plans
/dwp-status [plan]               # report details for a specific plan
```

## Поведінка

1. **Чотири виміри життєвого циклу:** повідомляє формат (`lite` або `full`), статус матеріалізації (`materializing`, `ready` або `promoting`), схвалення перевірки (`pending`, `approved` або `pre_approved`) і хід виконання (`pending`, `in_progress`, `blocked` або `completed`).
2. **Огляд усього репозиторію:** за виклику без аргументів перелічує всі плани в `.dwp/plans/` із відсотками завершення, локаторами активних задач і підсумками блокерів.
3. **Ресурсний конверт:** показує спожиті значення відносно стель за відстежуваними вимірами (`wall_clock`, повтори, диспетчеризації, витрати, токени) і вказує, чи ліміти застосовуються примусово, чи мають рекомендаційний характер.
4. **Діагностика блокерів:** виводить подробиці активних блокерів зі `state.json.blocked`, класифіковані за стандартною таксономією ескалації (класи C1–C7).
5. **Спостереження за делегуванням:** підсумовує відкриті й завершені делегування субагентам і записані обміни з пірами.

## Аліаси

- `dwp:status`
