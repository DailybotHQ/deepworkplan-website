# Аддон Devcontainer

Надайте репозиторію відтворюваний, ізольований контейнер для розробки — такий, яким можуть користуватися люди, редактори та агенти для програмування. У **DWP v7** (`v7.0.0`) цей аддон інтегрує **[devcontainer-kit](https://github.com/DailybotHQ/devcontainer-kit)** — продукт за ліцензією MIT, що працює без Deep Work Plan, — і замінює шаблон, який раніше містив пакет. Він опційний: репозиторій без нього повністю відповідає вимогам.

## Що надає devcontainer-kit

- **Шаблон** на основі специфікації [Dev Containers](https://containers.dev), який `dck init` рендерить у репозиторій: `devcontainer.json`, файл compose і `docker/local/`. Під час повторного запуску він узгоджує зміни й ніколи не перезаписує ваші правки; будь-яку зміну наявного файлу спершу показано, і вона потребує згоди.
- **`dck`** — лаунчер, що запускає контейнер зі звичайного термінала — `setup`, `up`, `shell`, `ssh`, `rebuild`, `doctor` — з VS Code чи Cursor або без них.
- **Базові образи** у трьох варіантах, `python-3.13`, `node-24` і `debian`, які постачаються **без** агентів для програмування.
- **Бібліотека entrypoint** для постійних томів, SSH і середовища SSH-сесій замість вручну скопійованого entrypoint у кожному репозиторії.
- **Машини Herdr.** Кожен контейнер може приєднатися до [Herdr](https://herdr.dev) через SSH-сервер, доступний лише через loopback, тож агенти в ньому стають досяжними peer-агентами.

## Встановлення

```bash
git clone --branch v0.1.4 https://github.com/DailybotHQ/devcontainer-kit && ./devcontainer-kit/install.sh
cd your-repo && dck init
```

Вимоги: `bash` 3.2 або новіший і `python3` 3.11 або новіший на хості з Linux чи macOS, а також Docker з Compose v2 для команд контейнера. Перевірте реліз за його ресурсом `SHA256SUMS`.

| Елемент | Значення |
|---|---|
| Продукт | `DailybotHQ/devcontainer-kit`, тег `v0.1.4`, інтерфейс 1 |
| Ключ реєстру | `devcontainer` у `.dwp/config.json` |
| Конфігурація репозиторію | `.devcontainer/dck.toml` |
| Виявлення | `dck doctor --json` |

## Шари вмикаються за бажанням

Базові образи містять інструменти розробки — git, gh, ripgrep, SSH-сервер, Herdr і Neovim з DeepWorkPlan Vim, закріпленим за тегом, — і жодного агента для програмування, жодного CLI для звітування та жодного секрету. Усе інше — це шар, який ви вмикаєте в `dck.toml`:

| Шар | За замовчуванням | Що він додає |
|---|---|---|
| `agents` | вимк. | Встановлює [coding-agents-kit](/kit/agentkit) і перелічені вами CLI, кожен із власним постійним томом. Жоден прапорець обходу дозволів не встановлюється. |
| `editor` | увімк. | Neovim з DeepWorkPlan Vim; вимкнення дає звичайний редактор. |

## Типові налаштування безпеки

- Кожен опублікований порт прив’язується до `127.0.0.1`, якщо `dck.toml` не задає `bind`.
- Переспрямування SSH-агента з хоста; приватні ключі хоста ніколи не копіюються в контейнер.
- SSH-ключі хоста генеруються під час виконання в том окремого проєкту й ніколи не вбудовуються в образ; сервер приймає лише публічні ключі, без входу root і без паролів.
- Шаблон не додає `cap_add`, режиму `privileged` і сокета Docker.
- Базові образи та інструменти закріплено за версією й перевірено контрольною сумою; compose посилається на базовий образ за digest, коли digest вдається визначити.

## Примітки

Опційний і ніколи не обов’язковий. Репозиторій без опційних аддонів повністю відповідає вимогам. v0.1 підтримує хости з Linux і macOS.
