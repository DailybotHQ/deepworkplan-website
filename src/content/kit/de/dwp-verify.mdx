# dwp-verify

Repository- und Plankonformität objektiv prüfen — nur lesend.

<CmdVerify lang="de" class="not-prose my-8" />

## Was es tut

`dwp-verify` prüft mechanisch, ob ein Repository AI-first (DeepWorkPlan-konform) ist und ob seine Pläne wohlgeformt sind, und berichtet dann Bestanden/Nicht-bestanden. Es verändert nichts.

## Verwendung

```
/dwp-verify            # das Repository verifizieren
/dwp-verify plan auth  # zusätzlich einen bestimmten Plan verifizieren
/dwp-verify all        # Repository + jeden Plan
```

## Verhalten

1. Das Repository prüfen: `AGENTS.md` mit echten, ausführbaren Befehlen; `CLAUDE.md`-Auflösung; `docs/`-Kategorien; `.agents/`-Katalog, der der Festplatte entspricht; schlanke `dwp-*`-Delegatoren; gitignore-ausgeschlossenes `.dwp/` und `tmp/`; eine auflösbare Skill.
2. Einen Plan prüfen (wenn angefordert): jede Aufgabe hat Akzeptanzkriterien und ein Validierungs-Gate, der Fortschritt ist persistiert, das aufgezeichnete Final Review ist vorhanden (einschließlich seines Sicherheitstests), und die Aufgaben verankern sich erneut am Ziel.
3. **KONFORM** oder **NICHT KONFORM** berichten, mit jedem aufgeführten Fehlschlag.
4. Anbieten, Lücken als Deep Work Plan zu erfassen; niemals stillschweigend beheben.

**Versionsspezifische Planprüfung.** Der Herkunftsprüfer des Repositorys akzeptiert den aktuellen DWP-Standard 7.0.0; Planprüfungen bleiben jedoch generationsspezifisch. Ein v6- oder v7-Plan wird anhand des Contract-Verweises in seinem Manifest, von `contract.json` oder einer Revisionskette unter `contracts/` erkannt und von `conformance.sh --plan` im Nur-Lese-Modus an seinen eigenen Aufzeichnungen gemessen: Jede Contract-Revision ist gültig, das Manifest passt zur Generation des Contracts, das Journal ist unversehrt und gültig, eine Freigabe verweist auf den aktuell gültigen Contract, und `state.json` stimmt mit der Journal-Projektion überein (ein veralteter Snapshot ist nur ein Hinweis und wird neu erzeugt, nie von Hand bearbeitet). Die v5-Lebenszyklusprüfungen gelten nur für Pläne der Generation v5 und älter, und der v5-Abschluss lehnt einen v6- oder v7-Plan ab. Die Generationen bestehen nebeneinander, und keine wird bei der Prüfung migriert.
