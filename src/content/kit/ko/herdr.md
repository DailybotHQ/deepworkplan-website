# Herdr 애드온

[Herdr](https://herdr.dev)는 코딩 에이전트를 페인(pane)에 배치합니다. 여러분의 머신뿐 아니라 SSH로 연결되는 머신에서도 가능합니다. 이 애드온은 Deep Work Plan이 그 에이전트들을 **피어**로 사용할 수 있게 합니다. 계획은 범위가 정해진 작업을 다른 페인의 에이전트에 넘기고, 승인된 정확히 하나의 응답을 받고, 그 교환의 기록을 남길 수 있습니다.

이것은 **DWP v7 beta**(`v7.0.0-beta.1`, 사전 릴리스)의 선택형 애드온입니다. 방법론은 이것 없이도 똑같이 동작합니다. 애드온이 없거나 비활성화되어 있으면 모든 작업은 이전과 똑같이 현재 세션에서 실행됩니다.

## 무엇을 통합하는가

이 애드온은 얇은 통합 계층입니다. 실제 작업은 [**herdr-peers**](https://github.com/DailybotHQ/herdr-peers)가 수행합니다. 이는 **`v0.1.0`** 태그에 고정된 독립형 MIT skill이며, Deep Work Plan 없이도 유용합니다. Herdr 자체가 열어 둔 부분을 정의합니다. 누가 응답할 수 있는지, 응답이 머신을 넘어 어떻게 돌아오는지, 두 에이전트가 서로에게 끝없이 응답하는 일을 어떻게 피하는지, 그리고 "내가 물었고, 그것이 답했다"는 기록이 어디에 남는지입니다.

| 항목 | 값 |
|---|---|
| 제품 | `DailybotHQ/herdr-peers`, 태그 `v0.1.0`, 프로토콜 1 |
| 레지스트리 키 | `.dwp/config.json`의 `herdr` |
| 전송 방식 | 대화형: Herdr 페인 안의 피어 |
| 제공 | `subagents`, `cancel_children` |
| 요구 | 계획 계약의 `agent_delegation` 부여 |

## 설치

herdr-peers와, 그것이 의존하는 Herdr 공식 skill을 설치합니다. 에이전트가 응답해야 하는 모든 머신에도 이 skill이 필요합니다.

```bash
npx --yes skills add DailybotHQ/herdr-peers@v0.1.0 --skill herdr-peers -g
npx --yes skills add herdrdev/herdr@v0.9.3 --skill herdr -g
```

요구 사항: Herdr 0.9.1 이상, `bash`, 그리고 `python3` 3.9 이상(표준 라이브러리만 사용). 온보딩이 이 애드온을 제안하고 여러분의 답을 애드온 레지스트리에 기록합니다. 동의 없이 활성화되는 일은 결코 없습니다.

## 계획에 무엇을 더하는가

- **피어에게 위임.** 계약이 `agent_delegation`을 부여한 v7 계획에서 `execute`는 `parallel_safe` 작업이나 읽기 전용 질문을 다른 페인의 에이전트에 넘길 수 있습니다. 그 에이전트는 이 머신에 있든 다른 머신에 있든 상관없습니다.
- **승인된 하나의 응답.** 요청에는 정확히 하나의 응답을 승인하는 스탬프가 붙습니다. 피어는 헬퍼를 통해 한 번 응답하고, 그 응답에도 자체 스탬프가 붙습니다.
- **의존하기 전에 기록.** 모든 위임은 응답이 사용되기 전에 계획의 `analysis_results/delegations.ndjson`에 기록되며, v7의 `delegation` 저널 이벤트에 대응합니다.
- **확인될 때까지 결과는 주장.** 피어의 응답은 계획 자체의 게이트 러너가 관찰할 때까지 `asserted` 증거입니다. 그것만으로 작업을 종료하는 일은 결코 없습니다.

## 안전 모델

| 규칙 | 의미 |
|---|---|
| 부여가 먼저 | 위임은 계획 계약이 `agent_delegation`을 부여한 경우에만 실행됩니다. |
| 깊이 제한 1 | `depth=1` 또는 `reply-to=` 스탬프가 붙은 메시지에는 결코 응답하지 않으며, 위임받은 쪽은 다시 위임하지 않습니다. |
| 팬아웃 상한 | 기본적으로 호출자당 최대 네 개의 피어. |
| 지시가 아닌 데이터 | 응답은 수신자가 원래 갖지 않았던 권한을 결코 부여하지 않습니다. |
| 경로당 작성자 하나 | 쓰기 작업을 하는 피어는 자신의 git worktree에서 작업합니다. |

herdr-peers는 발신자를 인증하지 않습니다. 스탬프의 `from=` 필드는 주장일 뿐입니다. 완화 수단은 `HERDR_PEERS_SCOPE` 허용 목록으로, 피어가 받아들이는 워크스페이스와 머신을 제한합니다.

## Herdr 또는 agentkit

두 애드온은 같은 위임 인터페이스 — `launch`, `observe`, `collect`, `cancel` — 를 서로 다른 전송 방식으로 구현합니다.

| 상황 | 사용 |
|---|---|
| 출력이 선언된, 범위가 정해진 `parallel_safe` 작업 | [agentkit](/kit/agentkit)(worktree에서 헤드리스 `ak run`) |
| 작업에 상호작용이 필요하거나, 오래 실행되거나, 다른 머신에 있음 | Herdr(페인 안의 피어) |

## 참고

선택형이며 결코 필수가 아닙니다. 리포지토리는 선택적 애드온이 하나도 없어도 완전히 적합하며, 어떤 플로우도 이 애드온에 의존하지 않습니다. 두 페인 간의 머신을 넘는 왕복은 시뮬레이션된 Herdr를 대상으로 한 테스트로 검증됩니다. 첫 실행은 사람이 감독하도록 계획하세요.
