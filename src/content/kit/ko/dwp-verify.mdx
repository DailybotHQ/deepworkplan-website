# dwp-verify

리포지토리와 계획의 적합성을 객관적으로 확인합니다 — 읽기 전용.

<CmdVerify lang="ko" class="not-prose my-8" />

## 하는 일

`dwp-verify`는 리포지토리가 AI-first(DeepWorkPlan 적합)인지와 그 계획이 잘 구성되었는지를 기계적으로 확인한 뒤 합격/불합격을 보고합니다. 아무것도 바꾸지 않습니다.

## 사용법

```
/dwp-verify            # 리포지토리 검증
/dwp-verify plan auth  # 특정 계획도 함께 검증
/dwp-verify all        # 리포지토리 + 모든 계획
```

## 동작

1. 리포지토리를 확인합니다: 실제로 실행 가능한 명령을 갖춘 `AGENTS.md`, `CLAUDE.md` 해석, `docs/` 범주, 디스크와 일치하는 `.agents/` 카탈로그, 얇은 `dwp-*` 위임자, gitignore된 `.dwp/`와 `tmp/`, 해석 가능한 스킬.
2. 계획을 확인합니다(요청 시): 모든 task가 인수 기준과 검증 게이트를 가지고, 진행 상황이 영속화되며, 기록된 Final Review가(그 보안 점검을 포함하여) 존재하고, task가 목표에 다시 닻을 내리는지.
3. 각 실패를 나열하며 **CONFORMANT** 또는 **NOT CONFORMANT**를 보고합니다.
4. 미비점을 Deep Work Plan으로 포착하도록 제안합니다. 조용히 고치는 일은 결코 없습니다.

**세대별 계획 검증.** 저장소 출처 검증기는 현재 DWP 표준 7.0.0을 허용하지만 계획 검사는 세대별로 수행됩니다. v6 또는 v7 계획은 manifest의 contract 포인터, `contract.json` 또는 `contracts/` 개정 체인으로 식별하며, `conformance.sh --plan`이 계획 자체의 기록에 비추어 읽기 전용으로 판정합니다. 모든 contract 개정이 유효한지, manifest가 contract의 세대와 일치하는지, journal이 끊기지 않고 유효한지, 승인이 현재 contract를 인용하는지, `state.json`이 journal projection과 일치하는지를 확인합니다(오래된 snapshot은 권고 사항이며 다시 생성되고, 직접 수정하지 않습니다). v5 수명 주기 검사는 v5 이하 계획에만 적용되며, v5 마무리 절차는 v6 또는 v7 계획을 거부합니다. 여러 세대는 함께 존재하며 검증 중 어느 것도 마이그레이션되지 않습니다.
