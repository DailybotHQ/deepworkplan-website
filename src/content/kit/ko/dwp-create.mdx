# dwp-create

상위 수준 목표로부터 새 Deep Work Plan을 생성합니다.

<CmdCreate lang="ko" class="not-prose my-8" />

## 하는 일

`dwp-create`는 상위 수준 목표를 받아 구조화되고 실행 가능한 Deep Work Plan으로 바꿉니다. 요구 사항을 분석하고, 모호하면 명확히 하는 질문을 하며, `.dwp/plans/PLAN_<id>_<slug>/` 아래에 Lite 또는 Full 계획을 직접 구체화합니다.

## 사용법

```
/dwp-create <goal>
/dwp-create trust lite <goal>
/dwp-create <goal> full trust
```

## 모드와 경계 옵션

경계 옵션은 검토 동작과 계획 형식을 설정합니다. 명령의 시작이나 끝에 토큰으로 둘 수 있으며 순서는 상관없습니다.

- **검토 모드:**
  - **가이드(기본값):** 실행 가능한 Lite 계획 제안을 구체화하고, 관찰된 신호와 형식 선택 근거를 보여 준 뒤, Lite로 유지할지, Full로 승격할지, 편집할지, 중단할지 묻습니다.
  - **Trust(`trust` 또는 `auto`):** 검토를 건너뛰고 곧바로 사전 승인된, 바로 실행 가능한 계획으로 진행합니다.
- **형식 선호:**
  - **`lite`:** 앵커가 달린 task 기록(`#task-N`)을 담은 `README.md` 단일 파일의 간결한 계획을 선호함을 나타냅니다.
  - **`full`:** 분해된 번호 매김 task 파일(`N.task_<slug>.md`)을 선호함을 나타냅니다.
  - `lite`와 `full`을 함께 지정하면 명시적 충돌입니다.
- **종결자:** `--`는 옵션 파싱을 종료합니다. `--` 뒤의 모든 내용은 문자 그대로의 목표 컨텍스트로 해석됩니다.

## 동작

1. **요구 사항 분석:** 리포지토리 컨텍스트, 아키텍처, 문서화된 테스트 명령을 살펴봅니다.
2. **명확화:** 범위나 요구 사항이 모호하면 명확히 하는 질문을 합니다.
3. **단조 할당:** POSIX 파일 잠금(`fcntl`) 아래에서 `.next-plan-id`를 사용해 `.dwp/plans/` 아래에 0으로 채운 폴더 이름 `PLAN_<id>_<slug>/`를 할당합니다. 숫자 ID는 단조 증가하며 절대 재사용되지 않습니다.
4. **계약 구체화:** `ledger.py materialize`를 실행해 `manifest.json`을 작성하고, 콘텐츠 주소 기반 `contract.json`(`parallel_safe` task 표시가 있는 v7 세대)을 기록하며, 최초의 `approval` 이벤트를 남깁니다.
5. **Final Review:** 계획은 필수 5단계 Final Review task(필수 로컬 리뷰를 포함한 보안 점검, 최종 상태 검증, 스킬 조정, 문서 조정, 완료)로 끝맺습니다.
