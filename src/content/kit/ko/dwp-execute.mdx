# dwp-execute

기존 Deep Work Plan을 task 단위로 실행합니다.

<CmdExecute lang="ko" class="not-prose my-8" />

## 하는 일

`dwp-execute`는 결정론적 기록 계층을 통해 기존 계획을 task 단위로 실행합니다. 대상 계획을 확인하고, 의존성을 평가하며, 선언된 순서대로 각 task를 실행하고, 검증 게이트를 돌리며, 변경 불가능한 진행 기록을 남깁니다.

## 사용법

```
/dwp-execute                     # execute latest plan
/dwp-execute [plan]              # by exact folder, id, or slug
/dwp-execute [plan] trust        # unattended execution without per-task prompts
```

## 모드

- **가이드(기본값):** task 사이마다 확인을 요청하여 모든 task 경계에서 증거와 결정을 검토할 수 있게 합니다.
- **Trust(`auto`):** `trust`를 덧붙이면 대상 task를 순차적으로 완료까지 실행하며, 일상적인 확인을 위해 멈추지 않고 실제로 차단되었을 때(에스컬레이션 등급 C1–C7)에만 멈춥니다.

## 동작

1. **계획 확인:** 정확한 폴더 이름, 숫자 ID, 고유한 슬러그, 또는 `latest`(숫자 ID가 가장 큰 계획)로 확인합니다.
2. **원장 루프:** `ledger.py ready`로 의존성 DAG와 불변 조건을 평가하고, `ledger.py start`로 선행 조건을 확인하며, `ledger.py gate`로 검증 명령을 실행해 `observed` 증거를 발급합니다.
3. **보호된 완료:** `ledger.py complete`는 테스트 0건 통제, 불변 조건의 새로운 평가, task 단위의 스킬 및 문서 결정을 강제합니다.
4. **계획 내 위임:** v7 계약에서 `parallel_safe`로 표시된 task는 헤드리스(worktree에서 `ak run`) 또는 대화형(`herdr` 창) 전송 방식으로 하위 에이전트에 위임할 수 있습니다. 결과는 계획의 게이트 실행기가 관찰할 때까지 `asserted` 상태로 남습니다.
5. **용량 점검:** 디스패치 전에 task 경계에서 계정의 남은 여유 용량을 평가합니다.
6. **Final Review:** 필수 5단계 마무리 task(필수 로컬 리뷰를 포함한 보안 점검, 최종 상태 검증, 스킬 조정, 문서 조정, 완료)로 끝납니다.
