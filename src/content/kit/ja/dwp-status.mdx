# dwp-status

Deep Work Plan の状態を実行せずに報告します。

<CmdStatus lang="ja" class="not-prose my-8" />

## 何をするか

`dwp-status` は契約上、厳密に読み取り専用です。進捗、現在のブロッカー、チェックポイント、リソースエンベロープを要約し、どのファイルにも変更を加えません。

## 使い方

```
/dwp-status                      # list and summarize all plans
/dwp-status [plan]               # report details for a specific plan
```

## 振る舞い

1. **4 つのライフサイクル次元：** 形式（`lite` または `full`）、マテリアライズ状態（`materializing`、`ready`、`promoting`）、レビュー承認（`pending`、`approved`、`pre_approved`）、実行の進捗（`pending`、`in_progress`、`blocked`、`completed`）を報告する。
2. **リポジトリ全体の概要：** 引数なしで呼び出すと、`.dwp/plans/` の下のすべての計画を、完了率、現在のタスクの位置、ブロッカーの要約とともに一覧表示する。
3. **リソースエンベロープ：** 追跡対象の次元（`wall_clock`、リトライ、ディスパッチ、支出、トークン）ごとに消費量と上限を表示し、上限が実際に強制されているか助言にとどまるかを示す。
4. **ブロッカーの診断：** `state.json.blocked` から現在のブロッカーの詳細を、標準のエスカレーション分類（区分 C1–C7）に沿って示す。
5. **委任の観測：** 進行中および完了したサブエージェントへの委任と、記録されたピアとのやり取りを要約する。

## エイリアス
