# Herdr アドオン

[Herdr](https://herdr.dev) は、コーディングエージェントをペインに配置します。あなたのマシン上でも、SSH 経由で到達できるマシン上でも可能です。このアドオンにより、Deep Work Plan はそれらのエージェントを**ピア**として使えるようになります。計画は範囲の限定されたタスクを別のペインのエージェントに渡し、認可されたちょうど一つの返信を受け取り、そのやり取りの記録を残せます。

これは **DWP v7 beta**（`v7.0.0-beta.1`、プレリリース）の任意のアドオンです。方法論はこれがなくても同じように機能します。アドオンが存在しない、または無効化されている場合、すべてのタスクはこれまでとまったく同じく現在のセッションで実行されます。

## 何を統合するか

このアドオンは薄い統合レイヤーです。実際の作業は **[herdr-peers](https://github.com/DailybotHQ/herdr-peers)** が担います。これは **`v0.1.0`** に固定された独立した MIT のスキル で、Deep Work Plan がなくても役立ちます。Herdr 自体が未定義のまま残している部分を定めています。誰が回答してよいか、回答がマシンをまたいでどう戻ってくるか、二つのエージェントが互いに延々と回答し合うのをどう防ぐか、そして「質問し、回答があった」という記録をどこに保持するか、です。

| 項目 | 値 |
|---|---|
| プロダクト | `DailybotHQ/herdr-peers`、タグ `v0.1.0`、プロトコル 1 |
| レジストリキー | `.dwp/config.json` 内の `herdr` |
| トランスポート | 対話型：Herdr ペイン内のピア |
| 提供するもの | `subagents`、`cancel_children` |
| 必要なもの | 計画コントラクトの `agent_delegation` 付与 |

## インストール

herdr-peers と、それが依存する Herdr 公式のスキル をインストールします。エージェントに回答させたいすべてのマシンにも、このスキル が必要です。

```bash
npx --yes skills add DailybotHQ/herdr-peers@v0.1.0 --skill herdr-peers -g -y
npx --yes skills add herdrdev/herdr@v0.9.3 --skill herdr -g -y
```

要件：Herdr 0.9.1 以降、`bash`、および `python3` 3.9 以降（標準ライブラリのみ）。オンボーディングがこのアドオンを提案し、あなたの回答をアドオンレジストリに記録します。同意なしに有効化されることはありません。

## 計画に追加されるもの

- **ピアへの委任。** コントラクトが `agent_delegation` を付与している v7 の計画では、`execute` が `parallel_safe` なタスク、または読み取り専用の質問を、別のペインのエージェントに渡せます。そのエージェントはこのマシン上でも別のマシン上でも構いません。
- **認可された一つの返信。** リクエストには、ちょうど一つの回答を認可するスタンプが付きます。ピアはヘルパーを通じて一度だけ返信し、その返信にも独自のスタンプが付きます。
- **依拠する前に記録。** すべての委任は、返信が使われる前に計画の `analysis_results/delegations.ndjson` に書き込まれ、v7 の `delegation` ジャーナルイベントに対応します。
- **結果は確認されるまで主張のまま。** ピアの回答は、計画自身のゲートランナーが観測するまで `asserted` な証拠です。それだけでタスクを完了させることはありません。

## 安全モデル

| ルール | 意味 |
|---|---|
| 付与が先 | 委任は、計画コントラクトが `agent_delegation` を付与している場合にのみ実行されます。 |
| 深さの上限 1 | `depth=1` または `reply-to=` のスタンプが付いたメッセージには決して回答せず、委任先がさらに委任することもありません。 |
| ファンアウト上限 | デフォルトでは、呼び出し元ごとに最大四つのピアまで。 |
| 指示ではなくデータ | 返信が、受信側にもともとなかった権限を与えることはありません。 |
| パスごとに書き手は一人 | 書き込みを行うピアは、自身の git worktree の中で作業します。 |

herdr-peers は送信者を認証しません。スタンプ内の `from=` フィールドは主張にすぎません。その緩和策が `HERDR_PEERS_SCOPE` 許可リストで、ピアが受け入れるワークスペースとマシンを制限します。

## Herdr か agentkit か

どちらのアドオンも同じ委任インターフェース（`launch`、`observe`、`collect`、`cancel`）を、異なるトランスポートで実装しています。

| 状況 | 使うもの |
|---|---|
| 出力が宣言された、範囲の限定された `parallel_safe` なタスク | [agentkit](/kit/agentkit)（worktree 内でヘッドレスに `ak run`） |
| タスクに対話が必要、長時間実行される、または別のマシン上にある | Herdr（ペイン内のピア） |

## 補足

任意であり、必須となることはありません。リポジトリはオプションアドオンがゼロでも完全に適合し、このアドオンに依存するフローはありません。二つのペインによるマシンをまたいだ往復は、模擬した Herdr に対するテストでカバーされています。初回の実行は人が監督する形で計画してください。
