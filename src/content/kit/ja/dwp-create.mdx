# dwp-create

高レベルの目標から新しい Deep Work Plan を作成します。

<CmdCreate lang="ja" class="not-prose my-8" />

## 何をするか

`dwp-create` は高レベルの目標を受け取り、それを構造化された実行可能な Deep Work Plan へと変えます。要件を分析し、曖昧な場合は明確化のための質問をし、`.dwp/plans/PLAN_<id>_<slug>/` の下に Lite または Full の計画を直接マテリアライズします。

## 使い方

```
/dwp-create <goal>
/dwp-create trust lite <goal>
/dwp-create <goal> full trust
```

## モードと境界オプション

境界オプションはレビューの振る舞いと計画の形式を設定します。コマンドの先頭または末尾に、任意の順序でトークンとして置けます。

- **レビューモード：**
  - **ガイド付き（既定）：** 実行可能な Lite 計画の提案をマテリアライズし、観測されたシグナルと形式の根拠を示したうえで、Lite のまま維持するか、Full へ昇格させるか、編集するか、中止するかを尋ねます。
  - **Trust（`trust` または `auto`）：** レビューを飛ばし、そのまま事前承認済みの実行可能な計画へ進みます。
- **形式の希望：**
  - **`lite`：** `README.md` 内にアンカー付きのタスク記録（`#task-N`）を持つ、コンパクトな単一ファイル計画を希望することを示します。
  - **`full`：** 分解された番号付きタスクファイル（`N.task_<slug>.md`）を希望することを示します。
  - `lite` と `full` を両方指定するのは明示的な矛盾です。
- **終端記号：** `--` はオプション解析を終了します。`--` 以降はすべて文字どおりの目標コンテキストとして解釈されます。

## 振る舞い

1. **要件分析：** リポジトリのコンテキスト、アーキテクチャ、文書化されたテストコマンドを調べる。
2. **明確化：** 範囲や要件が曖昧な場合は明確化のための質問をする。
3. **単調な割り当て：** POSIX ファイルロック（`fcntl`）のもとで `.next-plan-id` を用い、`.dwp/plans/` の下にゼロ埋めのフォルダ名 `PLAN_<id>_<slug>/` を割り当てる。数値 ID は単調増加し、再利用されない。
4. **契約のマテリアライズ：** `ledger.py materialize` を実行して `manifest.json` を書き出し、コンテンツアドレス方式の `contract.json`（`parallel_safe` タスクマーカー付きの v7 世代）を刻印し、最初の `approval` イベントを記録する。
5. **Final Review：** 計画は必須の 5 部構成の Final Review タスク（必須のローカルレビューを含むセキュリティパス、最終状態の検証、スキルの突き合わせ、ドキュメントの突き合わせ、完了）で締めくくる。
