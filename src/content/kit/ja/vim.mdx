# DeepWorkPlan Vim

**DeepWorkPlan Vim** は Deep Work Plan のターミナルエディタです。ターミナルで作業する人とコーディングエージェントのための Neovim 設定で、計画もドキュメントもすべてのコマンドの索引も、キー操作ひとつで手の届く場所にあります。

これは独立した製品で、Deep Work Plan v7（`v7.0.0`）の任意の `vim` アドオンとして提供されています。Deep Work Plan はどのエディタとも、エディタなしでも動作し、このエディタも Deep Work Plan を必要としません。マシンには単独で追加でき、計画があってもなくてもエディタとして動作します。このページはリリース **v0.6.0** を説明しています。

## なぜ Deep Work Plan にターミナルエディタなのか

Deep Work Plan は `.dwp/plans/` 以下の Markdown のフォルダです。ゴール、アトミックなタスク、検証ゲート、継続的なログで構成されます。人がレビューし、エージェントが実行し、どちらもターミナルで行うことが多くあります。この作業のために作られたエディタは、計画自体、その周りのドキュメント、そして両者の間を移動するキー操作という 3 つを手元に置きます。

DeepWorkPlan Vim はそのエディタです。目指すのは、ターミナルの中のミニ VS Code です。ファイルを移動し、どのファイルが変更されたかを確認し、差分をレビューして変更を承認または破棄できます。親しみやすく軽量で、エージェントファーストであり、計画の状況が常に視界に入ります。言語サーバー、補完、フォーマット、あいまい検索、ファイルツリー、厳選したカラーテーマを遅延読み込みで備えた、整えられた Neovim 設定に、Deep Work Plan のエディタたらしめるいくつかの画面が加わります。

## ツアー：古くならないコマンド索引

`SPC h h`（Space がリーダーキー）を押すか `:DwpCommands` を実行すると、エディタが持つすべてのマッピングが 1 行の説明付きで一覧表示されます。一覧は実際のキーマップから生成されるため、どこで定義したマッピングも登録なしで索引に現れ、索引が古くなることはありません。

ツアーはこれだけです。`nvim` を起動し、Space、`h`、`h` と押してください。

## 得られるもの

5 つの機能が、それぞれキー操作ひとつで使えます。

| 機能 | キー | 内容 |
|---|---|---|
| 生成されるコマンド索引 | `SPC h h` | 設定内のすべてのマッピングを、実際のキーマップから生成して一覧にします。 |
| VS Code 風の操作 | `<C-a>`, `SPC y` | 1 キーでファイル全体を選択し、システムクリップボードへコピーします。クリップボードはシステム共通なので、単独の `y` もそこにコピーされます。 |
| Deep Work Plan ブラウザ | `SPC P` | リポジトリ内の計画を状態別にまとめて進捗バーとともに表示するサイドバー。計画をクリックするとリーダーが開きます。 |
| Markdown ビューア | `SPC m p`, `SPC m r` | ブラウザで Markdown をプレビューするか、バッファ内で描画します。 |
| 検証付きインストーラ | — | macOS、Linux、WSL 向けの自己完結的なインストーラ。Windows には文書化された手動の手順があります。 |

## エディタを離れずに計画を読む

`SPC P`、`:DwpPlans`、またはステータスラインのセグメントのクリックで、計画のサイドバーが開きます。現在のディレクトリと Neovim の設定ディレクトリにあるすべての `.dwp/plans/` フォルダが対象で、注意が最も必要なものから順に並びます。エディタ上のラベルは `Working`、`Needs attention`、`Ready`、`Not started`、`Done` です。各計画には進捗バーが表示されます。

計画をクリックするか Enter を押すと、リーダーが開きます。1 文のゴール、状態と進捗、現在のタスクに印を付けたタスクチェックリスト、そして計画自身のファイルへの分かりやすい移動先が表示されます。ステータスラインには現在アクティブな計画が表示され、スタート画面には上位 3 件が並びます。これらの画面は計画を説明するだけで、`.dwp/` には書き込みません。

サイドバーはマウスでもキーボードでも操作できます。計画の横の小さな矢印でタスクとファイルの表示を切り替え、タスクやファイルをクリックするとそれが開きます。`j`、`k`、矢印キー、`Ctrl-n`、`Ctrl-p` で、空行や装飾を飛ばして計画から計画へ移動します。各セクションには件数が表示され、アイコンと進捗バーは状態の色で示されます。進行中の計画のタイトルは強調され、完了済みの計画のタイトルは薄く表示されます。6 件を超える Done グループは折りたたまれた状態で開きます。ウィンドウは読み取り専用で静かに動作し、編集系のキーはエラーを出さず、何も起こりません。

計画とファイルツリーは交代で表示されます。一方のサイドバーを開くともう一方が閉じるため、見るものは一度にひとつです。リーダーは計画のサイドバーと一緒に閉じます。一方のサイドバーを開くともう一方が閉じるかどうかは、`dwpvim.json` の `sidebars.exclusive` キーで設定します。

計画の Markdown ファイルをその場で読むには、`SPC m p` で現在のバッファをブラウザでプレビューし、`SPC m r` でバッファ内に描画します。どちらも Markdown バッファでのみ動作します。

## ダッシュボード

スタート画面は DeepWorkPlan Vim 独自のものです。点字文字で刻んだ Deep Work Plan のロゴの P の下に小さな VIM が添えられ、その下に「powered by Dailybot」のクレジットが入り、右側には刻印風の情景が表示されます。Deep Work Plan の灯台と、その海を進む船です。ダッシュボードが表示されている間、光の筋はゆっくりと脈打ちます。止めるには `vim.g.dwp_greeter_pulse = false` を設定してください。

情景は 6 種類の高さがあり、ウィンドウに残っている行数に応じて選ばれます。幅の狭いウィンドウでは、ワードマークが情景の上に重なるか、単独で表示されます。幅の広いウィンドウではショートカットと「Your plans」が横に並び、狭いウィンドウでは縦に積まれます。Enter でカーソル下の行を実行し、`e` で計画のサイドバーを開きます。

## サイドバーを設定する

`dwpvim.json` ファイルで、2 つのサイドバーの位置と幅を設定します。エディタのディレクトリ（`~/.config/nvim`）にあるファイルはすべてのプロジェクトに適用され、Neovim を起動したディレクトリにある `.dwpvim.json` は、そのプロジェクトに限って上書きします。設定は起動時に読み込まれるため、ファイルを編集したら Neovim を再起動してください。

```json
{
  "tree":  { "side": "left", "width": 40 },
  "plans": { "side": "left", "width": 48 },
  "sidebars": { "exclusive": true }
}
```

| キー | 値 | デフォルト | 内容 |
|---|---|---|---|
| `tree.side` | `"left"` または `"right"` | `"left"` | ファイルツリー（`SPC n`）の位置 |
| `tree.width` | 20 から 120 の整数 | `40` | ツリーの最大幅。内容に合わせて縮みます |
| `plans.side` | `"left"` または `"right"` | `"left"` | 計画のサイドバー（`SPC P`）の位置 |
| `plans.width` | 20 から 120 の整数 | `48` | 計画のサイドバーの最大幅 |
| `sidebars.exclusive` | `true` または `false` | `true` | 一度にひとつのサイドバーだけを表示します。`false` にすると両方を開いたままにできます |

ファイルがなくても問題ありません。有効な JSON でないファイル、未知のキー、無効な値は無視されて報告されるだけで、致命的なエラーにはなりません。`:DwpConfig` を実行すると、有効なすべての値、その取得元のファイル、見つかった問題を確認できます。

## より軽いエディタ

バージョン 0.6.0 では、誰も使っていないものを取り除きました。固定するプラグインが減り、初回起動時にインストールして更新するパッケージも減ります。

- Mason の言語サーバー 11 個を廃止しました。efm、diagnosticls、tailwindcss、grammarly、bashls、および astro、svelte、Vue 2、Angular、SQL、Vim script 用のサーバーです。
- nvim-lint を削除しました。リンターが一度も設定されていなかったためです。
- prettier のフォーマッタ項目を削除しました。prettier をインストールするものがなかったためです。`:Format` は biome、black、shfmt、stylua を引き続き使います。
- marksman は、リンクの移動、リンクと見出しの補完、アウトラインのために残し、診断は無効にしています。Markdown にフォーマッタを置かないのは意図的です。

Mason に以前の環境のサーバーが残っていても、有効になるのは設定に列挙されたサーバーだけです。すべてのプラグイン、サーバー、ツールと、それらがある理由は [PLUGINS.md](https://github.com/DailybotHQ/deepworkplan-vim/blob/v0.6.0/docs/PLUGINS.md) にまとめています。

## インストール

インストールは 3 つのコマンドです。スクリプトをダウンロードし、このサイトが配布するファイルの SHA-256 と照合してから実行します。インストーラは自身のリリースに固定されているため、[別のバージョンを選ぶ](#choose-a-version)場合を除き、このページが説明するリリースである `v0.6.0` を正確にインストールします。

<VimInstall lang="ja" />

インストーラは次の順に実行します。

1. OS とパッケージマネージャを確認し、git、curl、Lua インタプリタが足りなければインストールします（`--skip-packages` を指定した場合は何もインストールしません）。
2. バージョンを解決します。自身のリリースか、`--version` で指定されたリリースです。
3. `--nvim X.Y.Z` を指定すると、その Neovim リリースを `~/.local/opt` にインストールし、Neovim が公開している SHA-256 で検証します。
4. 既存の Neovim 設定に手を付ける前に確認します。端末がない場合は、`--yes` でその設定を退避するよう指示しない限り、何も変更せずに停止します。
5. リポジトリを `~/.config/nvim` にクローンします。すでにある場合は更新します。
6. リポジトリ自身の `lua install.lua` を実行します。
7. プラグインをヘッドレスでインストールして確認するため、終了して開き直す手順はありません。`--strict` を指定すると、プラグインのインストールの失敗や不完全なインストールはエラーになります。

ここで配布しているスクリプトは、`v0.6.0` タグの `install.sh` とバイト単位で同一のコピーです。チェックサムはその隣の `https://deepworkplan.com/vim/install.sh.sha256` で配布しているため、`shasum -a 256 -c install.sh.sha256`（Linux では `sha256sum -c install.sh.sha256`）でダウンロードを検証できます。別の配布元でも確認するには、GitHub リリースの `SHA256SUMS` にある `install.sh` の行と比較してください。すべてのオプションを一覧するには `bash install.sh --help` を実行します。

## バージョンを選ぶ

デフォルトでは、インストーラは自身のリリースである `v0.6.0` をインストールします。別のバージョンを選ぶには、`DWP_VIM_VERSION` を設定するか `--version` を渡します。どちらも同じ働きをするので読みやすい方を使ってください。フラグは環境変数より優先されます。どちらも次の形式を受け付けます。

| 形式 | 例 | インストールされるもの |
|---|---|---|
| 正確なバージョン | `0.6.0` または `v0.6.0` | そのリリース |
| 最低バージョン | `'>=0.4.2'` | 最低バージョン以上の最新の安定版リリース |
| 最新 | `latest` | 最新の安定版リリース |

上記のダウンロードとチェックサムの確認を終えたら、次のように実行します。

```bash
# exact version
DWP_VIM_VERSION=0.6.0 bash install.sh
bash install.sh --version 0.6.0

# minimum floor: the newest stable release at or above 0.4.2
DWP_VIM_VERSION='>=0.4.2' bash install.sh

# latest stable release
bash install.sh --version latest
```

シェルが `>` をリダイレクトとして解釈しないよう、最低バージョンは引用符で囲んでください。バージョンは安定版のリリースタグにのみ解決されます。ブランチやコミットを使うには、代わりに `DWP_VIM_REF` を設定します（`DWP_VIM_REF=main` は `main` に追従します）。バージョンと ref が食い違う場合はエラーになります。

### コンテナと CI

端末がなく、多くの場合 root 権限もないイメージや CI ジョブでは、スクリプトをダウンロードして検証し、結果を再現可能にするフラグを付けて 1 ステップで実行します。

```bash
curl -fsSL -o install.sh https://deepworkplan.com/vim/install.sh && \
curl -fsSL -o install.sh.sha256 https://deepworkplan.com/vim/install.sh.sha256 && \
sha256sum -c install.sh.sha256 && \
bash install.sh --version 0.6.0 --nvim 0.12.5 --skip-packages --strict
```

- `--version 0.6.0` はエディタのリリースを固定します。
- `--nvim 0.12.5` はその Neovim リリースを `~/.local/opt/nvim-v0.12.5` にインストールし、`~/.local/bin/nvim` としてリンクして、Neovim が公開している SHA-256 で検証します（Linux と macOS）。
- `--skip-packages` はシステムパッケージを一切インストールしません。イメージに git、curl、Lua があらかじめ含まれている必要があります。
- `--strict` は、ヘッドレスでのプラグインのインストールが失敗した場合や、プラグインが欠けている場合に 0 以外のコードで終了します。また、すべてのプラグインと pckr が、リリースの `pckr/lockfile.lua` で固定されたコミットでチェックアウトされているかも確認します。

すべてのフラグには対応する環境変数があります（`DWP_VIM_VERSION`、`DWP_VIM_NVIM`、`DWP_VIM_SKIP_PACKAGES=1`、`DWP_VIM_STRICT=1`）。`--yes` は、退避すべき Neovim 設定がイメージにすでに含まれている可能性がある場合にのみ追加してください。

## 要件とプラットフォーム

- Neovim 0.12 以降。自分でインストールするか、`--nvim X.Y.Z` でインストーラに検証済みのリリースを追加させます（Linux と macOS）。
- Lua：`lua`、`lua5.4`、`luajit` のいずれか。足りなければインストーラが追加します。
- macOS、Linux、WSL ではインストーラを実行できます。Windows にはリポジトリ README に手動の手順があります。winget で Neovim をインストールし、`v0.6.0` タグを `%LOCALAPPDATA%\nvim` にクローンして、Git Bash から `lua install.lua` を実行します。
- GPL-3.0 ライセンス：自由に利用、研究、改変できます。

## 更新、バージョン固定、アンインストール

更新するには、より新しいリリースのインストーラを実行するか、`bash install.sh --version latest` を実行します。再実行すると、既存の DeepWorkPlan Vim のチェックアウトを選択したリリースへ移動し、ブランチはそのまま保持し、ローカルの変更をリセットすることはありません。ローカルの変更やコミットが失われる場合は、停止して何も変更しません。

リリースを固定するには `--version` を使います（[バージョンを選ぶ](#choose-a-version)を参照）。ブランチやコミットには `DWP_VIM_REF` を設定します。リリースをおすすめします。`v0.4.0` より前のリリースには、VS Code 風の操作、計画ブラウザ、Markdown ビューア、このインストーラが含まれていません。

```bash
# pin a specific release, here the previous one
curl -fsSL -o install.sh https://deepworkplan.com/vim/install.sh && \
curl -fsSL -o install.sh.sha256 https://deepworkplan.com/vim/install.sh.sha256 && \
shasum -a 256 -c install.sh.sha256 && \
bash install.sh --version 0.5.1
```

アンインストールするには、設定ディレクトリで `lua delete.lua` を実行します。設定、プラグイン、Mason のデータ、キャッシュと状態、インストーラがコピーしたフォントを削除し、Neovim 本体とシステムのパッケージはそのまま残します。

```bash
cd ~/.config/nvim && lua delete.lua
```

## よくある質問

### Neovim の設定は上書きされますか？

いいえ、あなたの承認なしには上書きされません。DeepWorkPlan Vim ではない設定が見つかると、対話実行では `~/.config/previous-deepworkplan-vim` に移す前に確認します。端末がない場合は、`--yes` を渡して無人で退避させない限り、何も変更せずに停止します。そのバックアップ先がすでに存在する場合は、常に何も変更せずに停止します。

### Windows で動きますか？

インストーラは Windows では動作しません。リポジトリ README の手動の手順を使うか、WSL の中でインストーラを実行してください。

### 使うのに Deep Work Plan は必要ですか？

いいえ。まずはエディタです。Deep Work Plan のスキルをインストールすることも必要とすることもありません。`.dwp/plans/` フォルダが存在するまで、計画ブラウザに一覧するものがないだけです。

### v7 の vim アドオンはどう使いますか？

Deep Work Plan v7 は、オンボーディング中にこのエディタを任意の `vim` アドオンとして提示します。アドオンはエディタの `addon/surface.json` を通じて既存のインストールを読み取り専用で検出し、固定されたチェックサム検証済みのインストールは、あなたの同意がある場合にのみ提示します。明示的な承認なしに既存の Neovim 設定を上書きすることはなく、必須になることもありません。

### コーディングエージェントはどう使いますか？

ターミナルで動く人とコーディングエージェントのために作られています。キーバインドはコントラクトテストで固定されているため、筋肉記憶もエージェントの期待もアップデート後に保たれます。

### どのバージョンが入りますか？

インストーラは、自身が属するリリース（現在は `v0.6.0`）をインストールします。別のバージョンを選ぶには、`--version` または `DWP_VIM_VERSION` で、正確なバージョン、`>=` による最低バージョン、または `latest` を指定します。`DWP_VIM_REF` はブランチまたはコミットを受け付け、`DWP_VIM_REF=main` を設定すると `main` に追従します。このページはリリース `v0.6.0` を説明しており、ここに挙げたすべての機能を含んでいます。
