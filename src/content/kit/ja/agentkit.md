# Agentkit アドオン

ターミナルで動くコーディングエージェントは、それぞれが独自のフラグでセッションを継続し、独自の方法で二つめのアカウントを分離し、独自のヘッドレスモードと、権限プロンプトを飛ばすための独自のスイッチを持っています。**[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** は、それらすべての上に一つのコマンド体系を被せます：`ak <kind> [@profile]`。

このアドオンは、このキットを **DWP v7**（パック `v7.7.1`）に**ヘッドレス**な委任トランスポートとして統合します。任意のアドオンであり、これがなければ、すべてのタスクはこれまでとまったく同じく現在のセッションで実行されます。キット自体は MIT のプロダクトで、Deep Work Plan がなくても動作します。

## キットが提供するもの

- **すべての CLI に共通の文法。** `ak claude`、`ak codex`、`ak cursor`、`ak opencode`、`ak pi`、`ak cline`、`ak grok`、さらにプロバイダーごとのバリアント（GLM、Azure、xAI）が、同じセッションフラグを使います。`-c` で継続し、`-r <id>` で再開します。
- **プロファイル。** `ak claude @work` は二つめのアカウントを専用のホームで実行し、一つめのアカウントから分離します。
- **ヘッドレス実行。** `ak run <kind> -- "<prompt>"` は一つのプロンプトを非対話で実行し、文書化された終了コードを返します。任意で一つの JSON オブジェクトとして返すこともできます。
- **ドクター。** `ak doctor --json` は、インストール済みの CLI、プロファイル、そして設定済みのキーの名前を報告します。値を報告することはありません。
- **検証済みのインストール。** `ak install <cli>` は、不足している CLI をベンダーの公式チャネルから固定バージョンでインストールし、固定された sha256 または npm レジストリの完全性情報と照合します。
- **なじみのある名前。** 二つのエイリアスプリセットがあり、有効にするまではオフです：`classic`（`claudex`、`codexx`、`cursorx`、`opencodex`、`pix`、`clinex`、`grokx`）と `providers`（`claude-glm`、`codex-azure`、`codex-xai`、`pi-glm`、…）。いずれも一つの `ak <kind>` に対応します。

## アカウント、クォータ、アカウントの選び方

キットは、あなたが持つログインやキーの一つひとつを**アカウント**として扱います。一つの CLI × 一つのプロファイルです。`@default`（または `@1`）は CLI 自身の home で、`@2`、`@work`、`@client-x` は別々のログインです。それぞれプロファイルのルート配下の専用ディレクトリに置かれ、並行して動きます。`ak profiles` はそれらをログイン状態とキーの名前とともに一覧表示し、`ak profiles --json` はツール向けに同じ一覧を返します（スキーマ `profiles-v1`）。`v0.5.1` 以降は、Claude Code のトークンが実際にどこにあるか（`file`、`keychain`（macOS）、`none`、`unknown`）を、シークレットを読まずに存在の有無だけで報告します。また、コンテナ内でも Linux ホスト上でも、Linux 上の Cursor ログインを認識します。`v0.5.2` 以降は、`AGENTKIT_DEFAULT_PROFILE_<CLI>` で引数なしの `ak <cli>` が使うアカウントを指定できます（位置引数の `@profile` が引き続き優先されます）。開発コンテナはこの仕組みで、共有するホストアカウントを選びます。`v0.5.3` 以降、別のマシンと共有している Codex home に、このマシン上にないバックグラウンドデーモンが記録されている場合、`ak codex` は `--no-daemon` を付けます。

`ak usage`（`ak status` でも可）は、キットが把握しているすべての CLI のすべてのアカウントを、CLI ごとにアカウントとプロファイル単位で 1 行ずつ一覧表示します。Claude Code のサブスクリプション（5 時間、週次、モデル別のウィンドウ）、ChatGPT での Codex ログイン、Z.AI コーディングプランのキー、そして `v0.7.0` 以降は Linux とコンテナ内での Antigravity の Google ログイン（agy 自身の `/usage` パネルにある 5 時間と週次のウィンドウ）のクォータをライブで取得します。クォータを読み取れないアカウントにも行があり、接続方法と理由を添えて `n/d`（Cursor、Grok、xAI、Azure OpenAI、Gemini API キー、または macOS のキーチェーンに保存された Antigravity ログイン）と表示するか、ログインするためのコマンドを添えて `no login` と表示します。そのため、この表で各 CLI のどのアカウントが接続済みかもわかります。読み取り専用で、ログインを更新することも、トークンを表示することも、プロファイル内に書き込むこともありません。`--json` はツール向けに同じ一覧を返します（スキーマ `usage-v1`）。使用量のエンドポイントはベンダー内部の非公式なものです。

`ak pick <kind>` は同じ行を読み、余裕の最も大きいアカウントを示します。`--count N` は余裕の大きい順に最大 N 個のアカウントを返し、`--exclude @<profile>` は使用中のアカウントを除外し、`--model` は一つのモデルの週次ウィンドウで数え、`--need 5h:40` はそれだけの余裕がなければ選択を拒みます。`--json` はスキーマ `pick-v1` を返します。

```bash
ak usage                   # すべてのアカウントとプロファイルのクォータ
ak pick claude --count 3   # 余裕が最も大きい Claude アカウント 3 つ
ak claude @work --trust-cwd  # 2 つ目のアカウント、フォルダは事前に信頼
ak profiles --json         # ツール向けの profiles-v1
ak setup verify            # 順序付きのチェック（それぞれに修復コマンド付き）
```

`--trust-cwd`（または `AGENTKIT_TRUST_CWD=1`）は、エージェントが起動するフォルダを事前に信頼するため、Claude Code と Codex はフォルダ信頼の画面なしで開きます。`ak setup probe | verify | docker` は `agentkit-setup` スキルが使う読み取り専用のヘルパーで、マシンを調べ、インストールを検証し、タグで固定され検証済みのコンテナレシピを生成します。

## 複数のエージェント、複数のアカウント

`agentkit-orchestrate` スキル（`ak --skill orchestrate`）は、作業を複数のエージェント、アカウント、ベンダーに分散させる方法をエージェントに教えます。バッチの前に `ak usage` を一度実行し、`ak pick --count N` でアカウントを選び、アカウントごとに一つの委任先を置き、すべての結果にリポジトリ自身のゲートを実行し、あるアカウントが上限に達したら次のアカウントへ切り替えます。キットは観測し、計算し、実行しますが、スケジューリングはしません。判断するのはリード（あなた、またはあなたが依頼したエージェント）であり、使うのは自分のアカウントだけで、各ベンダーの規約の範囲内に留めます。

長時間の対話的なレーンでは、各レーンが [Herdr](/kit/herdr) のペインで自分のアカウントを使って動きます。方法論の章[多数のエージェントを動かす](/methodology/06-orchestration)は、モデル全体を説明しています。リードとそのレーン、余裕で選ぶアカウント、herdr-peers による調整、そしてリポジトリごとに一つのブランチと一つのリリースです。[スウォームの自律性](/ja/methodology/07-swarm-autonomy)は、キャパシティの確認、ハンドオフ、リードの継承を加えます。

## キャパシティとリース

`v0.6.0` 以降、エージェントは自分のアカウントにどれだけ余裕があるかを、すべてのタスクの境目で低コストに尋ねられます。これが、アカウントが尽きる前にスウォームが作業を引き渡すための合図です（[スウォームの自律性](/ja/methodology/07-swarm-autonomy)）。

- **`ak capacity --self --json`**（スキーマ `capacity-v1`）は、実行中のアカウントの `headroom_pct`、その `binding_window`、`resets_at`、そして `verdict` を返します。`verdict` は `ok`、`low`（25 % 以下）、`critical`（10 % 以下、またはレート制限中）、`unknown`（クォータの情報源がない：Cursor、Grok、または macOS 上の Antigravity）のいずれかです。`ak pick` と同じ計算を使うため両者が食い違うことはなく、300 秒保持される使用量キャッシュ（`--max-age`）を読むため、タスクの境目ごとの確認も低コストに保たれます。`--self` は `ak` が起動したアカウントを解決します。`ak` による起動の外では終了コード 3 で終了し、推測することは決してありません。`ak usage` は引き続きライブで読み取り、キャッシュを更新します。
- **しきい値と訓練。** `AGENTKIT_CAPACITY_LOW` と `AGENTKIT_CAPACITY_CRITICAL`（または `--low` と `--critical`）でしきい値を動かせます。`AGENTKIT_CAPACITY_CAP=@<profile>=<pct>` は読み取り値を下げることしかできません。訓練でアカウントを余裕のないように見せる方法であり、アカウントをより余裕があるように見せることは決してできません。
- **`ak lease <kind> @<profile> --owner <addr>`** は一つのレーンのためにアカウントを確保します。後継がハンドオフを受け入れたら `ak lease release …` で解放し、`ak lease ls` でリースを一覧表示します（スキーマ `leases-v1`）。Codex のプロファイルが受け付けるリースは一つだけで（認証ファイルごとに書き手は一人）、リースを解放できるのはその所有者だけです。リースは期限切れになり、数値、プロファイル名、ペインのアドレスを記録した助言的な記録にすぎず、認証情報では決してありません。
- **`ak pick <kind> --owner <lead>`** は、所有者自身のものも含め、有効なリースをすべて数えます。候補を `headroom / (1 + leases)` で順位付けし、リース中の Codex アカウントは保有者自身にも決して提示しません。`--reuse @<profile>` は所有者自身のリースの一つを引き継がせます。たとえばレーンの後継に渡す場合です。`--owner` がなければ順位付けは変わりません。

```bash
ak capacity --self --json                        # このエージェント自身の余裕と判定
ak lease claude @work --owner local:w2:p1        # レーンのためにアカウントを確保する
ak pick codex --owner local:w1:p1 --count 2      # 他者にリースされたアカウントを飛ばす
```

作業が移るのは、計画のために宣言したアカウントの間だけであり、各ベンダーの規約の範囲内です。どのエージェントもアカウントを作成せず、ログインを更新せず、Codex のリセットを使いません。Deep Work Plan のパックは自身のヘルパーを通じて判定を読み、それを継続、準備、ハンドオフのいずれかに変えます。キットがない場合や古いキットの場合、キャパシティは unknown として報告され、ok として報告されることは決してありません。

## インストール

```bash
git clone --branch v0.7.1 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

要件：macOS または Linux 上の `bash`、および `python3` 3.9 以降。それ以外は不要です。Windows では `install.ps1` を使います。`v0.7.1` に固定してください。`v0.2.0` と `v0.2.1` はサポート対象外です。リリースは、その `SHA256SUMS` アセットで検証してください。

| 項目 | 値 |
|---|---|
| プロダクト | `DailybotHQ/coding-agents-kit`、タグ `v0.7.1`、インターフェース 1 |
| レジストリキー | `.dwp/config.json` 内の `agentkit` |
| トランスポート | ヘッドレス：委任先ごとに専用の git worktree で `ak run` を一回 |
| 提供するもの | `subagents`、`cancel_children`、`model_routing` |
| 必要なもの | 計画コントラクトの `agent_delegation` 付与 |

## デフォルトは自律実行、オプトアウトが常に優先

`v0.2.0` 以降、`ak <kind>` はすべてのエージェントを**自律モード**で起動します。CLI 自身の自律フラグを追加し、そのフラグはキットの `providers.toml` にのみ保持されます。自律モードは、開発コンテナのような使い捨ての環境やサンドボックス化された環境を想定しています。

**オプトアウトが常に優先されます**：一つのコマンドに `--ask` を付けるか、環境またはキットの env ファイルに `AGENTKIT_PERMISSIONS=ask` を設定すると、同じコマンドに `--auto` があってもフラグは抑止されます。オプトアウトしたセッションは、自らが起動するエージェントにもオプトアウトを引き継ぎます。ホスト上では、オプトアウトを設定してください。

このアドオンは自律フラグを一切記述せず、`--auto` を渡すこともありません。計画がオプトアウトを記録している場合は `--ask` を渡します。ホスト上で `agent_delegation` を付与する計画は、それぞれの worktree に閉じ込められた自律的な委任先を受け入れることになりますが、worktree はサンドボックスではありません。

## 計画に追加されるもの

コントラクトが `agent_delegation` を付与している v7 の計画では、`execute` が `parallel_safe` なタスクを別の CLI に渡せます。専用の git worktree を作成し、そこでタイムアウト付きで `ak run` を実行し、結果を計画の `analysis_results/delegations/` に収集します。結果は、計画自身のゲートランナーが観測するまで `asserted` な証拠です。委任先をキャンセルすると、そのプロセスツリー全体が停止します。

## Agentkit か Herdr か

| 状況 | 使うもの |
|---|---|
| 出力が宣言された、範囲の限定された `parallel_safe` なタスク | Agentkit（ヘッドレス） |
| タスクに対話が必要、長時間実行される、または別のマシン上にある | [Herdr](/kit/herdr)（ペイン内のピア） |

二つは組み合わせられます。herdr-peers は、`ak env <kind> @profile` が出力する環境を使って、ペイン内にピアを起動できます。多数のレーンを同時に動かす場合は、[多数のエージェントを動かす](/methodology/06-orchestration)を参照してください。

## 補足

任意であり、必須となることはありません。API キーの値が出力されたり、ログに記録されたり、設定ファイルに書き込まれたりすることはありません。文書化された例外は Cline で、コマンドライン上でキーを受け取ります。OpenCode、Pi、Cline、Grok の結果抽出はベンダーのドキュメントに基づいて構築されており、実際のアカウントに対してはまだ検証されていません。認識できない出力は生のテキストにフォールバックします。
