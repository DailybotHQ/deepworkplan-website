# dwp-create

Create a new Deep Work Plan from a high-level goal.

<CmdCreate lang="en" class="not-prose my-8" />

## What it does

`dwp-create` takes a high-level goal and turns it into a structured, executable Deep Work Plan. It analyzes requirements, asks clarifying questions if ambiguous, and materializes a Lite or Full plan directly under `.dwp/plans/PLAN_<id>_<slug>/`.

## Usage

```
/dwp-create <goal>
/dwp-create trust lite <goal>
/dwp-create <goal> full trust
```

## Modes and boundary options

Boundary options configure review behavior and plan format. They can appear as tokens at the beginning or end of the command in either order:

- **Review modes:**
  - **Guided (default):** materializes an executable Lite plan proposal, shows observed signals and format rationale, and asks whether to retain Lite, promote to Full, edit, or stop.
  - **Trust (`trust` or `auto`):** skips review and goes straight to a pre-approved, ready-to-run plan.
- **Format preferences:**
  - **`lite`:** expresses a preference for a compact single-file plan in `README.md` with anchored task records (`#task-N`).
  - **`full`:** expresses a preference for decomposed numbered task files (`N.task_<slug>.md`).
  - Specifying both `lite` and `full` is an explicit conflict.
- **Terminator:** `--` terminates option parsing; everything after `--` is interpreted as literal goal context.

## Behavior

1. **Requirements analysis:** inspects repository context, architecture, and documented testing commands.
2. **Clarification:** asks clarifying questions if scope or requirements are ambiguous.
3. **Monotonic allocation:** allocates a zero-padded folder name `PLAN_<id>_<slug>/` under `.dwp/plans/` using `.next-plan-id` under POSIX file lock (`fcntl`). Numeric IDs are monotonic and never reused.
4. **Contract materialization:** runs `ledger.py materialize` to write `manifest.json`, stamp content-addressed `contract.json` (v7 generation with `parallel_safe` task markers), and record the initial `approval` event.
5. **Final Review:** plans end with a mandatory five-part Final Review task (security pass with required local review, final-state validation, skills reconciliation, documentation reconciliation, completion).
