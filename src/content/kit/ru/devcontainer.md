# Аддон Devcontainer

Дайте репозиторию воспроизводимый, изолированный контейнер для разработки — такой, которым могут пользоваться люди, редакторы и агенты для программирования. В **бете DWP v7** (`v7.0.0-beta.1`, предварительный релиз) этот аддон интегрирует **[devcontainer-kit](https://github.com/DailybotHQ/devcontainer-kit)** — продукт под лицензией MIT, работающий без Deep Work Plan, — и заменяет шаблон, который раньше содержал пакет. Он опционален: репозиторий без него полностью соответствует требованиям.

## Что предоставляет devcontainer-kit

- **Шаблон** на основе спецификации [Dev Containers](https://containers.dev), который `dck init` рендерит в репозиторий: `devcontainer.json`, файл compose и `docker/local/`. При повторном запуске он согласовывает изменения и никогда не затирает ваши правки; любое изменение существующего файла сначала показывается и требует согласия.
- **`dck`** — лаунчер, который запускает контейнер из обычного терминала — `setup`, `up`, `shell`, `ssh`, `rebuild`, `doctor` — с VS Code или Cursor либо без них.
- **Базовые образы** в трёх вариантах, `python-3.13`, `node-24` и `debian`, которые поставляются **без** агентов для программирования.
- **Библиотека entrypoint** для постоянных томов, SSH и окружения SSH-сессий вместо вручную скопированного entrypoint в каждом репозитории.
- **Машины Herdr.** Каждый контейнер может подключиться к [Herdr](https://herdr.dev) через SSH-сервер, доступный только через loopback, так что агенты в нём становятся достижимыми peer-агентами.

## Установка

```bash
git clone --branch v0.1.2 https://github.com/DailybotHQ/devcontainer-kit && ./devcontainer-kit/install.sh
cd your-repo && dck init
```

Требования: `bash` 3.2 или новее и `python3` 3.11 или новее на хосте с Linux или macOS, а также Docker с Compose v2 для команд контейнера. Проверьте релиз по его ресурсу `SHA256SUMS`.

| Элемент | Значение |
|---|---|
| Продукт | `DailybotHQ/devcontainer-kit`, тег `v0.1.2`, интерфейс 1 |
| Ключ реестра | `devcontainer` в `.dwp/config.json` |
| Конфигурация репозитория | `.devcontainer/dck.toml` |
| Обнаружение | `dck doctor --json` |

## Слои включаются по выбору

Базовые образы содержат инструменты разработки — git, gh, ripgrep, SSH-сервер, Herdr и Neovim с DeepWorkPlan Vim, закреплённым по тегу, — и ни одного агента для программирования, ни CLI для отчётности, ни секретов. Всё остальное — это слой, который вы включаете в `dck.toml`:

| Слой | По умолчанию | Что он добавляет |
|---|---|---|
| `agents` | выкл. | Устанавливает [coding-agents-kit](/kit/agentkit) и перечисленные вами CLI, каждый со своим постоянным томом. Никакой флаг обхода разрешений не устанавливается. |
| `editor` | вкл. | Neovim с DeepWorkPlan Vim; выключение даёт обычный редактор. |

## Настройки безопасности по умолчанию

- Каждый публикуемый порт привязывается к `127.0.0.1`, если `dck.toml` не задаёт `bind`.
- Проброс SSH-агента с хоста; приватные ключи хоста никогда не копируются в контейнер.
- SSH-ключи хоста генерируются во время выполнения в том отдельного проекта и никогда не запекаются в образ; сервер принимает только публичные ключи, без входа под root и без паролей.
- Шаблон не добавляет `cap_add`, режим `privileged` и сокет Docker.
- Базовые образы и инструменты закреплены по версии и проверены контрольной суммой; compose ссылается на базовый образ по digest, когда digest удаётся определить.

## Примечания

Опционален и никогда не обязателен. Репозиторий без опциональных аддонов полностью соответствует требованиям. v0.1 поддерживает хосты с Linux и macOS.
