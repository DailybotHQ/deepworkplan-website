# Аддон Devcontainer

Дайте репозиторию воспроизводимый, изолированный контейнер для разработки — такой, которым могут пользоваться люди, редакторы и агенты для программирования. В **DWP v7** (пакет `v7.3.3`) этот аддон интегрирует **[devcontainer-kit](https://github.com/DailybotHQ/devcontainer-kit)** — продукт под лицензией MIT, работающий без Deep Work Plan. Он опционален: репозиторий без него полностью соответствует требованиям.

## Что предоставляет devcontainer-kit

- **Шаблон** на основе спецификации [Dev Containers](https://containers.dev), который `dck init` рендерит в репозиторий в одной фиксированной структуре: `.devcontainer/devcontainer.json`, `docker/local/<service>/Dockerfile`, `docker/local/docker-compose.yaml` и `dev.sh`. При повторном запуске он согласовывает изменения и никогда не затирает ваши правки; любое изменение существующего файла сначала показывается и требует согласия.
- **Собственный контейнер репозитория.** Dockerfile начинается с официального образа среды выполнения, закреплённого по digest, — `node-24`, `python-3.13` или `debian` — и копирует шаги сборки kit в `docker/local/<service>/dck/`. Общий базовый образ не используется.
- **`dev.sh` и `dck`.** `bash dev.sh up` собирает, запускает контейнер и подключается к нему из обычного терминала; `shell`, `rebuild`, `doctor` и остальные команды работают с VS Code или Cursor либо без них.
- **Herdr в обе стороны.** [Herdr](https://herdr.dev) на хосте подключает каждый контейнер как машину через SSH-сервер, доступный только через loopback, а контейнер открывается со стандартной боковой панелью: Home, Editor, Development и Agents. Внутри [herdr-peers](/kit/herdr) позволяет агентам обращаться к агентам на хосте и в других контейнерах.
- **Навык `dck-dockerfile`.** Агент по запросу создаёт или перегенерирует контейнер репозитория и подтверждает его реальной сборкой.

## Установка

```bash
git clone --branch v0.2.8 https://github.com/DailybotHQ/devcontainer-kit && ./devcontainer-kit/install.sh
cd your-repo && dck init && bash dev.sh up
```

Требования: `bash` 3.2 или новее и `python3` 3.11 или новее на хосте с Linux или macOS, а также Docker с Compose v2 для команд контейнера. Проверьте релиз по его ресурсу `SHA256SUMS`. Закрепите `v0.2.8`: `v0.2.0` не поддерживается.

| Элемент | Значение |
|---|---|
| Продукт | `DailybotHQ/devcontainer-kit`, тег `v0.2.8`, интерфейс 2 |
| Ключ реестра | `devcontainer` в `.dwp/config.json` |
| Конфигурация репозитория | `.devcontainer/dck.toml` |
| Обнаружение | `dck doctor --json` |

## Слои

Каждый контейнер содержит инструменты разработки — git, gh, ripgrep, SSH-сервер, Herdr и herdr-peers — и ни одного секрета. Всё остальное — это слой, который вы выбираете в `dck.toml`:

| Слой | По умолчанию | Что он добавляет |
|---|---|---|
| `agents` | выкл. | [coding-agents-kit](/kit/agentkit) из его проверенного релиза и перечисленные вами CLI, каждый со своим постоянным томом, а также пресеты `classic` (`claudex`, `codexx`, …) и `providers` (`claude-glm`, `codex-azure`, …). Агенты по умолчанию работают в автономии — песочницей служит контейнер. Отказ: `AGENTKIT_PERMISSIONS=ask` в `.env` сервиса. |
| `editor` | вкл. | Neovim с [DeepWorkPlan Vim](/kit/vim), закреплённым по тегу; выключение даёт обычный редактор. |
| `dailybot` | выкл. | CLI Dailybot для аддона dailybot. |

Входы в аккаунты, `gh`, конфигурация Herdr и git-идентичность сохраняются после `bash dev.sh rebuild`.

## Агенты на разных машинах

Начиная с `v0.2.3`, `dck up` в Docker Desktop настраивает двустороннюю сеть без ручных шагов:

- **Контейнеры и хост.** Агенты внутри контейнера достигают агентов Herdr на хосте, в каждом другом контейнере dck и в других loopback-контейнерах, которыми уже управляет Herdr вашего хоста, — а те достигают их в ответ. У каждого peer-агента закреплённый ключ хоста; ничто не получает доверия при первом подключении.
- **Необязательный listener на хосте.** `dck setup` один раз предлагает SSH-сервер уровня пользователя на `127.0.0.1`, который принимает только ключ dck и поддерживается в работе через launchd (macOS). Если у вас уже работает loopback-listener, вместо этого укажите его в профиле хоста. `dck host listener disable` удаляет его.
- **Переживает пересборки.** Каталог машин Herdr контейнера хранится в томе, поэтому `bash dev.sh rebuild` сохраняет все зарегистрированные в нём машины.
- **Ответы и с хоста.** `dck setup` устанавливает на хост проверенный [herdr-peers](/kit/herdr), поэтому `dck agents` и `dck ask` работают и там, а агенты хоста отвечают через `herdr-peers reply`.
- **Контейнеры, созданные не kit.** Перечислите публичные ключи, с которыми они входят, в `[ssh] authorized_extra` профиля хоста, и они тоже смогут достигать контейнеров dck.

Используйте вместе с [coding-agents-kit](/kit/agentkit) на хосте и в контейнере, и один и тот же `ak` будет запускать агентов на обеих сторонах.

## Настройки безопасности по умолчанию

- Каждый публикуемый порт привязывается к `127.0.0.1`, если `dck.toml` не задаёт `bind`.
- Git по SSH работает через SSH-агент хоста — его сокет, никогда не файл ключа и никогда не смонтированные `~/.ssh` или `~/.gitconfig`. Git-идентичность берётся из значений `DCK_GIT_*`, которые заполняет `dck setup`.
- SSH-ключи хоста генерируются во время выполнения в том отдельного проекта и никогда не запекаются в образ; сервер принимает только публичные ключи, без входа под root и без паролей.
- Шаблон не добавляет `cap_add`, режим `privileged` и сокет Docker.
- Каждая загрузка закреплена по версии и проверена контрольной суммой; базовый образ закреплён по digest.
- Сеть Herdr, через которую агенты в одном контейнере достигают остальных, включена по умолчанию и описана вместе со способами её отключения в модели угроз kit. Listener на хосте позволяет коду в запущенном контейнере открыть shell на хосте от вашего имени: он включается только по явному согласию, работает только через loopback, принимает только ключ dck и удаляется командой `dck host listener disable`.

## Примечания

Опционален и никогда не обязателен. Репозиторий без опциональных аддонов полностью соответствует требованиям. v0.2 поддерживает хосты с Linux и macOS; сеть между контейнерами требует Docker Desktop.
