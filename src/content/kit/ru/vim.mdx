# DeepWorkPlan Vim

**DeepWorkPlan Vim** — терминальный редактор для Deep Work Plan: конфигурация Neovim для людей и для программирующих агентов, которые работают в терминале. Ваши планы, документация и индекс всех команд находятся в одном нажатии клавиши.

Это отдельный продукт, который предлагается как необязательный аддон `vim` Deep Work Plan v7 (`v7.0.0`). Deep Work Plan работает с любым редактором или без него, а редактор не требует Deep Work Plan: вы добавляете его на машину самостоятельно, и он работает как редактор независимо от того, есть ли план. Эта страница описывает релиз **v0.6.0**.

## Зачем терминальный редактор для Deep Work Plan

Deep Work Plan — это папка с Markdown в `.dwp/plans/`: цель, атомарные задачи, validation gates и постоянно ведущийся журнал. Люди проверяют его, агенты выполняют, и те и другие часто делают это из терминала. Редактор, созданный для такой работы, держит под рукой три вещи: сам план, документацию вокруг него и клавиши, которые перемещают вас между ними.

DeepWorkPlan Vim — именно такой редактор. Цель — мини-VS Code в терминале: перемещаться по файлам, видеть, какие файлы изменились, просматривать diff и принимать или отклонять изменения; дружелюбный и лёгкий, ориентированный в первую очередь на агентов, с постоянно видимым статусом плана. Это продуманная конфигурация Neovim — языковые серверы, автодополнение, форматирование, нечёткий поиск, дерево файлов и подобранные цветовые темы с ленивой загрузкой — плюс несколько интерфейсов, которые делают её редактором для Deep Work Plan.

## Обзор: индекс команд, который не может устареть

Нажмите `SPC h h` (Пробел — это лидер-клавиша) или выполните `:DwpCommands`, и редактор выведет все свои сочетания с однострочным описанием. Список создаётся из актуальных раскладок клавиш, поэтому сочетание, определённое где угодно, появляется в индексе без регистрации, а сам индекс не может устареть.

Вот и весь обзор: запустите `nvim`, затем нажмите Пробел, `h`, `h`.

## Что вы получаете

Пять возможностей, каждая — в одном нажатии клавиши.

| Возможность | Клавиши | Что делает |
|---|---|---|
| Генерируемый индекс команд | `SPC h h` | Все сочетания конфигурации, созданные из актуальных раскладок клавиш. |
| Жесты в стиле VS Code | `<C-a>`, `SPC y` | Выделение всего файла одной клавишей и копирование в системный буфер обмена. Обычный `y` тоже копирует туда, потому что буфер обмена общий для всей системы. |
| Браузер планов Deep Work Plan | `SPC P` | Боковая панель по планам вашего репозитория, сгруппированным по статусу и с индикаторами прогресса; щелчок по плану открывает режим чтения. |
| Просмотрщик Markdown | `SPC m p`, `SPC m r` | Предпросмотр Markdown в браузере или отрисовка в буфере. |
| Проверенный установщик | — | Самодостаточный установщик для macOS, Linux и WSL с задокументированным ручным путём для Windows. |

## Планы, не выходя из редактора

`SPC P`, `:DwpPlans` или щелчок по сегменту строки состояния открывает боковую панель планов. Она охватывает каждую папку `.dwp/plans/` в текущем каталоге и в каталоге конфигурации Neovim и ставит выше те планы, которым нужно больше внимания. В редакторе метки такие: `Working`, `Needs attention`, `Ready`, `Not started` и `Done`. Для каждого плана показан индикатор прогресса.

Щёлкните по плану или нажмите на нём Enter, чтобы открыть режим чтения: цель в одном предложении, статус и прогресс, список задач с отмеченной текущей задачей и понятные переходы к файлам самого плана. Строка состояния показывает текущий активный план, а стартовый экран перечисляет первые три. Эти интерфейсы объясняют планы и никогда ничего не записывают в `.dwp/`.

Боковая панель отзывается и на мышь, и на клавиатуру. Маленькая стрелка рядом с планом показывает или скрывает его задачи и файлы, а щелчок по задаче или файлу открывает его. `j`, `k`, стрелки, `Ctrl-n` и `Ctrl-p` переходят от плана к плану, пропуская пустые строки и оформление. Каждый раздел показывает своё количество, цвета статуса отмечают значок и индикатор прогресса, у активных планов насыщенные заголовки, а у завершённых приглушённые, и группа Done из более чем шести планов открывается свёрнутой. Окно доступно только для чтения и ведёт себя тихо: клавиши редактирования ничего не делают, а не выводят ошибку.

Планы и дерево файлов сменяют друг друга: открытие одной боковой панели закрывает другую, так что вы смотрите на одно за раз. Режим чтения закрывается вместе с боковой панелью планов. Закрывает ли открытие одной боковой панели другую, задаёт ключ `sidebars.exclusive` в `dwpvim.json`.

Чтобы читать Markdown-файлы плана на месте, `SPC m p` показывает текущий буфер в браузере, а `SPC m r` отрисовывает его внутри буфера. Оба работают только в буферах Markdown.

## Дашборд

Стартовый экран — собственный экран DeepWorkPlan Vim. На нём логотип Deep Work Plan, выгравированный символами Брайля, с крошечной надписью VIM под буквой P, ниже подпись "powered by Dailybot", а справа гравированная сцена: маяк Deep Work Plan и корабль, плывущий по его морю. Пока дашборд на экране, луч медленно пульсирует; чтобы отключить это, задайте `vim.g.dwp_greeter_pulse = false`.

Сцена существует в шести высотах, которые выбираются по числу свободных строк окна. В более узком окне название располагается над сценой или остаётся одно. В широких окнах сочетания клавиш и список планов показаны рядом, в узких — друг под другом. Нажмите Enter, чтобы активировать строку под курсором, или `e`, чтобы открыть боковую панель планов.

## Настройка боковых панелей

Файл `dwpvim.json` задаёт, с какой стороны находятся две боковые панели и какой они ширины. Файл в каталоге редактора (`~/.config/nvim`) действует для всех проектов, а `.dwpvim.json` в каталоге, где вы запускаете Neovim, переопределяет его для этого проекта. Настройки читаются при запуске, поэтому после правки файла перезапустите Neovim.

```json
{
  "tree":  { "side": "left", "width": 40 },
  "plans": { "side": "left", "width": 48 },
  "sidebars": { "exclusive": true }
}
```

| Ключ | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `tree.side` | `"left"` или `"right"` | `"left"` | Сторона дерева файлов (`SPC n`) |
| `tree.width` | целое число от 20 до 120 | `40` | Максимальная ширина дерева; оно по-прежнему сжимается до своего содержимого |
| `plans.side` | `"left"` или `"right"` | `"left"` | Сторона боковой панели планов (`SPC P`) |
| `plans.width` | целое число от 20 до 120 | `48` | Максимальная ширина боковой панели планов |
| `sidebars.exclusive` | `true` или `false` | `true` | Одна боковая панель за раз; при `false` обе могут оставаться открытыми |

Отсутствие файла не проблема. Файл с недопустимым JSON, неизвестный ключ или недопустимое значение игнорируются с сообщением и никогда не приводят к сбою. Выполните `:DwpConfig`, чтобы увидеть все действующие значения, файл, из которого они взяты, и найденные проблемы.

## Более лёгкий редактор

Версия 0.6.0 убирает то, чем никто не пользовался, поэтому плагинов для фиксации меньше, а пакетов для установки и обновления при первом запуске меньше:

- Одиннадцать языковых серверов Mason выведены из состава: efm, diagnosticls, tailwindcss, grammarly, bashls, а также серверы для astro, svelte, Vue 2, Angular, SQL и Vim script.
- nvim-lint удалён, потому что ни один линтер никогда не был настроен.
- Записи форматтера prettier удалены, потому что ничто не устанавливало prettier. `:Format` по-прежнему использует biome, black, shfmt и stylua.
- marksman остаётся для перехода по ссылкам, автодополнения ссылок и заголовков и структуры документа, а его диагностика отключена. Markdown намеренно остаётся без форматтера.

Включены только серверы, перечисленные в конфигурации, даже если Mason всё ещё хранит другие от прежней установки. Каждый плагин, сервер и инструмент с указанием причины, по которой он здесь, перечислен в [PLUGINS.md](https://github.com/DailybotHQ/deepworkplan-vim/blob/v0.6.0/docs/PLUGINS.md).

## Установка

Установка — это три команды: скачайте скрипт, сверьте его с SHA-256 файла, который отдаёт этот сайт, затем запустите. Установщик фиксирует собственный релиз, поэтому устанавливает именно `v0.6.0` — релиз, который описывает эта страница, если только вы не [выберете другую версию](#choose-a-version).

<VimInstall lang="ru" />

По порядку установщик:

1. Проверяет вашу ОС и менеджер пакетов и устанавливает git, curl и интерпретатор Lua, если чего-то не хватает (с `--skip-packages` — ничего).
2. Определяет версию: собственный релиз или тот, который запрошен через `--version`.
3. С `--nvim X.Y.Z` устанавливает этот релиз Neovim в `~/.local/opt` и проверяет его по SHA-256, который публикует Neovim.
4. Спрашивает, прежде чем трогать существующую конфигурацию Neovim. Без терминала останавливается и ничего не меняет, если только `--yes` не велит ему отодвинуть эту конфигурацию в сторону.
5. Клонирует репозиторий в `~/.config/nvim` или обновляет его, если он уже там.
6. Запускает собственный `lua install.lua` из репозитория.
7. Устанавливает плагины в фоновом режиме и проверяет их, поэтому выходить и открывать заново не нужно. С `--strict` неудачная или неполная установка плагинов считается ошибкой.

Скрипт, который отдаётся здесь, — побайтно идентичная копия `install.sh` на теге `v0.6.0`. Его контрольная сумма отдаётся рядом, по адресу `https://deepworkplan.com/vim/install.sh.sha256`, поэтому загрузку можно проверить командой `shasum -a 256 -c install.sh.sha256` (в Linux — `sha256sum -c install.sh.sha256`). Для проверки из второго источника сравните её со строкой `install.sh` в `SHA256SUMS` релиза на GitHub. Выполните `bash install.sh --help`, чтобы увидеть все параметры.

## Выбор версии

По умолчанию установщик устанавливает собственный релиз, `v0.6.0`. Чтобы выбрать другой, задайте `DWP_VIM_VERSION` или передайте `--version`: оба способа делают одно и то же, поэтому используйте тот, что удобнее читать; флаг имеет приоритет над переменной окружения. Каждый принимает:

| Форма | Пример | Устанавливает |
|---|---|---|
| Точная версия | `0.6.0` или `v0.6.0` | Этот релиз |
| Минимальная граница | `'>=0.4.2'` | Новейший стабильный релиз не ниже границы |
| Последняя | `latest` | Новейший стабильный релиз |

После загрузки и проверки контрольной суммы, описанных выше:

```bash
# exact version
DWP_VIM_VERSION=0.6.0 bash install.sh
bash install.sh --version 0.6.0

# minimum floor: the newest stable release at or above 0.4.2
DWP_VIM_VERSION='>=0.4.2' bash install.sh

# latest stable release
bash install.sh --version latest
```

Заключайте границу в кавычки, чтобы оболочка не прочитала `>` как перенаправление. Версии разрешаются только в теги стабильных релизов. Для ветки или коммита задайте вместо этого `DWP_VIM_REF` (`DWP_VIM_REF=main` следует за `main`); если версия и ref противоречат друг другу, это ошибка.

### Контейнеры и CI

В образе или задании CI, где нет терминала и часто нет root, скачайте и проверьте скрипт, затем запустите его за один шаг с флагами, которые делают результат воспроизводимым:

```bash
curl -fsSL -o install.sh https://deepworkplan.com/vim/install.sh && \
curl -fsSL -o install.sh.sha256 https://deepworkplan.com/vim/install.sh.sha256 && \
sha256sum -c install.sh.sha256 && \
bash install.sh --version 0.6.0 --nvim 0.12.5 --skip-packages --strict
```

- `--version 0.6.0` фиксирует релиз редактора.
- `--nvim 0.12.5` устанавливает этот релиз Neovim в `~/.local/opt/nvim-v0.12.5`, связывает его как `~/.local/bin/nvim` и проверяет по SHA-256, который публикует Neovim (Linux и macOS).
- `--skip-packages` не устанавливает системных пакетов: образ уже должен содержать git, curl и Lua.
- `--strict` завершается с ненулевым кодом, если установка плагинов в фоновом режиме не удалась или оставила плагины недостающими. Он также проверяет, что каждый плагин и pckr находятся на коммите, закреплённом в выпуске в `pckr/lockfile.lua`.

У каждого флага есть двойник в виде переменной окружения (`DWP_VIM_VERSION`, `DWP_VIM_NVIM`, `DWP_VIM_SKIP_PACKAGES=1`, `DWP_VIM_STRICT=1`). Добавляйте `--yes`, только если в образе уже может быть конфигурация Neovim, которую нужно отодвинуть в сторону.

## Требования и платформы

- Neovim 0.12 или новее. Установите его сами или позвольте установщику добавить проверенный релиз с помощью `--nvim X.Y.Z` (Linux и macOS).
- Lua: `lua`, `lua5.4` или `luajit`. Если его нет, установщик добавит.
- На macOS, Linux и WSL работает установщик. Для Windows в README репозитория описан ручной путь: установите Neovim через winget, клонируйте тег `v0.6.0` в `%LOCALAPPDATA%\nvim` и запустите `lua install.lua` из Git Bash.
- Лицензия GPL-3.0: свободно использовать, изучать и изменять.

## Обновление, фиксация версии и удаление

Чтобы обновить, запустите установщик более нового релиза или выполните `bash install.sh --version latest`. Повторный запуск переводит существующий клон DeepWorkPlan Vim на выбранный релиз, сохраняет ваши ветки и никогда не сбрасывает локальные изменения: если локальные изменения или коммиты были бы потеряны, он останавливается и ничего не меняет.

Чтобы зафиксировать релиз, используйте `--version` (см. [Выбор версии](#choose-a-version)); для ветки или коммита задайте `DWP_VIM_REF`. Предпочитайте релиз: релизы до `v0.4.0` не содержат жестов, браузера планов, просмотрщика Markdown и этого установщика.

```bash
# pin a specific release, here the previous one
curl -fsSL -o install.sh https://deepworkplan.com/vim/install.sh && \
curl -fsSL -o install.sh.sha256 https://deepworkplan.com/vim/install.sh.sha256 && \
shasum -a 256 -c install.sh.sha256 && \
bash install.sh --version 0.5.1
```

Чтобы удалить, выполните `lua delete.lua` в каталоге конфигурации. Он удаляет конфигурацию, плагины, данные Mason, кэш и состояние, а также копию шрифта, сделанную установщиком, и оставляет в покое исполняемый файл Neovim и ваши системные пакеты.

```bash
cd ~/.config/nvim && lua delete.lua
```

## Вопросы

### Перезапишет ли он мою конфигурацию Neovim?

Нет, не без вашего одобрения. Если он находит конфигурацию, которая не принадлежит DeepWorkPlan Vim, интерактивный запуск спрашивает, прежде чем переместить её в `~/.config/previous-deepworkplan-vim`. Без терминала он останавливается и ничего не меняет, если только вы не передадите `--yes`, чтобы отодвинуть её в сторону без участия человека. Если этот путь резервной копии уже существует, он всегда останавливается и ничего не меняет.

### Работает ли он в Windows?

Установщик не работает в Windows. Используйте ручной путь из README репозитория или запустите установщик внутри WSL.

### Нужен ли мне Deep Work Plan, чтобы им пользоваться?

Нет. Это прежде всего редактор. Он не устанавливает навык Deep Work Plan и не требует его; браузеру планов просто нечего показывать, пока нет папки `.dwp/plans/`.

### Как его использует аддон vim в v7?

Deep Work Plan v7 предлагает редактор как необязательный аддон `vim` во время онбординга. Аддон обнаруживает существующую установку в режиме только для чтения, через файл `addon/surface.json` редактора, и предлагает зафиксированную установку с проверкой контрольной суммы только с вашего согласия. Он никогда не перезаписывает существующую конфигурацию Neovim без явного одобрения и никогда не является обязательным.

### Как им пользуются программирующие агенты?

Он создан для людей и для программирующих агентов, которые работают в терминале. Его сочетания клавиш зафиксированы контрактными тестами, поэтому мышечная память и ожидания агента переживают обновления.

### Какую версию я получу?

Установщик ставит релиз, к которому относится, — сегодня это `v0.6.0`, — если вы не выберете другой через `--version` или `DWP_VIM_VERSION`: точную версию, границу `>=` или `latest`. `DWP_VIM_REF` принимает ветку или коммит; `DWP_VIM_REF=main` следует за `main`. Эта страница описывает релиз `v0.6.0`, в который входят все перечисленные здесь возможности.

### Под какой лицензией он и откуда взялся?
