# DeepWorkPlan Vim

**DeepWorkPlan Vim** — терминальный редактор для Deep Work Plan: конфигурация Neovim для людей и для программирующих агентов, которые работают в терминале. Ваши планы, документация и индекс всех команд находятся в одном нажатии клавиши.

Это отдельный продукт, который предлагается как необязательный аддон `vim` бета-версии Deep Work Plan v7 (`v7.0.0-beta.1`, предварительный релиз). Deep Work Plan работает с любым редактором или без него, а редактор не требует Deep Work Plan: вы добавляете его на машину самостоятельно, и он работает как редактор независимо от того, есть ли план. Эта страница описывает релиз **v0.4.0**.

## Зачем терминальный редактор для Deep Work Plan

Deep Work Plan — это папка с Markdown в `.dwp/plans/`: цель, атомарные задачи, validation gates и постоянно ведущийся журнал. Люди проверяют его, агенты выполняют, и те и другие часто делают это из терминала. Редактор, созданный для такой работы, держит под рукой три вещи: сам план, документацию вокруг него и клавиши, которые перемещают вас между ними.

DeepWorkPlan Vim — именно такой редактор. Это продуманная конфигурация Neovim — языковые серверы, автодополнение, линтинг, форматирование, нечёткий поиск, дерево файлов и подобранные цветовые темы с ленивой загрузкой — плюс несколько интерфейсов, которые делают её редактором для Deep Work Plan.

## Обзор: индекс команд, который не может устареть

Нажмите `SPC h h` (Пробел — это лидер-клавиша) или выполните `:DwpCommands`, и редактор выведет все свои сочетания с однострочным описанием. Список создаётся из актуальных раскладок клавиш, поэтому сочетание, определённое где угодно, появляется в индексе без регистрации, а сам индекс не может устареть.

Вот и весь обзор: запустите `nvim`, затем нажмите Пробел, `h`, `h`.

## Что вы получаете

Пять возможностей, каждая — в одном нажатии клавиши.

| Возможность | Клавиши | Что делает |
|---|---|---|
| Генерируемый индекс команд | `SPC h h` | Все сочетания конфигурации, созданные из актуальных раскладок клавиш. |
| Жесты в стиле VS Code | `<C-a>`, `SPC y` | Выделение всего файла одной клавишей и копирование в системный буфер обмена. Обычный `y` тоже копирует туда, потому что буфер обмена общий для всей системы. |
| Браузер планов Deep Work Plan | `SPC P` | Боковая панель по планам вашего репозитория, сгруппированным по статусу и с индикаторами прогресса, и режим чтения для одного плана. |
| Просмотрщик Markdown | `SPC m p`, `SPC m r` | Предпросмотр Markdown в браузере или отрисовка в буфере. |
| Установка одной строкой | — | Самодостаточный установщик для macOS, Linux и WSL с задокументированным ручным путём для Windows. |

## Планы, не выходя из редактора

`SPC P`, `:DwpPlans` или щелчок по сегменту строки состояния открывает боковую панель планов. Она охватывает каждую папку `.dwp/plans/` в текущем каталоге и в каталоге конфигурации Neovim и ставит выше те планы, которым нужно больше внимания. В редакторе метки такие: `Working`, `Needs attention`, `Ready`, `Not started` и `Done`. Для каждого плана показан индикатор прогресса.

Нажмите Enter на плане, чтобы открыть режим чтения: цель в одном предложении, статус и прогресс, список задач с отмеченной текущей задачей и понятные переходы к файлам самого плана. Строка состояния показывает текущий активный план, а стартовый экран перечисляет первые три. Эти интерфейсы объясняют планы и никогда ничего не записывают в `.dwp/`.

Чтобы читать Markdown-файлы плана на месте, `SPC m p` показывает текущий буфер в браузере, а `SPC m r` отрисовывает его внутри буфера. Оба работают только в буферах Markdown.

## Установка

Вся установка — одна строка. Сама по себе она устанавливает ветку `main` репозитория; задайте `DWP_VIM_REF=v0.4.0`, чтобы установить именно тот релиз, который описывает эта страница.

<VimInstall lang="ru">

```bash
curl -fsSL https://deepworkplan.com/vim/install.sh | bash
```

</VimInstall>

По порядку установщик:

1. Проверяет вашу ОС и менеджер пакетов и устанавливает git, curl и интерпретатор Lua, если чего-то не хватает.
2. Спрашивает, прежде чем трогать существующую конфигурацию Neovim. Если запущен через конвейер без терминала, останавливается и ничего не меняет.
3. Клонирует репозиторий в `~/.config/nvim` или обновляет его, если он уже там.
4. Запускает собственный `lua install.lua` из репозитория.
5. Устанавливает плагины в фоновом режиме, поэтому выходить и открывать заново не нужно.

Скрипт, который отдаётся здесь, — побайтно идентичная копия `install.sh` на теге `v0.4.0`. Чтобы сначала прочитать его, скачайте его командой `curl -fsSL https://deepworkplan.com/vim/install.sh -o install.sh`, сравните его SHA-256 со значением выше, прочитайте и затем выполните `DWP_VIM_REF=v0.4.0 bash install.sh`.

## Требования и платформы

- Neovim 0.12 или новее. Сначала установите Neovim: установщик его не ставит.
- Lua: `lua`, `lua5.4` или `luajit`. Если его нет, установщик добавит.
- На macOS, Linux и WSL работает однострочная команда. Для Windows в README репозитория описан ручной путь: установите Neovim через winget, клонируйте репозиторий в `%LOCALAPPDATA%\nvim` и запустите `lua install.lua` из Git Bash.
- Лицензия GPL-3.0: свободно использовать, изучать и изменять.

## Обновление, фиксация версии и удаление

Чтобы обновить, запустите установщик снова. Он идемпотентен: существующий клон DeepWorkPlan Vim обновляется через fast-forward, а локальные изменения никогда не сбрасываются.

Чтобы установить конкретный тег, задайте `DWP_VIM_REF`. Фиксируйте тег, а не ветку: релизы до `v0.4.0` не содержат жестов, браузера планов, просмотрщика Markdown и этого установщика.

```bash
curl -fsSL https://deepworkplan.com/vim/install.sh | DWP_VIM_REF=v0.4.0 bash
```

Чтобы удалить, выполните `lua delete.lua` в каталоге конфигурации. Он удаляет конфигурацию, плагины, данные Mason, кэш и состояние, а также копию шрифта, сделанную установщиком, и оставляет в покое исполняемый файл Neovim и ваши системные пакеты.

```bash
cd ~/.config/nvim && lua delete.lua
```

## Вопросы

### Перезапишет ли он мою конфигурацию Neovim?

Нет, не без вашего одобрения. Если он находит конфигурацию, которая не принадлежит DeepWorkPlan Vim, интерактивный запуск спрашивает, прежде чем переместить её в `~/.config/previous-deepworkplan-vim`. Без терминала или если этот путь резервной копии уже существует, он останавливается и ничего не меняет.

### Работает ли он в Windows?

Однострочная команда в Windows не применяется. Используйте ручной путь из README репозитория или запустите её внутри WSL.

### Нужен ли мне Deep Work Plan, чтобы им пользоваться?

Нет. Это прежде всего редактор. Он не устанавливает навык Deep Work Plan и не требует его; браузеру планов просто нечего показывать, пока нет папки `.dwp/plans/`.

### Как его использует аддон vim в v7?

Бета-версия Deep Work Plan v7 предлагает редактор как необязательный аддон `vim` во время онбординга. Аддон обнаруживает существующую установку в режиме только для чтения, через файл `addon/surface.json` редактора, и предлагает зафиксированную установку с проверкой контрольной суммы только с вашего согласия. Он никогда не перезаписывает существующую конфигурацию Neovim без явного одобрения и никогда не является обязательным.

### Как им пользуются программирующие агенты?

Он создан для людей и для программирующих агентов, которые работают в терминале. Его сочетания клавиш зафиксированы контрактными тестами, поэтому мышечная память и ожидания агента переживают обновления.

### Какую версию я получу?

Установщик ставит `main`, если вы не задали `DWP_VIM_REF`. Эта страница описывает релиз `v0.4.0`, в который входят все перечисленные здесь возможности; задайте `DWP_VIM_REF=v0.4.0`, чтобы получить именно этот релиз.

### Под какой лицензией он и откуда взялся?

GPL-3.0. Он создан на основе mu-vim Andrés M Prieto, и указание авторства сохранено в репозитории.
