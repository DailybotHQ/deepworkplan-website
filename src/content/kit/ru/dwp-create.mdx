# dwp-create

Создание нового Deep Work Plan из высокоуровневой цели.

<CmdCreate lang="ru" class="not-prose my-8" />

## Что он делает

`dwp-create` берёт высокоуровневую цель и превращает её в структурированный план. Он анализирует цель, при необходимости задаёт уточняющие вопросы, раскладывает работу на последовательные задачи и пишет файлы плана.

## Использование

```
/dwp-create <goal>
/dwp-create trust lite <goal>
/dwp-create <goal> full trust
```

## Режимы

`dwp-create` по умолчанию работает в **управляемом** режиме: он собирает контекст, выполняет анализ и сразу материализует Lite-план — компактное, уже исполняемое предложение, а не черновик на выброс — **показывает его вам и спрашивает, оставить ли его как Lite, повысить до Full-плана с файлами задач, отредактировать или остановиться** — так что вы всегда читаете реальный план перед принятием решения. Это рекомендуемый режим по умолчанию, особенно в первые несколько раз.

Добавьте **`trust`** (или `auto`) последним словом, чтобы пропустить эту проверку — агент сразу переходит к заранее одобренному, готовому к запуску плану (Lite или Full, выбранному по тем же признакам):

```
/dwp-create <goal> trust
```

Режим trust — это сокращение для опытных пользователей, когда вы доверяете процессу; управляемый режим по умолчанию оставляет человека в цикле.

## Поведение
1. Проанализировать цель и контекст репозитория.
2. Задать уточняющие вопросы, если есть неоднозначность.
3. Материализовать план прямо в `.dwp/plans/PLAN_<id>_<slug>/` — по умолчанию Lite-план, либо Full для более крупной работы (в управляемом режиме проверить его и выбрать: оставить как Lite, повысить до Full, отредактировать или остановиться).
4. Разложить на последовательные задачи и написать README, файлы задач и PROGRESS.
4. `ledger.py materialize` -> `contract.json` (v7).
5. Завершить Final Review (проверка безопасности, валидация финального состояния, сверка решений по skills).

Пакет 7.x по умолчанию создает планы v7. Существующие планы сохраняют записанное поколение; для миграции требуется явный запрос. Новые планы получают монотонно возрастающие числовые ID длиной не менее трёх цифр (например, `PLAN_001_add_payment_webhooks/`). Замороженные схемы v5 считают числовой ID одним словом, поэтому slug v5 содержит 2–4 слова, а slug v7 — 2–4. `ledger.py materialize` -> `contract.json` (v7).
5. Существующие папки без номера `PLAN_<slug>/` остаются доступными для чтения и никогда не переименовываются. Если есть нумерованные планы, `latest` указывает на план с наибольшим числовым ID.
