# Аддон Agentkit

У каждого терминального агента для программирования свои флаги для продолжения сессии, свой способ держать второй аккаунт отдельно, свой headless-режим и свой переключатель для пропуска запросов разрешений. **[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** накладывает на них всех одну командную поверхность: `ak <kind> [@profile]`.

Этот аддон интегрирует kit в **DWP v7** (пакет `v7.5.0`) как **headless**-транспорт делегирования. Он опционален: без него каждая задача выполняется в текущей сессии, как и раньше. Сам kit — продукт под лицензией MIT, который работает без Deep Work Plan.

## Что даёт kit

- **Одна грамматика для любого CLI.** `ak claude`, `ak codex`, `ak cursor`, `ak opencode`, `ak pi`, `ak cline` и `ak grok`, а также варианты провайдеров (GLM, Azure, xAI), с одинаковыми флагами сессии: `-c` продолжает, `-r <id>` возобновляет.
- **Профили.** `ak claude @work` запускает второй аккаунт в собственном домашнем каталоге, отдельно от первого.
- **Headless-запуски.** `ak run <kind> -- "<prompt>"` выполняет один промпт неинтерактивно и возвращает документированный код выхода, при желании в виде одного JSON-объекта.
- **Doctor.** `ak doctor --json` сообщает, какие CLI установлены, профили и имена заданных ключей — никогда их значения.
- **Проверенная установка.** `ak install <cli>` устанавливает недостающий CLI из официального канала его поставщика в закреплённой версии, сверяя её с закреплённым sha256 или с integrity из реестра npm.
- **Привычные имена.** Два пресета псевдонимов, выключенные, пока вы их не включите: `classic` (`claudex`, `codexx`, `cursorx`, `opencodex`, `pix`, `clinex`, `grokx`) и `providers` (`claude-glm`, `codex-azure`, `codex-xai`, `pi-glm`, …), каждый из которых — это `ak <kind>`.

## Квоты, профили и настройка

`ak usage` показывает квоту и расход по каждой учётной записи, которую видит kit, — по строке на учётную запись и профиль: в реальном времени для подписок Claude Code (окна 5 часов, неделя и по модели), входов Codex через ChatGPT и ключей тарифа Z.AI для программирования; Cursor, Grok, xAI и Azure OpenAI показывают `n/d` с причиной. Команда только читает: она никогда не обновляет вход, никогда не выводит токен и никогда ничего не записывает в профиль. `--json` отдаёт тот же список инструментам. Эндпоинты расхода — внутренние и неофициальные API поставщиков.

```bash
ak usage              # квота каждой учётной записи и профиля
ak claude @2          # вторая учётная запись Claude в собственном home
ak profiles ls        # профили на этой машине
ak setup verify       # упорядоченные проверки, каждая с командой исправления
```

Профили разделяют учётные записи: `@default` (или `@1`) — собственный home CLI, а `@2`, `@work` или `@client-x` — отдельные входы, которые работают параллельно. `ak setup probe | verify | docker` — помощник только для чтения, которым управляет skill `agentkit-setup`: он осматривает машину, проверяет установку и формирует закреплённый по тегу и проверенный рецепт контейнера.

## Установка

```bash
git clone --branch v0.4.0 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

Требования: `bash` на macOS или Linux и `python3` 3.9 или новее; больше ничего. Windows использует `install.ps1`. Закрепите `v0.4.0`: `v0.2.0` и `v0.2.1` не поддерживаются. Проверьте релиз по его ресурсу `SHA256SUMS`.

| Элемент | Значение |
|---|---|
| Продукт | `DailybotHQ/coding-agents-kit`, тег `v0.4.0`, интерфейс 1 |
| Ключ реестра | `agentkit` в `.dwp/config.json` |
| Транспорт | headless: один `ak run` на делегата в отдельном git worktree |
| Предоставляет | `subagents`, `cancel_children`, `model_routing` |
| Требует | разрешения `agent_delegation` в контракте плана |

## Автономия по умолчанию с отказом, который всегда побеждает

Начиная с `v0.2.0`, `ak <kind>` запускает каждого агента в **автономии**: он добавляет собственный флаг автономии CLI, который хранится только в `providers.toml` kit. Автономия предназначена для одноразовых или изолированных сред, например контейнера для разработки.

**Отказ всегда побеждает**: `--ask` для одной команды или `AGENTKIT_PERMISSIONS=ask` в окружении или в env-файле kit подавляет флаг, даже если та же команда указывает `--auto`. Сессия с отказом передаёт отказ агентам, которых она запускает. На хосте установите отказ.

Аддон не прописывает никакого флага автономии и никогда не передаёт `--auto`. Он передаёт `--ask`, когда план фиксирует отказ. План, который предоставляет `agent_delegation` на хосте, принимает автономных делегатов, ограниченных собственным worktree, а worktree не является песочницей.

## Что он добавляет в план

В плане v7, контракт которого предоставляет `agent_delegation`, `execute` может передать задачу `parallel_safe` другому CLI: он создаёт отдельный git worktree, запускает там `ak run` с тайм-аутом и собирает результат в `analysis_results/delegations/` плана. Результат является доказательством `asserted`, пока собственный gate runner плана его не зафиксирует. Отмена делегата останавливает всё его дерево процессов.

## Agentkit или Herdr

| Ситуация | Использовать |
|---|---|
| Ограниченная задача `parallel_safe` с объявленным результатом | Agentkit (headless) |
| Задача требует взаимодействия, выполняется долго или находится на другой машине | [Herdr](/kit/herdr) (peer-агент в панели) |

Они сочетаются: herdr-peers может запустить peer-агента в панели с окружением, которое выводит `ak env <kind> @profile`.

## Примечания

Опционален и никогда не обязателен. Значения API-ключей никогда не выводятся, не логируются и не записываются в файл конфигурации; документированное исключение — Cline, который получает свой ключ в командной строке. Извлечение результатов для OpenCode, Pi, Cline и Grok построено по документации поставщиков и ещё не проверялось на реальных аккаунтах; нераспознанный вывод возвращается как сырой текст.
