# Аддон Agentkit

У каждого терминального агента для программирования свои флаги для продолжения сессии, свой способ держать второй аккаунт отдельно, свой headless-режим и свой переключатель для пропуска запросов разрешений. **[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** накладывает на них всех одну командную поверхность: `ak <kind> [@profile]`.

Этот аддон интегрирует kit в **DWP v7** (`v7.0.0`) как **headless**-транспорт делегирования. Он опционален: без него каждая задача выполняется в текущей сессии, как и раньше. Сам kit — продукт под лицензией MIT, который работает без Deep Work Plan.

## Что даёт kit

- **Одна грамматика для любого CLI.** `ak claude`, `ak codex`, `ak cursor`, `ak opencode`, `ak pi`, `ak cline` и `ak grok`, а также варианты провайдеров (GLM, Azure, xAI), с одинаковыми флагами сессии: `-c` продолжает, `-r <id>` возобновляет.
- **Профили.** `ak claude @work` запускает второй аккаунт в собственном домашнем каталоге, отдельно от первого.
- **Headless-запуски.** `ak run <kind> -- "<prompt>"` выполняет один промпт неинтерактивно и возвращает документированный код выхода, при желании в виде одного JSON-объекта.
- **Doctor.** `ak doctor --json` сообщает, какие CLI установлены, профили и имена заданных ключей — никогда их значения.
- **Установка.** `ak install <cli>` устанавливает недостающий CLI из официального канала его поставщика.

## Установка

```bash
git clone --branch v0.1.1 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

Требования: `bash` на macOS или Linux и `python3` 3.9 или новее; больше ничего. Windows использует `install.ps1`. Закрепите `v0.1.1`: он заменяет `v0.1.0` и содержит исправление безопасности.

| Элемент | Значение |
|---|---|
| Продукт | `DailybotHQ/coding-agents-kit`, тег `v0.1.1`, интерфейс 1 |
| Ключ реестра | `agentkit` в `.dwp/config.json` |
| Транспорт | headless: один `ak run` на делегата в отдельном git worktree |
| Предоставляет | `subagents`, `cancel_children`, `model_routing` |
| Требует | разрешения `agent_delegation` в контракте плана |

## Разрешения передаются как есть

`ak <kind>` **не** добавляет никакого флага обхода разрешений. Автономия — явный opt-in: `--auto` для одной команды или `AGENTKIT_PERMISSIONS=auto` в окружении добавляет собственный флаг автономии CLI для этого запуска. Пресет псевдонимов `classic`, воссоздающий сокращения вроде `claudex`, поставляется выключенным.

Аддон никогда не добавляет флаг автономии сам. План использует `--auto` только по явному, зафиксированному opt-in разработчика и только внутри изолированного worktree или контейнера.

## Что он добавляет в план

В плане v7, контракт которого предоставляет `agent_delegation`, `execute` может передать задачу `parallel_safe` другому CLI: он создаёт отдельный git worktree, запускает там `ak run` с тайм-аутом и собирает результат в `analysis_results/delegations/` плана. Результат является доказательством `asserted`, пока собственный gate runner плана его не зафиксирует. Отмена делегата останавливает всё его дерево процессов.

## Agentkit или Herdr

| Ситуация | Использовать |
|---|---|
| Ограниченная задача `parallel_safe` с объявленным результатом | Agentkit (headless) |
| Задача требует взаимодействия, выполняется долго или находится на другой машине | [Herdr](/kit/herdr) (peer-агент в панели) |

Они сочетаются: herdr-peers может запустить peer-агента в панели с окружением, которое выводит `ak env <kind> @profile`.

## Примечания

Опционален и никогда не обязателен. Значения API-ключей никогда не выводятся, не логируются и не записываются в файл конфигурации; документированное исключение — Cline, который получает свой ключ в командной строке. Извлечение результатов для OpenCode, Pi, Cline и Grok построено по документации поставщиков и ещё не проверялось на реальных аккаунтах; нераспознанный вывод возвращается как сырой текст.
