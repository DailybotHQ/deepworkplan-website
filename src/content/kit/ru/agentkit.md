# Аддон Agentkit

У каждого терминального агента для программирования свои флаги для продолжения сессии, свой способ держать второй аккаунт отдельно, свой headless-режим и свой переключатель для пропуска запросов разрешений. **[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** накладывает на них всех одну командную поверхность: `ak <kind> [@profile]`.

Этот аддон интегрирует kit в **DWP v7** (пакет `v7.6.3`) как **headless**-транспорт делегирования. Он опционален: без него каждая задача выполняется в текущей сессии, как и раньше. Сам kit — продукт под лицензией MIT, который работает без Deep Work Plan.

## Что даёт kit

- **Одна грамматика для любого CLI.** `ak claude`, `ak codex`, `ak cursor`, `ak opencode`, `ak pi`, `ak cline` и `ak grok`, а также варианты провайдеров (GLM, Azure, xAI), с одинаковыми флагами сессии: `-c` продолжает, `-r <id>` возобновляет.
- **Профили.** `ak claude @work` запускает второй аккаунт в собственном домашнем каталоге, отдельно от первого.
- **Headless-запуски.** `ak run <kind> -- "<prompt>"` выполняет один промпт неинтерактивно и возвращает документированный код выхода, при желании в виде одного JSON-объекта.
- **Doctor.** `ak doctor --json` сообщает, какие CLI установлены, профили и имена заданных ключей — никогда их значения.
- **Проверенная установка.** `ak install <cli>` устанавливает недостающий CLI из официального канала его поставщика в закреплённой версии, сверяя её с закреплённым sha256 или с integrity из реестра npm.
- **Привычные имена.** Два пресета псевдонимов, выключенные, пока вы их не включите: `classic` (`claudex`, `codexx`, `cursorx`, `opencodex`, `pix`, `clinex`, `grokx`) и `providers` (`claude-glm`, `codex-azure`, `codex-xai`, `pi-glm`, …), каждый из которых — это `ak <kind>`.

## Учётные записи, квоты и выбор учётной записи

Kit считает каждый ваш вход или ключ **учётной записью**: один CLI × один профиль. `@default` (или `@1`) — собственный home CLI; `@2`, `@work` или `@client-x` — отдельные входы, каждый в своём каталоге внутри корня профилей, которые работают параллельно. `ak profiles` показывает их с состоянием входа и именами их ключей; `ak profiles --json` отдаёт тот же список инструментам (схема `profiles-v1`). Начиная с `v0.5.1`, команда сообщает, где на самом деле находится токен Claude Code — `file`, `keychain` (macOS), `none` или `unknown`, — проверяя только его наличие и никогда не читая секрет, а также распознаёт вход Cursor в Linux — в контейнере или на хосте с Linux. Начиная с `v0.5.2`, `AGENTKIT_DEFAULT_PROFILE_<CLI>` задаёт учётную запись, которую использует простой `ak <cli>` (позиционный `@profile` по-прежнему имеет приоритет), — так dev-контейнер выбирает общую с хостом учётную запись. Начиная с `v0.5.3`, `ak codex` добавляет `--no-daemon`, когда home Codex, общий с другой машиной, фиксирует фоновый демон, которого нет на этой машине.

`ak usage` показывает квоту и расход по каждой учётной записи, которую видит kit, — по строке на учётную запись и профиль: в реальном времени для подписок Claude Code (окна 5 часов, неделя и по модели), входов Codex через ChatGPT и ключей тарифа Z.AI для программирования; Cursor, Grok, xAI и Azure OpenAI показывают `n/d` с причиной. Команда только читает: она никогда не обновляет вход, никогда не выводит токен и никогда ничего не записывает в профиль. `--json` отдаёт тот же список инструментам (схема `usage-v1`). Эндпоинты расхода — внутренние и неофициальные API поставщиков.

`ak pick <kind>` читает те же строки и называет учётную запись с наибольшим запасом. `--count N` возвращает до N учётных записей, начиная с лучшей; `--exclude @<profile>` исключает занятую; `--model` учитывает недельное окно одной модели; `--need 5h:40` отказывается выбирать без такого запаса. `--json` отдаёт схему `pick-v1`.

```bash
ak usage                   # квота каждой учётной записи и профиля
ak pick claude --count 3   # три учётные записи Claude с наибольшим запасом
ak claude @work --trust-cwd  # вторая учётная запись, папка заранее доверена
ak profiles --json         # profiles-v1, для инструментов
ak setup verify            # упорядоченные проверки, каждая с командой исправления
```

`--trust-cwd` (или `AGENTKIT_TRUST_CWD=1`) заранее делает доверенной папку, в которой стартует агент, поэтому Claude Code и Codex открываются без экрана доверия к папке. `ak setup probe | verify | docker` — помощник только для чтения, которым управляет skill `agentkit-setup`: он осматривает машину, проверяет установку и формирует закреплённый по тегу и проверенный рецепт контейнера.

## Несколько агентов, несколько учётных записей

Skill `agentkit-orchestrate` (`ak --skill orchestrate`) учит агента распределять работу между несколькими агентами, учётными записями и поставщиками: один `ak usage` перед пакетом, `ak pick --count N` для выбора учётных записей, один делегат на учётную запись, собственный gate репозитория для каждого результата и переключение на следующую учётную запись, когда одна упирается в лимит. Kit наблюдает, вычисляет и запускает; он никогда не планирует. Решает ведущий агент — вы или агент, которого вы попросили, — используя только ваши собственные учётные записи и в рамках условий каждого поставщика.

Для долгих интерактивных линий каждая линия работает в панели [Herdr](/kit/herdr) на собственной учётной записи. Глава методологии [Запуск множества агентов](/methodology/06-orchestration) описывает всю модель: ведущий агент и его линии, учётные записи, выбранные по запасу, координация через herdr-peers, а также одна ветка и один релиз на репозиторий.

## Установка

```bash
git clone --branch v0.5.3 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

Требования: `bash` на macOS или Linux и `python3` 3.9 или новее; больше ничего. Windows использует `install.ps1`. Закрепите `v0.5.3`: `v0.2.0` и `v0.2.1` не поддерживаются. Проверьте релиз по его ресурсу `SHA256SUMS`.

| Элемент | Значение |
|---|---|
| Продукт | `DailybotHQ/coding-agents-kit`, тег `v0.5.3`, интерфейс 1 |
| Ключ реестра | `agentkit` в `.dwp/config.json` |
| Транспорт | headless: один `ak run` на делегата в отдельном git worktree |
| Предоставляет | `subagents`, `cancel_children`, `model_routing` |
| Требует | разрешения `agent_delegation` в контракте плана |

## Автономия по умолчанию с отказом, который всегда побеждает

Начиная с `v0.2.0`, `ak <kind>` запускает каждого агента в **автономии**: он добавляет собственный флаг автономии CLI, который хранится только в `providers.toml` kit. Автономия предназначена для одноразовых или изолированных сред, например контейнера для разработки.

**Отказ всегда побеждает**: `--ask` для одной команды или `AGENTKIT_PERMISSIONS=ask` в окружении или в env-файле kit подавляет флаг, даже если та же команда указывает `--auto`. Сессия с отказом передаёт отказ агентам, которых она запускает. На хосте установите отказ.

Аддон не прописывает никакого флага автономии и никогда не передаёт `--auto`. Он передаёт `--ask`, когда план фиксирует отказ. План, который предоставляет `agent_delegation` на хосте, принимает автономных делегатов, ограниченных собственным worktree, а worktree не является песочницей.

## Что он добавляет в план

В плане v7, контракт которого предоставляет `agent_delegation`, `execute` может передать задачу `parallel_safe` другому CLI: он создаёт отдельный git worktree, запускает там `ak run` с тайм-аутом и собирает результат в `analysis_results/delegations/` плана. Результат является доказательством `asserted`, пока собственный gate runner плана его не зафиксирует. Отмена делегата останавливает всё его дерево процессов.

## Agentkit или Herdr

| Ситуация | Использовать |
|---|---|
| Ограниченная задача `parallel_safe` с объявленным результатом | Agentkit (headless) |
| Задача требует взаимодействия, выполняется долго или находится на другой машине | [Herdr](/kit/herdr) (peer-агент в панели) |

Они сочетаются: herdr-peers может запустить peer-агента в панели с окружением, которое выводит `ak env <kind> @profile`. Для множества линий одновременно см. [Запуск множества агентов](/methodology/06-orchestration).

## Примечания

Опционален и никогда не обязателен. Значения API-ключей никогда не выводятся, не логируются и не записываются в файл конфигурации; документированное исключение — Cline, который получает свой ключ в командной строке. Извлечение результатов для OpenCode, Pi, Cline и Grok построено по документации поставщиков и ещё не проверялось на реальных аккаунтах; нераспознанный вывод возвращается как сырой текст.
