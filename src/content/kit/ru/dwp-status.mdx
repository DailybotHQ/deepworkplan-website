# dwp-status

Отчёт о статусе Deep Work Plan без выполнения.

<CmdStatus lang="ru" class="not-prose my-8" />

## Что он делает

`dwp-status` по контракту работает строго только на чтение. Он сводит прогресс, активные блокировки, контрольные точки и ресурсные конверты, не изменяя ни одного файла.

## Использование

```
/dwp-status                      # list and summarize all plans
/dwp-status [plan]               # report details for a specific plan
```

## Поведение

1. **Четыре измерения жизненного цикла:** сообщает формат (`lite` или `full`), статус материализации (`materializing`, `ready` или `promoting`), одобрение проверки (`pending`, `approved` или `pre_approved`) и ход выполнения (`pending`, `in_progress`, `blocked` или `completed`).
2. **Обзор всего репозитория:** при вызове без аргументов перечисляет все планы в `.dwp/plans/` с процентами завершения, локаторами активных задач и сводками блокировок.
3. **Ресурсный конверт:** показывает израсходованные значения относительно потолков по отслеживаемым измерениям (`wall_clock`, повторы, диспетчеризации, расходы, токены) и указывает, применяются ли лимиты принудительно или носят рекомендательный характер.
4. **Диагностика блокировок:** выводит сведения об активных блокировках из `state.json.blocked`, классифицированные по стандартной таксономии эскалации (классы C1–C7).
5. **Наблюдение за делегированием:** сводит открытые и завершённые делегирования субагентам и записанные обмены с пирами.

## Псевдонимы

- `dwp:status`
