# dwp-refine

Refina un Deep Work Plan existente de manera segura.

## Qué hace

`dwp-refine` modifica un plan existente de forma segura. Puede añadir, eliminar o reordenar tareas preservando estrictamente la evidencia completada, prohibiendo el debilitamiento no confirmado de criterios y registrando revisiones atómicas de contratos.

## Uso

```
/dwp-refine [plan]
/dwp-refine promote [plan]
```

## Comportamiento

1. **Lectura del plan:** lee el plan de destino e inspecciona el historial existente del contrato y del diario.
2. **Enmiendas de contrato:** en planes v7, las modificaciones del contrato se realizan mediante `ledger.py amend`. La revisión se conserva en `contracts/`, se añade un evento `amendment` a `journal.ndjson` y se registra una aprobación nueva.
3. **Conjunto cerrado de adaptaciones:** las adaptaciones del plan a mitad de ejecución se restringen a cinco operaciones autorizadas: `split`, `reorder`, `insert`, `change_strategy` y `retry`. Las propuestas que amplíen alcance, permisos o presupuesto se rechazan.
4. **Preservar evidencia:** la evidencia de las tareas completadas nunca se modifica ni invalida. El debilitamiento no confirmado de criterios está estrictamente prohibido.
5. **Promoción de Lite a Full:** `/dwp-refine promote {plan}` expande los registros de tareas en línea del README en archivos de tareas numerados independientes sin alterar los identificadores de tarea ni invalidar la evidencia existente.

## Migración explícita

Los planes existentes conservan su generación registrada cuando se actualiza el paquete de habilidades. La migración nunca es automática. Un plan v5 pasa a v6 solo mediante una migración explícita y previsualizada (`shared/migrate_v6.py`). Un plan v6 conserva su generación y se ejecuta sin cambios; los planes nuevos utilizan la generación v7 actual, y un plan existente nunca se migra implícitamente.
