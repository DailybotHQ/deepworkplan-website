# dwp-status

报告 Deep Work Plan 的状态而不执行。

<CmdStatus lang="zh" class="not-prose my-8" />

## 它做了什么

`dwp-status` 按契约严格只读。它汇总进度、当前阻塞项、检查点与资源包络，不对任何文件做改动。

## 用法

```
/dwp-status                      # list and summarize all plans
/dwp-status [plan]               # report details for a specific plan
```

## 行为

1. **四个生命周期维度：** 报告格式（`lite` 或 `full`）、物化状态（`materializing`、`ready` 或 `promoting`）、审阅批准（`pending`、`approved` 或 `pre_approved`）以及执行进度（`pending`、`in_progress`、`blocked` 或 `completed`）。
2. **仓库级概览：** 不带参数调用时，列出 `.dwp/plans/` 下的所有计划，并附完成百分比、当前任务定位与阻塞摘要。
3. **资源包络：** 展示各跟踪维度（`wall_clock`、重试、派发、花费、token）的已用量与上限，并指明这些上限是在强制执行还是仅作参考。
4. **阻塞诊断：** 呈现 `state.json.blocked` 中的当前阻塞详情，按标准升级分类（类别 C1–C7）归类。
5. **委派观察：** 汇总进行中与已完成的子代理委派，以及已记录的同伴交流。

## 别名

- `dwp:status`
