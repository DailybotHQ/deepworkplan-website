# dwp-create

从一个高层目标创建一份新的 Deep Work Plan。

<CmdCreate lang="zh" class="not-prose my-8" />

## 它做了什么

`dwp-create` 接收一个高层目标，并把它转化为一份结构化、可执行的 Deep Work Plan。它会分析需求，在含糊时提出澄清性的问题，并直接在 `.dwp/plans/PLAN_<id>_<slug>/` 下物化出 Lite 或 Full 计划。

## 用法

```
/dwp-create <goal>
/dwp-create trust lite <goal>
/dwp-create <goal> full trust
```

## 模式与边界选项

边界选项用于配置审阅行为与计划格式。它们可以作为词元出现在命令的开头或末尾，顺序不限：

- **审阅模式：**
  - **引导（默认）：** 物化出一份可执行的 Lite 计划提案，展示观察到的信号与格式依据，并询问是保留为 Lite、晋升为 Full、编辑，还是停止。
  - **Trust（`trust` 或 `auto`）：** 跳过审阅，直接进入一份预先批准、可直接运行的计划。
- **格式偏好：**
  - **`lite`：** 表示偏好紧凑的单文件计划，即 `README.md` 中带锚点的任务记录（`#task-N`）。
  - **`full`：** 表示偏好拆分后的编号任务文件（`N.task_<slug>.md`）。
  - 同时指定 `lite` 与 `full` 属于显式冲突。
- **终止符：** `--` 终止选项解析；`--` 之后的所有内容都被视为字面的目标上下文。

## 行为

1. **需求分析：** 检查仓库上下文、架构以及文档中记载的测试命令。
2. **澄清：** 当范围或需求含糊时提出澄清性的问题。
3. **单调分配：** 在 POSIX 文件锁（`fcntl`）下借助 `.next-plan-id`，于 `.dwp/plans/` 下分配补零的文件夹名 `PLAN_<id>_<slug>/`。数字 ID 单调递增，永不复用。
4. **契约物化：** 运行 `ledger.py materialize` 写出 `manifest.json`，生成按内容寻址的 `contract.json`（v7 代际，带 `parallel_safe` 任务标记），并记录初始的 `approval` 事件。
5. **Final Review：** 计划以一项必需的五部分 Final Review 任务作结（含必需本地审查的安全审查、最终状态验证、技能核对、文档核对、完成）。

- `dwp:create`
