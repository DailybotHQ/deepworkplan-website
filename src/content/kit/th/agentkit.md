# แอดออน Agentkit

coding agent บนเทอร์มินัลแต่ละตัวมีแฟล็กของตัวเองสำหรับทำเซสชันต่อ มีวิธีของตัวเองในการแยกบัญชีที่สองออกจากกัน มีโหมด headless ของตัวเอง และมีสวิตช์ของตัวเองสำหรับข้ามการถามสิทธิ์ **[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** ครอบทั้งหมดนั้นด้วยชุดคำสั่งเดียว: `ak <kind> [@profile]`

แอดออนนี้ผสานชุดเครื่องมือดังกล่าวเข้ากับ **DWP v7** (แพ็ก `v7.1.0`) ในฐานะช่องทางการมอบหมายงานแบบ **headless** แอดออนนี้เป็นแบบเลือกใช้ หากไม่มีมัน ทุกงานจะรันในเซสชันปัจจุบันเหมือนที่เคยเป็นมาทุกประการ ตัวชุดเครื่องมือเองเป็นผลิตภัณฑ์ MIT ที่ทำงานได้แม้ไม่มี Deep Work Plan

## สิ่งที่ชุดเครื่องมือมอบให้

- **ไวยากรณ์เดียวสำหรับทุก CLI** `ak claude`, `ak codex`, `ak cursor`, `ak opencode`, `ak pi`, `ak cline` และ `ak grok` รวมถึงรุ่นย่อยตามผู้ให้บริการ (GLM, Azure, xAI) ใช้แฟล็กเซสชันชุดเดียวกัน โดย `-c` คือทำต่อ และ `-r <id>` คือกลับมาทำต่อจากเซสชันที่ระบุ
- **โปรไฟล์** `ak claude @work` รันบัญชีที่สองใน home ของตัวเอง แยกออกจากบัญชีแรก
- **การรันแบบ headless** `ak run <kind> -- "<prompt>"` รัน prompt หนึ่งรายการแบบไม่โต้ตอบ และคืนค่า exit code ที่มีเอกสารกำกับ โดยเลือกให้คืนเป็นออบเจ็กต์ JSON หนึ่งรายการได้
- **ตัววินิจฉัย** `ak doctor --json` รายงานว่าติดตั้ง CLI ใดไว้บ้าง มีโปรไฟล์ใด และชื่อของคีย์ที่ตั้งค่าไว้ โดยไม่รายงานค่าของคีย์เลย
- **การติดตั้งที่ผ่านการตรวจสอบ** `ak install <cli>` ติดตั้ง CLI ที่ขาดอยู่จากช่องทางทางการของผู้ผลิตในเวอร์ชันที่ตรึงไว้ และตรวจสอบกับ sha256 ที่ตรึงไว้หรือข้อมูล integrity ของ npm registry
- **ชื่อที่คุ้นเคย** preset alias สองชุดที่ปิดไว้จนกว่าคุณจะเปิด ได้แก่ `classic` (`claudex`, `codexx`, `cursorx`, `opencodex`, `pix`, `clinex`, `grokx`) และ `providers` (`claude-glm`, `codex-azure`, `codex-xai`, `pi-glm`, …) แต่ละชื่อคือ `ak <kind>` หนึ่งคำสั่ง

## การติดตั้ง

```bash
git clone --branch v0.3.0 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

ข้อกำหนด: `bash` บน macOS หรือ Linux และ `python3` 3.9 ขึ้นไป ไม่ต้องมีอย่างอื่น Windows ใช้ `install.ps1` ให้ตรึงไว้ที่ `v0.3.0` เนื่องจาก `v0.2.0` และ `v0.2.1` ไม่ได้รับการสนับสนุน ตรวจสอบรีลีสด้วย asset `SHA256SUMS` ของรีลีสนั้น

| รายการ | ค่า |
|---|---|
| ผลิตภัณฑ์ | `DailybotHQ/coding-agents-kit` แท็ก `v0.3.0` อินเทอร์เฟซ 1 |
| คีย์ใน registry | `agentkit` ใน `.dwp/config.json` |
| ช่องทางการส่ง | headless: `ak run` หนึ่งครั้งต่อผู้รับมอบหมายหนึ่งราย ใน git worktree เฉพาะ |
| สิ่งที่มอบให้ | `subagents`, `cancel_children`, `model_routing` |
| สิ่งที่ต้องมี | การอนุญาต `agent_delegation` ในสัญญาของแผน |

## ทำงานอัตโนมัติโดยค่าเริ่มต้น โดยการเลือกไม่ใช้มีผลเหนือกว่าเสมอ

ตั้งแต่ `v0.2.0` คำสั่ง `ak <kind>` จะเปิดเอเจนต์ทุกตัวใน**โหมดอัตโนมัติ** โดยเพิ่มแฟล็กอัตโนมัติของ CLI นั้นเอง ซึ่งเก็บไว้เฉพาะใน `providers.toml` ของชุดเครื่องมือ โหมดอัตโนมัติมีไว้สำหรับสภาพแวดล้อมที่ใช้แล้วทิ้งได้หรืออยู่ใน sandbox เช่น dev container

**การเลือกไม่ใช้มีผลเหนือกว่าเสมอ**: การใส่ `--ask` ในคำสั่งหนึ่ง หรือตั้ง `AGENTKIT_PERMISSIONS=ask` ใน environment หรือในไฟล์ env ของชุดเครื่องมือ จะระงับแฟล็กนั้น แม้คำสั่งเดียวกันจะระบุ `--auto` ก็ตาม เซสชันที่เลือกไม่ใช้จะส่งต่อการเลือกไม่ใช้นั้นไปยังเอเจนต์ที่มันเริ่มขึ้น บนโฮสต์ ให้ตั้งค่าการเลือกไม่ใช้ไว้

แอดออนนี้ไม่เขียนแฟล็กอัตโนมัติใด ๆ และไม่ส่ง `--auto` เลย แอดออนจะส่ง `--ask` เมื่อแผนบันทึกการเลือกไม่ใช้ไว้ แผนที่ให้สิทธิ์ `agent_delegation` บนโฮสต์ถือว่ายอมรับผู้รับมอบหมายที่ทำงานอัตโนมัติซึ่งถูกจำกัดอยู่ใน worktree ของตัวเอง และ worktree ไม่ใช่ sandbox

## สิ่งที่เพิ่มให้กับแผน

ในแผน v7 ที่สัญญาให้สิทธิ์ `agent_delegation` คำสั่ง `execute` สามารถส่งงาน `parallel_safe` ให้ CLI อื่นได้ โดยจะสร้าง git worktree เฉพาะ รัน `ak run` ในนั้นพร้อม timeout และรวบรวมผลลัพธ์ไว้ใน `analysis_results/delegations/` ของแผน ผลลัพธ์เป็นหลักฐานแบบ `asserted` จนกว่า gate runner ของแผนเองจะสังเกตเห็นมัน การยกเลิกผู้รับมอบหมายจะหยุดทั้ง process tree ของมัน

## Agentkit หรือ Herdr

| สถานการณ์ | ใช้ |
|---|---|
| งาน `parallel_safe` ที่มีขอบเขตชัดเจนและประกาศผลลัพธ์ไว้ | Agentkit (headless) |
| งานที่ต้องโต้ตอบ รันนาน หรืออยู่บนเครื่องอื่น | [Herdr](/kit/herdr) (peer ใน pane) |

ทั้งสองใช้ร่วมกันได้ herdr-peers สามารถเปิด peer ใน pane ด้วย environment ที่ `ak env <kind> @profile` พิมพ์ออกมา

## หมายเหตุ

เป็นแบบเลือกใช้และไม่บังคับเสมอ ค่าของ API key จะไม่ถูกพิมพ์ ไม่ถูกบันทึกใน log และไม่ถูกเขียนลงไฟล์ config ข้อยกเว้นที่มีเอกสารกำกับคือ Cline ซึ่งรับคีย์ผ่าน command line การดึงผลลัพธ์สำหรับ OpenCode, Pi, Cline และ Grok สร้างขึ้นจากเอกสารของผู้ผลิต และยังไม่ได้ทดสอบกับบัญชีจริง ผลลัพธ์ที่ไม่รู้จักจะถอยกลับไปใช้ข้อความดิบ
