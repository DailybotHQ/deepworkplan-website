# แอดออน Agentkit

coding agent บนเทอร์มินัลแต่ละตัวมีแฟล็กของตัวเองสำหรับทำเซสชันต่อ มีวิธีของตัวเองในการแยกบัญชีที่สองออกจากกัน มีโหมด headless ของตัวเอง และมีสวิตช์ของตัวเองสำหรับข้ามการถามสิทธิ์ **[coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit)** ครอบทั้งหมดนั้นด้วยชุดคำสั่งเดียว: `ak <kind> [@profile]`

แอดออนนี้ผสานชุดเครื่องมือดังกล่าวเข้ากับ **DWP v7** (แพ็ก `v7.8.1`) ในฐานะช่องทางการมอบหมายงานแบบ **headless** แอดออนนี้เป็นแบบเลือกใช้ หากไม่มีมัน ทุกงานจะรันในเซสชันปัจจุบันเหมือนที่เคยเป็นมาทุกประการ ตัวชุดเครื่องมือเองเป็นผลิตภัณฑ์ MIT ที่ทำงานได้แม้ไม่มี Deep Work Plan

## สิ่งที่ชุดเครื่องมือมอบให้

- **ไวยากรณ์เดียวสำหรับทุก CLI** `ak claude`, `ak codex`, `ak cursor`, `ak opencode`, `ak pi`, `ak cline`, `ak grok` และ `ak antigravity` รวมถึงเส้นทางผู้ให้บริการ (Z.AI GLM, Azure OpenAI, xAI และ Gemini API) ใช้แฟล็กเซสชันชุดเดียวกัน โดย `-c` คือทำต่อ และ `-r <id>` คือกลับมาทำต่อจากเซสชันที่ระบุ
- **โปรไฟล์** `ak claude @work` รันบัญชีที่สองใน home ของตัวเอง แยกออกจากบัญชีแรก
- **การรันแบบ headless** `ak run <kind> -- "<prompt>"` รัน prompt หนึ่งรายการแบบไม่โต้ตอบ และคืนค่า exit code ที่มีเอกสารกำกับ โดยเลือกให้คืนเป็นออบเจ็กต์ JSON หนึ่งรายการได้
- **ตัววินิจฉัย** `ak doctor --json` รายงานว่าติดตั้ง CLI ใดไว้บ้าง มีโปรไฟล์ใด และชื่อของคีย์ที่ตั้งค่าไว้ โดยไม่รายงานค่าของคีย์เลย
- **การติดตั้งที่ผ่านการตรวจสอบ** `ak install <cli>` ติดตั้ง CLI ที่ขาดอยู่จากช่องทางทางการของผู้ผลิตในเวอร์ชันที่ตรึงไว้ และตรวจสอบกับ sha256 ที่ตรึงไว้หรือข้อมูล integrity ของ npm registry
- **ชื่อที่คุ้นเคย** preset alias สองชุดที่ปิดไว้จนกว่าคุณจะเปิด ได้แก่ `classic` (`claudex`, `codexx`, `cursorx`, `opencodex`, `pix`, `clinex`, `grokx`) และ `providers` (`claude-glm`, `codex-azure`, `codex-xai`, `pi-glm`, …) แต่ละชื่อคือ `ak <kind>` หนึ่งคำสั่ง

## บัญชี โควตา และการเลือกบัญชี

ชุดเครื่องมือถือว่าทุกการล็อกอินหรือคีย์ที่คุณมีคือ **บัญชี** หนึ่งบัญชี: CLI หนึ่งตัว × โปรไฟล์หนึ่งโปรไฟล์ `@default` (หรือ `@1`) คือ home ของ CLI เอง ส่วน `@2`, `@work` หรือ `@client-x` คือการล็อกอินแยกกัน แต่ละอันอยู่ในไดเรกทอรีของตัวเองใต้รากของโปรไฟล์ และทำงานคู่กันได้ `ak profiles` แสดงรายการเหล่านี้พร้อมสถานะการล็อกอินและชื่อของคีย์ `ak profiles --json` ส่งรายการเดียวกันให้เครื่องมืออื่น (schema `profiles-v1`) ตั้งแต่ `v0.5.1` คำสั่งนี้รายงานว่าโทเค็นของ Claude Code อยู่ที่ใดจริง ๆ ได้แก่ `file`, `keychain` (macOS), `none` หรือ `unknown` โดยตรวจเพียงว่ามีอยู่หรือไม่ ไม่อ่านความลับเลย และยังรู้จักการล็อกอิน Cursor บน Linux ไม่ว่าจะอยู่ในคอนเทนเนอร์หรือบนโฮสต์ Linux ตั้งแต่ `v0.5.2` ตัวแปร `AGENTKIT_DEFAULT_PROFILE_<CLI>` จะระบุบัญชีที่คำสั่ง `ak <cli>` แบบไม่ระบุโปรไฟล์ใช้ (`@profile` ที่ระบุตามตำแหน่งยังคงมีลำดับความสำคัญเหนือกว่า) ซึ่งเป็นวิธีที่ dev container ใช้เลือกบัญชีโฮสต์ที่ตนแชร์ ตั้งแต่ `v0.5.3` คำสั่ง `ak codex` จะเพิ่ม `--no-daemon` เมื่อ home ของ Codex ที่แชร์กับเครื่องอื่นบันทึก daemon เบื้องหลังที่ไม่ได้อยู่บนเครื่องนี้

`ak usage` (หรือ `ak status`) แสดงทุกบัญชีของทุก CLI ที่ชุดเครื่องมือรู้จัก หนึ่งแถวต่อบัญชีและโปรไฟล์ ภายใต้ CLI ของบัญชีนั้น โดยแสดงโควตาแบบสดสำหรับการสมัครใช้งาน Claude Code (กรอบเวลา 5 ชั่วโมง รายสัปดาห์ และรายโมเดล) การล็อกอิน Codex ผ่าน ChatGPT คีย์แพ็กเกจเขียนโค้ดของ Z.AI และตั้งแต่ `v0.7.0` การล็อกอิน Google ของ Antigravity บน Linux และในคอนเทนเนอร์ (กรอบเวลาห้าชั่วโมงและรายสัปดาห์จากแผง `/usage` ของ agy เอง) บัญชีที่อ่านโควตาไม่ได้ก็ยังมีแถวของตัวเอง โดยแสดง `n/d` พร้อมวิธีที่เชื่อมต่อและเหตุผล ได้แก่ Cursor, Grok, xAI, Azure OpenAI, คีย์ API ของ Gemini หรือการล็อกอิน Antigravity ที่เก็บไว้ใน Keychain ของ macOS หรือแสดง `no login` พร้อมคำสั่งสำหรับล็อกอิน ตารางจึงบอกด้วยว่าบัญชีใดของแต่ละ CLI เชื่อมต่ออยู่ คำสั่งนี้อ่านอย่างเดียว ไม่รีเฟรชการล็อกอิน ไม่พิมพ์โทเคน และไม่เขียนสิ่งใดลงในโปรไฟล์ `--json` ส่งรายการเดียวกันให้เครื่องมืออื่น (schema `usage-v1`) endpoint การใช้งานเป็นของภายในผู้ให้บริการและไม่เป็นทางการ

`ak pick <kind>` อ่านแถวชุดเดียวกันและระบุบัญชีที่มีพื้นที่เหลือมากที่สุด `--count N` คืนบัญชีได้สูงสุด N บัญชี เรียงจากดีที่สุด `--exclude @<profile>` กันบัญชีที่กำลังยุ่งออก `--model` นับกรอบเวลารายสัปดาห์ของโมเดลเดียว `--need 5h:40` ปฏิเสธการเลือกหากพื้นที่เหลือไม่ถึงเท่านั้น `--json` ให้ผลเป็น schema `pick-v1`

```bash
ak usage                   # โควตาของทุกบัญชีและโปรไฟล์
ak pick claude --count 3   # บัญชี Claude สามบัญชีที่เหลือโควตามากที่สุด
ak claude @work --trust-cwd  # บัญชีที่สอง โฟลเดอร์เชื่อถือไว้ล่วงหน้า
ak profiles --json         # profiles-v1 สำหรับเครื่องมือ
ak setup verify            # การตรวจสอบตามลำดับ แต่ละข้อมีคำสั่งแก้ไข
```

`--trust-cwd` (หรือ `AGENTKIT_TRUST_CWD=1`) เชื่อถือโฟลเดอร์ที่เอเจนต์เริ่มทำงานไว้ล่วงหน้า Claude Code และ Codex จึงเปิดขึ้นโดยไม่มีหน้าจอยืนยันความเชื่อถือโฟลเดอร์ `ak setup probe | verify | docker` เป็นตัวช่วยแบบอ่านอย่างเดียวที่ skill `agentkit-setup` ใช้ ตรวจสอบเครื่อง ยืนยันการติดตั้ง และสร้างสูตรคอนเทนเนอร์ที่ตรึงด้วยแท็กและผ่านการตรวจสอบแล้ว

## หลายเอเจนต์ หลายบัญชี

skill `agentkit-orchestrate` (`ak --skill orchestrate`) สอนเอเจนต์ให้กระจายงานไปยังหลายเอเจนต์ หลายบัญชี และหลายผู้ให้บริการ: เรียก `ak usage` หนึ่งครั้งก่อนเริ่ม batch ใช้ `ak pick --count N` เลือกบัญชี มอบหมายงานหนึ่งรายต่อหนึ่งบัญชี รัน gate ของ repository เองกับทุกผลลัพธ์ และสลับไปยังบัญชีถัดไปเมื่อบัญชีหนึ่งชนขีดจำกัด ชุดเครื่องมือทำหน้าที่สังเกต คำนวณ และรัน แต่ไม่เคยจัดตารางงาน lead ซึ่งก็คือคุณ หรือเอเจนต์ที่คุณสั่ง เป็นผู้ตัดสินใจ โดยใช้เฉพาะบัญชีของคุณเองและอยู่ภายในข้อกำหนดของผู้ให้บริการแต่ละราย

สำหรับ lane แบบโต้ตอบที่ใช้เวลานาน แต่ละ lane รันอยู่ใน pane ของ [Herdr](/kit/herdr) บนบัญชีของตัวเอง บทในระเบียบวิธี [การรันเอเจนต์หลายตัว](/methodology/06-orchestration) อธิบายโมเดลทั้งหมด ได้แก่ lead และ lane ของมัน บัญชีที่เลือกตามโควตาที่เหลือ การประสานงานผ่าน herdr-peers และหนึ่ง branch หนึ่งรีลีสต่อ repository ส่วน [ความเป็นอิสระของ swarm](/th/methodology/07-swarm-autonomy) เพิ่มการตรวจความจุ handoff และการสืบทอดตำแหน่ง lead

## ความจุและ lease

ตั้งแต่ `v0.6.0` เอเจนต์สามารถถามได้ว่าบัญชีของตัวเองเหลือพื้นที่เท่าไร ด้วยต้นทุนต่ำ ที่ทุกขอบเขตของงาน — สัญญาณที่ทำให้ swarm ส่งต่องานได้ก่อนที่บัญชีจะหมด ([ความเป็นอิสระของ swarm](/th/methodology/07-swarm-autonomy))

- **`ak capacity --self --json`** (schema `capacity-v1`) ให้ `headroom_pct` ของบัญชีที่กำลังรัน `binding_window` ของมัน `resets_at` และ `verdict` ซึ่งเป็น `ok`, `low` (25 % หรือน้อยกว่า), `critical` (10 % หรือน้อยกว่า หรือถูกจำกัดอัตรา) หรือ `unknown` (ไม่มีแหล่งข้อมูลโควตา: Cursor, Grok หรือ Antigravity บน macOS) คำสั่งนี้ใช้การคำนวณเดียวกับ `ak pick` ทั้งสองจึงไม่เคยขัดกัน และอ่าน cache การใช้งานที่เก็บไว้ 300 วินาที (`--max-age`) การตรวจทุกขอบเขตของงานจึงยังมีต้นทุนต่ำ `--self` ระบุบัญชีที่ `ak` เป็นผู้เปิด นอกการเปิดด้วย `ak` มันจะออกด้วยรหัส 3 และไม่เดาเด็ดขาด `ak usage` ยังคงอ่านแบบสดและรีเฟรช cache
- **เกณฑ์และการซ้อม** `AGENTKIT_CAPACITY_LOW` และ `AGENTKIT_CAPACITY_CRITICAL` (หรือ `--low` และ `--critical`) ใช้เลื่อนเกณฑ์ `AGENTKIT_CAPACITY_CAP=@<profile>=<pct>` ลดค่าที่อ่านได้เท่านั้น — เป็นวิธีที่การซ้อมทำให้บัญชีดูเหมือนเหลือน้อย — และไม่มีทางทำให้บัญชีดูเหลือมากขึ้น
- **`ak lease <kind> @<profile> --owner <addr>`** จองบัญชีไว้ให้ lane หนึ่ง `ak lease release …` ปล่อยบัญชีเมื่อผู้สืบทอดยอมรับ handoff แล้ว และ `ak lease ls` แสดงรายการ lease (schema `leases-v1`) โปรไฟล์ Codex รับ lease ได้เพียงหนึ่งรายการ — ผู้เขียนหนึ่งรายต่อไฟล์ auth หนึ่งไฟล์ — และมีเพียงเจ้าของที่ปล่อย lease ได้ lease มีวันหมดอายุ และเป็นเพียงบันทึกเชิงแนะนำที่มีตัวเลข ชื่อโปรไฟล์ และที่อยู่ pane ไม่เคยเป็นข้อมูลรับรอง
- **`ak pick <kind> --owner <lead>`** นับ lease ที่ใช้งานอยู่ทุกรายการ รวมถึงของเจ้าของเองด้วย โดยจัดอันดับผู้สมัครด้วย `headroom / (1 + leases)` และไม่เสนอบัญชี Codex ที่ถูก lease อยู่เลย แม้แต่ให้ผู้ถือเอง `--reuse @<profile>` ส่งต่อ lease หนึ่งรายการของเจ้าของเอง เช่น ให้ผู้สืบทอดของ lane หากไม่มี `--owner` การจัดอันดับจะไม่เปลี่ยน

```bash
ak capacity --self --json                        # พื้นที่เหลือและผลตัดสินของเอเจนต์นี้เอง
ak lease claude @work --owner local:w2:p1        # จองบัญชีไว้ให้ lane
ak pick codex --owner local:w1:p1 --count 2      # ข้ามบัญชีที่ lease ให้ผู้อื่น
```

งานย้ายไปมาเฉพาะในบรรดาบัญชีที่คุณประกาศไว้สำหรับแผน และอยู่ภายในข้อกำหนดของผู้ให้บริการแต่ละราย ไม่มีเอเจนต์ใดสร้างบัญชี ต่ออายุการล็อกอิน หรือใช้สิทธิ์รีเซ็ตของ Codex แพ็ก Deep Work Plan อ่านผลตัดสินผ่าน helper ของตัวเอง และแปลงเป็นทำต่อ เตรียมตัว หรือส่งต่องาน หากไม่มีชุดเครื่องมือ หรือใช้รุ่นเก่ากว่า ความจุจะถูกรายงานเป็น unknown ไม่เคยเป็น ok

## การติดตั้ง

```bash
git clone --branch v1.0.1 https://github.com/DailybotHQ/coding-agents-kit && ./coding-agents-kit/install.sh
ak doctor
```

ข้อกำหนด: `bash` บน macOS หรือ Linux และ `python3` 3.9 ขึ้นไป ไม่ต้องมีอย่างอื่น Windows ใช้ `install.ps1` ให้ตรึงไว้ที่ `v1.0.1` เนื่องจาก `v0.2.0` และ `v0.2.1` ไม่ได้รับการสนับสนุน ตรวจสอบรีลีสด้วย asset `SHA256SUMS` ของรีลีสนั้น

| รายการ | ค่า |
|---|---|
| ผลิตภัณฑ์ | `DailybotHQ/coding-agents-kit` แท็ก `v1.0.1` อินเทอร์เฟซ 1 |
| คีย์ใน registry | `agentkit` ใน `.dwp/config.json` |
| ช่องทางการส่ง | headless: `ak run` หนึ่งครั้งต่อผู้รับมอบหมายหนึ่งราย ใน git worktree เฉพาะ |
| สิ่งที่มอบให้ | `subagents`, `cancel_children`, `model_routing` |
| สิ่งที่ต้องมี | การอนุญาต `agent_delegation` ในสัญญาของแผน |

**เสถียรตั้งแต่ `v1.0.0`** อินเทอร์เฟซสาธารณะของชุดเครื่องมือเป็นไปตาม semantic versioning และจะเปลี่ยนแบบไม่เข้ากันกับของเดิมเฉพาะในเวอร์ชันหลักใหม่เท่านั้น ได้แก่ ชุดคำสั่ง (`ak <kind> [@profile]` สำหรับทุก kind ใน `providers.toml` และทุกคำสั่งย่อยพร้อมแฟล็กที่มีเอกสารกำกับ) ท่าทีด้านสิทธิ์ อินเทอร์เฟซ 1 (`ak doctor --json`, `ak env`, ไวยากรณ์และ envelope ของ `ak run`) สคีมา JSON (`doctor-v1`, `usage-v1`, `pick-v1`, `capacity-v1`, `leases-v1`, `profiles-v1`, `setup-probe-v1` และ `setup-verify-v1`) และโครงสร้างการติดตั้งกับชื่อตัวแปรในไฟล์ env `v1.0.0` ไม่เปลี่ยนคำสั่ง แฟล็ก คีย์ หรือสคีมาใดจาก `v0.7.1`

## ทำงานอัตโนมัติโดยค่าเริ่มต้น โดยการเลือกไม่ใช้มีผลเหนือกว่าเสมอ

ตั้งแต่ `v0.2.0` คำสั่ง `ak <kind>` จะเปิดเอเจนต์ทุกตัวใน**โหมดอัตโนมัติ** โดยเพิ่มแฟล็กอัตโนมัติของ CLI นั้นเอง ซึ่งเก็บไว้เฉพาะใน `providers.toml` ของชุดเครื่องมือ โหมดอัตโนมัติมีไว้สำหรับสภาพแวดล้อมที่ใช้แล้วทิ้งได้หรืออยู่ใน sandbox เช่น dev container

**การเลือกไม่ใช้มีผลเหนือกว่าเสมอ**: การใส่ `--ask` ในคำสั่งหนึ่ง หรือตั้ง `AGENTKIT_PERMISSIONS=ask` ใน environment หรือในไฟล์ env ของชุดเครื่องมือ จะระงับแฟล็กนั้น แม้คำสั่งเดียวกันจะระบุ `--auto` ก็ตาม เซสชันที่เลือกไม่ใช้จะส่งต่อการเลือกไม่ใช้นั้นไปยังเอเจนต์ที่มันเริ่มขึ้น บนโฮสต์ ให้ตั้งค่าการเลือกไม่ใช้ไว้

แอดออนนี้ไม่เขียนแฟล็กอัตโนมัติใด ๆ และไม่ส่ง `--auto` เลย แอดออนจะส่ง `--ask` เมื่อแผนบันทึกการเลือกไม่ใช้ไว้ แผนที่ให้สิทธิ์ `agent_delegation` บนโฮสต์ถือว่ายอมรับผู้รับมอบหมายที่ทำงานอัตโนมัติซึ่งถูกจำกัดอยู่ใน worktree ของตัวเอง และ worktree ไม่ใช่ sandbox

## สิ่งที่เพิ่มให้กับแผน

ในแผน v7 ที่สัญญาให้สิทธิ์ `agent_delegation` คำสั่ง `execute` สามารถส่งงาน `parallel_safe` ให้ CLI อื่นได้ โดยจะสร้าง git worktree เฉพาะ รัน `ak run` ในนั้นพร้อม timeout และรวบรวมผลลัพธ์ไว้ใน `analysis_results/delegations/` ของแผน ผลลัพธ์เป็นหลักฐานแบบ `asserted` จนกว่า gate runner ของแผนเองจะสังเกตเห็นมัน การยกเลิกผู้รับมอบหมายจะหยุดทั้ง process tree ของมัน

## Agentkit หรือ Herdr

| สถานการณ์ | ใช้ |
|---|---|
| งาน `parallel_safe` ที่มีขอบเขตชัดเจนและประกาศผลลัพธ์ไว้ | Agentkit (headless) |
| งานที่ต้องโต้ตอบ รันนาน หรืออยู่บนเครื่องอื่น | [Herdr](/kit/herdr) (peer ใน pane) |

ทั้งสองใช้ร่วมกันได้ herdr-peers สามารถเปิด peer ใน pane ด้วย environment ที่ `ak env <kind> @profile` พิมพ์ออกมา หากต้องการรันหลาย lane พร้อมกัน ดู [การรันเอเจนต์หลายตัว](/methodology/06-orchestration)

## หมายเหตุ

เป็นแบบเลือกใช้และไม่บังคับเสมอ ค่าของ API key จะไม่ถูกพิมพ์ ไม่ถูกบันทึกใน log และไม่ถูกเขียนลงไฟล์ config ข้อยกเว้นที่มีเอกสารกำกับคือ Cline ซึ่งรับคีย์ผ่าน command line การดึงผลลัพธ์สำหรับ OpenCode, Pi, Cline และ Grok สร้างขึ้นจากเอกสารของผู้ผลิต และยังไม่ได้ทดสอบกับบัญชีจริง ผลลัพธ์ที่ไม่รู้จักจะถอยกลับไปใช้ข้อความดิบ
