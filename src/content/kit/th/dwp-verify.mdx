# dwp-verify

ตรวจสอบความสอดคล้องของ repository และแผนอย่างเป็นกลาง โดยอ่านอย่างเดียว

<CmdVerify lang="th" class="not-prose my-8" />

## สิ่งที่มันทำ

`dwp-verify` ตรวจสอบเชิงกลไกว่า repository เป็น AI-first (สอดคล้องกับ DeepWorkPlan) หรือไม่ และแผนของมันถูกต้องตามรูปแบบหรือไม่ แล้วรายงานผ่าน/ไม่ผ่าน มันไม่เปลี่ยนแปลงสิ่งใด

## วิธีใช้

```
/dwp-verify            # verify the repository
/dwp-verify plan auth  # also verify a specific plan
/dwp-verify all        # repository + every plan
```

## พฤติกรรม

1. ตรวจ repository ทั้ง `AGENTS.md` ที่มีคำสั่งจริงรันได้ การ resolve ของ `CLAUDE.md` หมวดหมู่ใน `docs/` แคตตาล็อก `.agents/` ที่ตรงกับดิสก์ ตัวส่งต่อ `dwp-*` แบบบาง ๆ `.dwp/` และ `tmp/` ที่ถูก gitignore และ skill ที่ resolve ได้
2. ตรวจแผน (เมื่อร้องขอ) ว่าทุก task มี acceptance criteria และ validation gate ความคืบหน้าถูกบันทึกคงอยู่ มี Final Review ที่ถูกบันทึกไว้ครบ (รวมถึงการตรวจความปลอดภัยของมัน) และ task ผูกกลับไปยังเป้าหมาย
3. รายงาน **CONFORMANT** หรือ **NOT CONFORMANT** พร้อมแจกแจงทุกข้อที่ไม่ผ่าน
4. เสนอที่จะบันทึกช่องว่างที่พบเป็น Deep Work Plan โดยไม่แก้ไขแบบเงียบ ๆ

**การตรวจสอบแผนตามรุ่น** ตัวตรวจสอบ provenance ของ repository รองรับมาตรฐาน DWP ปัจจุบัน 7.0.0 แต่การตรวจแผนจะแยกตามรุ่น แผน v6 หรือ v7 ระบุได้จาก contract pointer ใน manifest ของแผน, `contract.json` หรือ revision chain ใน `contracts/` และ `conformance.sh --plan` จะประเมินแผนแบบอ่านอย่างเดียวเทียบกับบันทึกของแผนเอง ได้แก่ ทุก revision ของ contract ต้องผ่านการตรวจสอบ manifest ต้องตรงกับรุ่นของ contract journal ต้องสมบูรณ์ไม่ขาดตอนและถูกต้อง การอนุมัติต้องอ้างอิง contract ที่มีผลอยู่ และ `state.json` ต้องตรงกับ projection ของ journal (snapshot ที่ล้าสมัยเป็นเพียงคำแนะนำและจะถูกสร้างใหม่ ไม่มีการแก้ไขด้วยมือ) การตรวจ lifecycle ของ v5 ใช้กับแผน v5 และรุ่นที่เก่ากว่าเท่านั้น และขั้นตอน finalization ของ v5 จะปฏิเสธแผน v6 หรือ v7 รุ่นต่าง ๆ อยู่ร่วมกันได้และการตรวจสอบจะไม่ย้ายรุ่นของแผนใดเลย
