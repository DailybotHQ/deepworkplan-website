# dwp-status

รายงานสถานะ Deep Work Plan โดยไม่ดำเนินงาน

<CmdStatus lang="th" class="not-prose my-8" />

## สิ่งที่มันทำ

`dwp-status` เป็นแบบอ่านอย่างเดียวอย่างเคร่งครัดตามสัญญา มันสรุปความคืบหน้า ตัวบล็อกที่ยังมีผล checkpoint และกรอบทรัพยากร โดยไม่เปลี่ยนแปลงไฟล์ใดเลย

## วิธีใช้

```
/dwp-status                      # list and summarize all plans
/dwp-status [plan]               # report details for a specific plan
```

## พฤติกรรม

1. **สี่มิติของวงจรชีวิต:** รายงานรูปแบบ (`lite` หรือ `full`) สถานะการทำให้เป็นรูปธรรม (`materializing`, `ready` หรือ `promoting`) การอนุมัติการทบทวน (`pending`, `approved` หรือ `pre_approved`) และความคืบหน้าการดำเนินงาน (`pending`, `in_progress`, `blocked` หรือ `completed`)
2. **ภาพรวมทั้ง repository:** เมื่อเรียกโดยไม่มีอาร์กิวเมนต์ จะแสดงรายการแผนทั้งหมดภายใต้ `.dwp/plans/` พร้อมเปอร์เซ็นต์ความสำเร็จ ตำแหน่งของ task ที่กำลังทำ และสรุปตัวบล็อก
3. **กรอบทรัพยากร:** แสดงตัวนับที่ใช้ไปเทียบกับเพดานในแต่ละมิติที่ติดตาม (`wall_clock`, การลองใหม่, การส่งงาน, ค่าใช้จ่าย, token) และระบุว่าขีดจำกัดถูกบังคับใช้จริงหรือเป็นเพียงคำแนะนำ
4. **การวินิจฉัยตัวบล็อก:** แสดงรายละเอียดตัวบล็อกที่ยังมีผลจาก `state.json.blocked` โดยจัดหมวดตามอนุกรมวิธานการยกระดับมาตรฐาน (ระดับ C1–C7)
5. **การสังเกตการมอบหมายงาน:** สรุปการมอบหมายงานให้ subagent ที่ยังเปิดอยู่และที่เสร็จแล้ว รวมถึงการแลกเปลี่ยนกับ peer ที่บันทึกไว้
