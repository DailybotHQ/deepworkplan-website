# dwp-create

สร้าง Deep Work Plan ใหม่จากเป้าหมายระดับสูง

<CmdCreate lang="th" class="not-prose my-8" />

## สิ่งที่มันทำ

`dwp-create` รับเป้าหมายระดับสูงมาแล้วเปลี่ยนเป็นแผนที่มีโครงสร้าง มันวิเคราะห์เป้าหมาย ถามคำถามเพื่อความชัดเจนหากจำเป็น แยกงานออกเป็น task ตามลำดับ และเขียนไฟล์แผน

## วิธีใช้

```
/dwp-create <goal>
```

## โหมด

`dwp-create` ใช้โหมด **guided** เป็นค่าเริ่มต้น มันรวบรวมบริบท รันการวิเคราะห์ และทำให้แผน Lite เป็นรูปธรรมโดยตรง — ข้อเสนอที่กระชับซึ่งดำเนินการได้อยู่แล้ว ไม่ใช่ฉบับร่างที่ต้องทิ้ง — **แสดงให้คุณดู และถามว่าต้องการเก็บไว้เป็น Lite เลื่อนขั้นเป็นแผน Full แบบแยกไฟล์ต่องาน แก้ไข หรือหยุด** คุณจึงได้อ่านแผนจริงเสมอก่อนตัดสินใจ นี่คือค่าเริ่มต้นที่แนะนำ โดยเฉพาะในไม่กี่ครั้งแรก

ต่อท้ายด้วย **`trust`** (หรือ `auto`) เป็นคำสุดท้ายเพื่อข้ามการทบทวนนี้ agent จะไปยังแผนที่ได้รับการอนุมัติล่วงหน้าและพร้อมใช้งานโดยตรง (Lite หรือ Full เลือกตามสัญญาณเดียวกัน):

```
/dwp-create <goal> trust
```

โหมด trust เป็นทางลัดสำหรับผู้ใช้ระดับสูงเมื่อคุณไว้ใจกระบวนการแล้ว ส่วนโหมด guided คงให้มนุษย์อยู่ในวงรอบการตัดสินใจเป็นค่าเริ่มต้น

## พฤติกรรม
1. วิเคราะห์เป้าหมายและบริบทของ repository
2. ถามคำถามเพื่อความชัดเจนหากคลุมเครือ
3. ทำให้แผนเป็นรูปธรรมโดยตรงภายใต้ `.dwp/plans/PLAN_001_<slug>/` — เป็นแผน Lite โดยค่าเริ่มต้น หรือ Full สำหรับงานที่ใหญ่กว่า (ในโหมด guided ให้ตรวจทานและเลือกว่าจะเก็บไว้เป็น Lite เลื่อนขั้นเป็น Full แก้ไข หรือหยุด)
4. แยกออกเป็น task ตามลำดับ แล้วเขียน README ไฟล์ task และ PROGRESS
5. ปิดท้ายด้วย Final Review (การตรวจความปลอดภัย การตรวจสอบครบวงจรบนสถานะสุดท้าย และการกระทบยอดเรื่อง skill)

แผนใหม่จะได้รับ ID ตัวเลขที่เพิ่มขึ้นตามลำดับและมีอย่างน้อยสามหลัก (เช่น `PLAN_001_add_payment_webhooks/`) สคีมา v5 ที่ตรึงไว้จะนับ ID ตัวเลขเป็นหนึ่งคำ ดังนั้น slug ของ v5 จึงมี 2–4 คำ ส่วน slug ของ v6 มี 2–5 คำ โฟลเดอร์เดิมที่ไม่มีหมายเลข `PLAN_<slug>/` ยังคงอ่านได้และจะไม่มีการเปลี่ยนชื่อ หากมีแผนที่มีหมายเลข `latest` จะหมายถึงแผนที่มี ID ตัวเลขสูงสุด.

## ชื่อแทน

- `dwp:create`
