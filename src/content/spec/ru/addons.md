# Аддоны

> **Область версии:** это сохраненный базовый документ v5.0.0. Текущий стандарт, DWP 7.0.0, также требует применимые расширения `V6_*.md` и `V7_*.md`, перечисленные в [указателе спецификации](/spec). Существующие планы v5 и v6 сохраняют записанные правила.

**Версия 2.1.0.** Аддоны — расширения базовой методологии Deep Work Plan. Семь из восьми опциональны и **никогда не требуются для соответствия** — репозиторий без опциональных аддонов полностью AI-first и соответствует DWP. Каждый опциональный аддон предлагается при онбординге, явно принимается или отклоняется и — при принятии — **согласуется** с существующей настройкой вместо перезаписи. Один компонент — заявленное исключение: начиная со стандарта 2.3.0 **локальный обзор AI Diff Reviewer** входит в обязательный базовый уровень — онбординг его устанавливает, и каждый Final Review его запускает, — тогда как его CI-поверхность остаётся опциональной.

## Контракт аддона

Каждый поставляемый аддон включает четыре обязательных компонента:

| Компонент | Назначение |
|-----------|------------|
| **Spec** | Нормативное описание RFC-2119 того, что предоставляет аддон и что означает «соответствие этому аддону» |
| **Reasoning templates** | Руководства, которые агент заполняет, рассуждая о стеке целевого репозитория — не копипаст |
| **Onboarding hook** | Точка входа `SKILL.md`, которую вызывает поток `onboard` при принятии разработчиком |
| **Validation step** | Чеклист подтверждения корректного применения аддона |

Обнаружение: поток `onboard` перечисляет `skills/deepworkplan/addons/` и представляет каждый аддон как опциональный шаг в **фазе 7b** после базового каркаса.

## Поставляемые аддоны (восемь)

Сегодня поставляются восемь аддонов — семь опциональных плюс обязательный локальный обзор. У каждого есть **страница каталога kit** с пользовательскими деталями и **нормативная спецификация** внутри навыка Deep Work Plan. Четыре из них — devcontainer, Herdr, DeepWorkPlan Vim и Agentkit — тонкие интеграторы, закреплённые по тегу за продуктом с собственным репозиторием и циклом выпусков; каждый продукт работает без Deep Work Plan. Принятый аддон записывается в реестр аддонов `.dwp/config.json` (DWP 7.0.0), который может только предлагать или усиливать — он никогда не блокирует соответствие или план.

### Devcontainer (первый аддон)

Тонкий интегратор [devcontainer-kit](https://github.com/DailybotHQ/devcontainer-kit) (`dck`, закреплён на `v0.1.4`): шаблон Dev Containers, который `dck init` разворачивает в репозитории.

- **Страница kit:** [Devcontainer](/kit/devcontainer)
- **Что добавляет:** лаунчер `dck` (`setup`, `up`, `shell`, `ssh`, `doctor`), базовые образы в вариантах `python-3.13`, `node-24` и `debian`, поставляемые без агентов для программирования (агенты — подключаемый по желанию слой), порты только на loopback, проброс SSH-агента и опциональные машины Herdr для каждого контейнера
- **Поведение:** определяется через `dck doctor --json` (интерфейс 1); `dck init` согласует существующий devcontainer только после принятия его diff и сначала создаёт резервную копию файла — никогда не перезаписывается
- **Когда предлагается:** большинство репозиториев с Docker или сервисами, которым полезен изолированный dev-контейнер

### Dailybot (второй аддон)

Опциональное подключение к **команде Dailybot** разработчика для видимости прогресса агента.

- **Страница kit:** [Dailybot](/kit/dailybot) — полная справка по возможностям
- **Что подключает аддон DWP:** четыре отчёта жизненного цикла плана (kickoff, significant task, blocked, completion) через поднавык dailybot `report`; опциональное детерминированное принудительное применение хуков (`dailybot hook`, CLI `>= 3.9.0`)
- **Парный навык:** установка [DailybotHQ/agent-skill](https://github.com/DailybotHQ/agent-skill) (сейчас **3.23.3**) раскрывает **17 возможностей** — чат в Slack/Teams/Discord/Google Chat, чек-ины, создание форм, Ask AI, kudos, доски и задачи Plan, метки организации, API-ключи на репозиторий (`.dailybot/env.json`), email и др. Аддон DWP подключает только **report**; остальные возможности вызываются через навык Dailybot напрямую
- **Аутентификация:** полностью отложена до навыка Dailybot (`dailybot login` или `DAILYBOT_API_KEY`); этот аддон никогда не хранит учётные данные
- **Ограничение нейтральности по вендору:** базовый DWP имеет **нулевую** зависимость от Dailybot; никогда не устанавливать автоматически для всех
- **Когда предлагается:** разработчик или команда уже используют Dailybot или явно просят отчётность для команды

### Dependency upgrade (третий аддон)

Обновления зависимостей, независимые от менеджера пакетов, пакетные, проверенные, обратимые.

- **Страница kit:** [Dependency upgrade](/kit/dependency-upgrade)
- **Что добавляет:** обнаруживает **реальный** менеджер репозитория (npm/pnpm/yarn + ncu, pip/poetry/uv, cargo, go mod, bundler, composer, …), обновляет пакетами, классифицированными по semver, запускает валидационный gate репозитория после каждого пакета, откатывает неудачи, суммирует без автокоммита
- **Команда:** устанавливает `/lib-upgrade` в `.agents/commands/` только при принятии
- **Когда предлагается:** предлагается для каждого репозитория с объявленными зависимостями; неактивный делегатор `/lib-upgrade` устанавливается под согласием онбординга, если явно не отклонено — установка не запускает никакого обновления

### Design system (четвёртый аддон)

`DESIGN.md`, ограниченный интерфейсной поверхностью, который читает любой coding-агент для согласованного UI, CLI или разговорного вывода.

- **Страница kit:** [Design system](/kit/design-system)
- **Что добавляет:** `docs/DESIGN.md` (со ссылкой из `AGENTS.md`) с до трёх **профилей**, сложенных в один файл: **visual-ui** (токены и компоненты отрисованного UI), **cli-output** (семантические стили терминала, деградация TTY/`NO_COLOR`), **conversational** (голос, анатомия сообщений, рендеринг по платформам с plain-text fallback)
- **Сила профилей:** обнаружение делает предложение обязательным; установка защищена явным согласием как в режиме guide, так и в режиме trust — visual-ui **настоятельно рекомендуется при обнаружении**; cli-output и conversational **рекомендуются при обнаружении, всегда спрашиваются, никогда не применяются автоматически**
- **Когда предлагается:** только при обнаружении пользовательской интерфейсной поверхности — не для чистых библиотек, headless-сервисов или репозиториев только с инфраструктурой

### AI Diff Reviewer (пятый аддон — обязательный локальный обзор, опциональная CI-поверхность)

**[AI Diff Reviewer](https://github.com/DailybotHQ/ai-diff-reviewer)** (marketplace **«AI Diff Reviewer»**) даёт проверке безопасности обязательного Final Review структурированный локальный обзор и опционально блокирует pull request'ы в CI. Начиная со стандарта 2.3.0 **локальный обзор входит в базовый уровень**; опциональна только CI-поверхность. Этот аддон обновляется автоматически при каждом релизе, поэтому показанный ниже тег актуален на момент написания и может отставать от вендорённой копии — источником истины о фактически установленном теге служат собственный `SKILL.md` аддона и его релизы на GitHub. Установка всегда закрепляется за опубликованным тегом, а не за подвижной веткой.

- **Страница kit:** [AI Diff Reviewer](/kit/ai-diff-reviewer) — полный справочник возможностей
- **Обязателен при онбординге (Phase 7a):** закреплённая по тегу установка вендорённого skill (`npx --yes skills add https://github.com/DailybotHQ/ai-diff-reviewer/tree/v3.3.0 --skill ai-diff-reviewer -y`) плюс адаптированный под репозиторий `.review/extension.md` (через `generate-extension`), в рамках согласия онбординга; точечное обновление harness согласует оба элемента, если их нет; отказ фиксируется как заявленное исключение и сообщается `verify` до тех пор, пока элемент не установлен
- **Обязателен в каждом Final Review:** проверка безопасности запускает родительский поток по умолчанию вышестоящего skill по накопленному набору изменений и дописывает его вывод в локальный для плана `analysis_results/SECURITY_REVIEW.md` (внутри собственной папки плана, никогда в корне репозитория); отсутствующий skill или расширение — это зафиксированная находка `local reviewer not installed` — никогда не тихий пропуск и никогда не внезапная установка; установка принадлежит согласию онбординга или явному вызову адд-она; **подтверждённые критические находки** из завершённого прохода блокируют завершение до исправления или явного принятия (v3, BC-07 — неподтверждённые критические утверждения приходят как аннотированные предупреждения, а `incomplete`/`timeout`-обзор не является чистым проходом, BC-04)
- **Опциональная CI-поверхность (Flow B):** `pr-review.yml` (`DailybotHQ/ai-diff-reviewer@v3`) через вышестоящий под-skill `setup` плюс компаньоны `apply-review` (только чтение) и `address-review` (делает коммиты, push и перевзводит обозреватель; новый в v3.1.1) как вызываемые разработчиком удобства — предлагается явно, никогда не устанавливается без запроса, никогда не по умолчанию, никогда не задача плана
- **Никогда не блокирует (только вызов):** локальный обзор, который смог стартовать, но завершился ошибкой, — это предупредить один раз, зафиксировать и продолжить; он никогда не проваливает задачу
- **Паритет (Flow B):** общий `prompt.md` + расширение согласовывает методологию/серьёзность; Iteration-Aware Review в CI может сократить раунды 2+ при полном локальном проходе
- **Нейтральная защита от привязки к вендору:** ни один поток Deep Work Plan не требует коммерческого сервиса, CI-провайдера или секрета — reviewer это закреплённый по тегу skill под лицензией MIT, запускаемый собственным coding-агентом разработчика
- **Соответствие:** `verify` сообщает об отсутствующем локальном reviewer как о провале для репозиториев, объявляющих стандарт 2.3.0 или новее, и как о находке версии harness для устаревших репозиториев

### Herdr (шестой аддон)

Тонкий интегратор [herdr-peers](https://github.com/DailybotHQ/herdr-peers) (закреплён на `v0.1.0`, протокол `1`) — **интерактивный** транспорт делегирования для планов v7.

- **Страница kit:** [Herdr](/kit/herdr)
- **Что добавляет:** план может передать ограниченную задачу агенту для кода в другой панели [Herdr](https://herdr.dev) — на той же машине или на машине, до которой Herdr дотягивается по SSH, — и записать его единственный авторизованный ответ в журнал
- **Поведение:** протокол пиров (штамп, разрешение, ответ, защита от циклов, ограничения глубины и ветвления) живёт в herdr-peers, а не в пакете; любое использование требует разрешения контракта `agent_delegation`, а результат делегата остаётся заявленным, пока его не наблюдает собственный исполнитель плана
- **Когда предлагается:** явный opt-in в фазе 7b; обнаружение `herdr` и `herdr-peers` только для чтения; транспорт доступен только внутри сессии Herdr

### DeepWorkPlan Vim (седьмой аддон)

Тонкий интегратор [DeepWorkPlan Vim](https://github.com/DailybotHQ/deepworkplan-vim) (закреплён на `v0.4.2`, интерфейс `1`) — терминального редактора для Deep Work Plan (Neovim 0.12+).

- **Страница kit:** [DeepWorkPlan Vim](/kit/vim)
- **Что добавляет:** опциональную поверхность редактора на уровне машины для агентов и людей — генерируемый индекс команд, браузер планов только для чтения и просмотрщик Markdown; каждое утверждение считывается из закреплённой машиночитаемой поверхности продукта
- **Поведение:** существующая конфигурация Neovim никогда не перезаписывается без явного согласия; обнаружение только для чтения
- **Когда предлагается:** явный opt-in в фазе 7b; только информационно, если Neovim 0.12+ отсутствует

### Agentkit (восьмой аддон)

Тонкий интегратор [coding-agents-kit](https://github.com/DailybotHQ/coding-agents-kit) (`ak`) — транспорт делегирования **без интерфейса** для планов v7.

- **Страница kit:** [Agentkit](/kit/agentkit)
- **Что добавляет:** единую поверхность команды `ak` над терминальными агентами для кода, используемую для выполнения ограниченной задачи плана без интерфейса; возможности `subagents`, `cancel_children` и `model_routing` предоставляются только во время выполнения — когда аддон включён, обнаружен и интерфейс совместим
- **Поведение:** любое использование требует разрешения контракта `agent_delegation`; аддон никогда сам не устанавливает CLI агентов для кода и никогда не читает значения ключей провайдеров
- **Когда предлагается:** явный opt-in в фазе 7b; обнаружение только для чтения через `ak doctor --json`

## Навыки

Навыки — переиспользуемые процедуры, вызываемые по имени. Навык упаковывает повторяемый workflow (запуск тестов, исправление lint, создание компонента).

Методология поставляет небольшой набор базовых поднавыков. Среди них поднавык **author** позволяет репозиторию **развивать собственный kit**: вызывается через `/skill-create` и `/agent-create`, рассуждает о существующей раскладке и соглашениях `.agents/`, затем создаёт новый навык, агента или тонкий делегатор команд, соответствующий им, и синхронизирует каталог. Тот же поднавык обеспечивает проход сверки skills в Final Review.

Запись kit: [Skill create](/kit/skill-create), [Agent create](/kit/agent-create).

## Агенты

Агенты — специализированные работники с определённой ролью (reviewer, executor, architect). Они живут в `.agents/agents/` и каталогизируются в `.agents/docs/`.

## Аддоны обслуживания

Аддон **dependency-upgrade** (выше) — основной аддон обслуживания. Он рассуждает о реальном менеджере пакетов репозитория, а не предполагает npm, классифицирует обновления по semver, обновляет безопасными пакетами, запускает валидацию после каждого пакета и откатывает любой неудачный пакет.

## Аддон design-system

См. [Design system](/kit/design-system) в разделе поставляемых аддонов. `DESIGN.md` на уровне репозитория отличается от технического проектного документа по фиче: README плана DWP, критерии приёмки задач и валидационные gates уже покрывают проектирование по фичам. Аддон design-system заполняет долговременный, repo-native контекст **интерфейсного** дизайна.

## Пресеты

Пресеты адаптируют DWP к конкретному технологическому стеку (Django, React, Go, Astro + Svelte и др.). Просмотрите [каталог kit](/kit).

## Адаптеры

Адаптеры сопоставляют команды DWP с системой команд конкретного агента (Claude Code, Cursor, Codex, Gemini, Copilot, OpenClaw и др.). Записи адаптеров находятся в kit под именем каждого агента.

## Примеры

Примеры демонстрируют DWP на практике: сравнения до/после, образцовые планы, кейс-стади. См. [Examples](/examples) и [Dogfood this site](/kit/dogfood-this-site).

## Напоминание о соответствии

Репозиторий **ДОЛЖЕН** быть полностью соответствующим с **нулём** аддонов. Аддоны — многоуровневые опциональные возможности, никогда не предпосылки. См. [Conformance](/spec/conformance).
