## Набор Deep Work Plan

Набор — это всё необходимое, чтобы применять методологию на практике. Он устанавливается из
`DailybotHQ/deepworkplan-skill`:

```bash
npx skills add DailybotHQ/deepworkplan-skill@v6.0.2 --skill deepworkplan
```

Текущий пакет 6.x по умолчанию создает новые планы в формате v6. Существующие планы сохраняют записанное поколение; для миграции требуется явный запрос.

### Навык и его под-навыки

Навык Deep Work Plan — это маршрутизатор плюс девять под-навыков:

- **create** — разложить цель в структурированный план (`/dwp-create`).
- **execute** — выполнять план задача за задачей, проверяя каждый gate (`/dwp-execute`).
- **refine** — добавлять, удалять или переупорядочивать задачи, сохраняя завершённую работу (`/dwp-refine`).
- **resume** — восстановить состояние и продолжить прерванный план (`/dwp-resume`).
- **status** — отчитаться о прогрессе, ничего не меняя (`/dwp-status`).
- **verify** — объективно проверить соответствие репозитория и плана (`/dwp-verify`).
- **onboard** — сделать репозиторий AI-first (`/deepworkplan-onboard`).
- **author** — создать или развить собственные навыки, агентов и команды репозитория (`/skill-create`, `/agent-create`).
- **upgrade** — безопасно переводит установленный навык на новый релиз (`/dwp-upgrade`).

### Команды

Тонкие слеш-команды делегируют под-навыкам и дополнениям:

- `dwp-create`, `dwp-execute`, `dwp-refine`, `dwp-resume`, `dwp-status`, `dwp-verify` — цикл «планирование — выполнение — проверка».
- `skill-create`, `agent-create` — делегируют под-навыку author.
- `lib-upgrade` — делегирует дополнению dependency-upgrade (устанавливается, только когда это дополнение принято).

### Адаптеры

Тонкие интеграции для отдельных агентов: Claude Code, Cursor, OpenAI Codex, GitHub Copilot, Google Gemini, OpenCode, Windsurf, Cline, Antigravity, OpenClaw, Hermes и облачных/фоновых агентов (удалённые задачи Claude Code, Codex cloud, агенты класса Jules). OpenClaw и Hermes — автономные агентные платформы, выполняющие планы под профилем автономного выполнения по расписанию heartbeat или cron.

### Пресеты онбординга

Руководства-рассуждения по отдельным стекам, которые процесс onboard использует для адаптации документации, навыков и команд валидации, —
никогда не шаблоны. Шесть пресетов: Django, Vue + Vite, Astro/Svelte, Node/TS service, Python package/CLI
и запасной generic.

### Дополнения (по желанию)

Возможности, которые процесс onboard добавляет в репозиторий. Четыре опциональны и никогда не входят в базовый набор AI-first; локальный обзор AI Diff Reviewer обязателен начиная со стандарта 2.3.0:

- **Devcontainer** — воспроизводимый, изолированный dev-контейнер с устойчивой аутентификацией AI-CLI.
- **Dailybot** — отчётность о прогрессе и вехах по принципу best-effort для команд, использующих Dailybot.
- **Dependency upgrade** — независимые от менеджера пакетов, партийные, проверяемые, обратимые обновления.
- **Design system** — ограниченный поверхностями интерфейса `DESIGN.md` (по пути `docs/DESIGN.md`, на который ссылается `AGENTS.md`), выведенный из реального источника дизайна репозитория, с профилями для визуального UI, стилизованного вывода CLI и диалогового обмена сообщениями, чтобы агенты генерировали фирменный интерфейсный вывод; при обнаружении дизайн-системы предложение обязательно, а установка защищена явным согласием — визуальный профиль настоятельно рекомендуется при обнаружении, профили CLI и диалоговый рекомендуются при обнаружении, и о них всегда спрашивают.
- **AI Diff Reviewer** — обязательный локальный обзор: онбординг устанавливает [AI Diff Reviewer](https://github.com/DailybotHQ/ai-diff-reviewer) v3 + `.review/extension.md`, и проверка безопасности каждого Final Review его запускает; опциональный Flow B добавляет CI-гейт слияния PR, использующий ту же extension, — предлагается явно и никогда не устанавливается без запроса.

### Экосистема

**Методология работает сама по себе. Дополнения её усиливают.** Каждое дополнение — это тонкий интегратор внутри навыка Deep Work Plan, закреплённый по тегу за продуктом с собственным репозиторием, релизом и версией интерфейса. Каждый продукт работает без Deep Work Plan, и ни одно дополнение не обязательно.

- **Навык Deep Work Plan** — Создаёт, выполняет, проверяет, возобновляет и уточняет планы. Не требует дополнений.
- **[herdr](/ru/kit/herdr)** — Пиры в панелях Herdr на любой машине: интерактивное делегирование с одним авторизованным ответом. Закреплено на `herdr-peers@v0.1.0`.
- **[agentkit](/ru/kit/agentkit)** — Одна команда ak для любого терминального агента для кода: делегирование без интерфейса в worktree. Закреплено на `coding-agents-kit@v0.1.1`.
- **[devcontainer](/ru/kit/devcontainer)** — Шаблон Dev Containers и базовые образы, поставляемые без агентов для кода. Закреплено на `devcontainer-kit@v0.1.2`.
- **[vim](/ru/kit/vim)** — Терминальный редактор с браузером планов только для чтения и просмотрщиком Markdown. Закреплено на `deepworkplan-vim@v0.4.0`.

Реестр дополнений и дескрипторы поставляются в бета-версии v7, это пре-релиз: `v7.0.0-beta.1`
