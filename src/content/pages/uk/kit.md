## Набір Deep Work Plan

Набір — це все, що потрібно, щоб запустити методологію на практиці. Він встановлюється з
`DailybotHQ/deepworkplan-skill`:

```bash
npx --yes skills add https://github.com/DailybotHQ/deepworkplan-skill/tree/v7.1.0 --skill deepworkplan -y
```

Поточний пакет 7.x за замовчуванням створює нові плани у форматі v7. Наявні плани зберігають зафіксоване покоління; міграція потребує явного запиту.

### Скіл та його суб-скіли

Скіл Deep Work Plan — це маршрутизатор плюс дев’ять суб-скілів:

- **create** — розкласти мету на структурований план (`/dwp-create`).
- **execute** — виконати план завдання за завданням, перевіряючи кожен gate (`/dwp-execute`).
- **refine** — додати, видалити чи переставити завдання, зберігаючи завершену роботу (`/dwp-refine`).
- **resume** — відтворити стан та продовжити перерваний план (`/dwp-resume`).
- **status** — відзвітувати про прогрес без жодних змін (`/dwp-status`).
- **verify** — обʼєктивно перевірити відповідність репозиторію та плану (`/dwp-verify`).
- **onboard** — зробити репозиторій AI-first (`/deepworkplan-onboard`).
- **author** — створити чи розвинути власні скіли, агенти та команди репозиторію (`/skill-create`, `/agent-create`).
- **upgrade** — безпечно переводить установлений скіл на новий реліз (`/dwp-upgrade`).

### Команди

Тонкі слеш-команди делегують суб-скілам та add-on:

- `dwp-create`, `dwp-execute`, `dwp-refine`, `dwp-resume`, `dwp-status`, `dwp-verify` — цикл план-виконання-перевірка.
- `skill-create`, `agent-create` — делегують суб-скілу author.
- `lib-upgrade` — делегує add-on dependency-upgrade (встановлюється лише тоді, коли цей add-on прийнято).

### Адаптери

Тонкі інтеграції під кожного агента для Claude Code, Cursor, OpenAI Codex, GitHub Copilot, Google Gemini, OpenCode, Windsurf, Cline, Antigravity, OpenClaw, Hermes та хмарних і фонових агентів (віддалені завдання Claude Code, Codex cloud, агенти класу Jules). OpenClaw та Hermes — автономні агентні платформи, що виконують плани під профілем автономного виконання, керованого heartbeat або cron-плануванням.

### Пресети онбордингу

Орієнтири міркування під кожен стек, які потік onboard використовує для адаптації документації, скілів та валідаційних команд —
ніколи не шаблони. Шість пресетів: Django, Vue + Vite, Astro/Svelte, Node/TS-сервіс, Python-пакет/CLI
та загальний запасний варіант.

### Аддони (опційні)

Можливості, які потік onboard нашаровує на репозиторій. Сім із них опційні та ніколи не є частиною AI-first базису; локальний огляд AI Diff Reviewer обовʼязковий починаючи зі стандарту 2.3.0:

- **Devcontainer** — відтворюваний, ізольований dev-контейнер зі стійкою автентифікацією AI-CLI.
- **Dailybot** — найкраще-можливе звітування про прогрес та віхи для команд, що використовують Dailybot.
- **Dependency upgrade** — незалежні від менеджера пакетів, партіями, перевірені, відкочувані оновлення.
- **Дизайн-система** — обмежений інтерфейсними поверхнями `DESIGN.md` (за шляхом `docs/DESIGN.md`, з посиланням з `AGENTS.md`), осмислений із реального джерела дизайну репозиторію, з профілями для візуального UI, стилізованого виводу CLI та розмовних повідомлень, щоб агенти генерували інтерфейсний вивід у стилі бренду; коли виявлено дизайн-систему, пропозиція обовʼязкова, але установка захищена явною згодою — візуальний профіль наполегливо рекомендується при виявленні, а профілі CLI та розмовний рекомендуються при виявленні, і про них завжди запитують.
- **AI Diff Reviewer** — обовʼязковий локальний огляд: онбординг встановлює [AI Diff Reviewer](https://github.com/DailybotHQ/ai-diff-reviewer) v3 + `.review/extension.md`, і перевірка безпеки кожного Final Review його запускає; опціональний Flow B додає CI PR merge gate, що використовує той самий extension, — пропонується явно та ніколи не встановлюється без запиту.
- **[Herdr](/uk/kit/herdr)** — інтерактивне делегування: план передає обмежене завдання агенту для програмування в іншій панелі Herdr і записує його єдину авторизовану відповідь.
- **[DeepWorkPlan Vim](/uk/kit/vim)** — термінальний редактор для Deep Work Plan з індексом команд, переглядачем планів лише для читання та переглядачем Markdown.
- **[Agentkit](/uk/kit/agentkit)** — одна команда `ak` для кожного термінального агента для програмування та headless-делегування обмежених завдань плану.

### Екосистема

**Методологія працює сама по собі. Аддони її посилюють.** Кожен аддон — це тонкий інтегратор усередині скілу Deep Work Plan, закріплений за тегом до продукту з власним репозиторієм, релізом і версією інтерфейсу. Кожен продукт працює без Deep Work Plan, і жоден аддон не є обовʼязковим.

- **Скіл Deep Work Plan** — Створює, виконує, перевіряє, відновлює та уточнює плани. Не потребує аддонів.
- **[herdr](/uk/kit/herdr)** — Peer-агенти в панелях Herdr на будь-якій машині: інтерактивне делегування з однією авторизованою відповіддю. Закріплено на `herdr-peers@v0.1.0`.
- **[agentkit](/uk/kit/agentkit)** — Одна команда ak для кожного термінального агента для програмування: автономія за замовчуванням із можливістю відмови та делегування без інтерфейсу у worktree. Закріплено на `coding-agents-kit@v0.3.0`.
- **[devcontainer](/uk/kit/devcontainer)** — Власний dev-контейнер кожного репозиторію з одного шаблону: агенти через ak, Herdr в обидва боки, без SSH-ключа всередині. Закріплено на `devcontainer-kit@v0.2.1`.
- **[vim](/uk/kit/vim)** — Термінальний редактор із оглядачем планів лише для читання та переглядачем Markdown. Закріплено на `deepworkplan-vim@v0.5.1`.

Реєстр аддонів і дескриптори постачаються в Deep Work Plan v7: `v7.0.0`
