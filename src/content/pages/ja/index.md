## 仕様ファースト、ループで完結。

リポジトリがハーネスとなり、計画は自ら完了まで走り続けます。

Deep Work Plan（DWP）は、AIエージェントとともに複雑なソフトウェア作業を計画し実行するための、オープンで MIT ライセンスの方法論とキットです。インストール方法を選んだり、テンプレートをコピーしたりする必要はありません。init.md のプロンプトをコピーしてエージェントに貼り付けるだけです。

> init.md のプロンプトをコピーして、お使いのコーディングエージェント — Claude Code、Cursor、Codex、またはその他のツール — に貼り付けることで、あらゆるリポジトリを AI-first にします。

- [方法論を読む](/methodology)

## この方法論を支えるもの。

1. **仕様ファースト** — 計画は永続的な信頼できる情報源です。原子タスク、受け入れ基準、そしてエージェントが通過すべき検証ゲート。
2. **リポジトリこそがハーネス** — コンテキスト、ツール、ガードレール、状態は、どのエージェントでも読めるプレーンなファイルとしてリポジトリに置かれます。

3. **Loop engineering** — 計画は最後まで走ります。登録、人間が起動するデーモン、権限を一切加えない催促、フェイルオーバー、そして計画イベント。
4. **計測された効率** — フローごとの指示バイト数を、その方法とともに計測・公開します。トークン削減率をでっち上げることは決してありません。

---

## 問題と答え

短い作業では驚異的な性能を発揮するコーディングエージェント。長期のミッション——移行、新しいサブシステム、数十ファイルに及ぶリファクタリング——を任せると、コンテキストが満杯になり、先の判断は薄れ、数時間の作業が途中で止まります。



コンテキストはエージェントにとって最も貴重な資源です。そのためハーネスは、自身の指示量を抑え、監査しやすく保ちます。指示は段階的に読み込まれ、検証は変更箇所に絞られ、各タスクには作業に必要なコンテキストが与えられます。フローごとの指示量はバイト単位で公開し、その負荷を確認できるようにします。計画も作業に合わせて選べます。範囲の限られた修正には Lite、数時間に及ぶ作業には Full を使います。形式は作業の規模に沿い、焦点と追跡しやすさを保ちます。

## 人間が舵を取る。エージェントが実行する。

「完了」の意味と境界線を決めるのは人です。計画が意図を担い、エージェントが時間を担います。常時の監視も、二十分ごとの修正も不要です。

- あなた：意図、受け入れ基準、レビュー
- エージェント：タスクを一つずつ実行
- 計画：両者を結ぶ契約

[方法論を読む](/ja/methodology)

## エージェントが逸脱できない計画。

長いタスクはどんなモデルのコンテキストを埋め尽くします。詳細は失われ、エージェントはドリフトします。書かれた計画——原子タスク、検証ゲート、再開可能な状態こそが、周回ごとに立ち返る拠り所です。

1. 計画
2. アトミックなタスク
3. 検証ゲート
4. 完了
5. 再開可能な状態

[コアループを見る](/ja/methodology)

## 完了は契約であり、感覚ではない。

各タスクは受け入れ基準と、通過すべき検証を明記します。エージェントが「完了した気分」で終わることはできません。通過するか、タスクは開いたままです。

- テストが通る
- 型チェックが通る
- 受け入れ基準を満たす
- さもなければタスクは未完了のまま

## リポジトリこそが harness です。

- ディスク上の永続的な仕様
- 感覚ではなく検証ゲート

## 計画は最後まで走る。権限は人の手に残る。

Loop engineering は、人間がポーリングしなくても計画を完了させる仕組みです。以下の行はループのリリース済み契約を示します。大半は herdr-peers の契約で、計画キューはパックの契約です。Herdr は任意であり、方法論はそれなしでも機能します。

> 仕様ファーストは何をするかを、ハーネスはどこでするかを、Loop engineering はどう終えるかを示します。

**ループ：** 登録（`lead claim`、リードと継承順） → デーモン（`autopilot --loop`、人間が起動） → 催促（`idle ≥ 5 min`、権限を加えない） → 引き継ぎ（`lead takeover`、最初に到達可能な継承者） → 通知（`plan-event-v1`、人間のコマンドへ） → 完了（`plan_completed`、ゲート通過）。リードレコードを持つすべての開いている計画が、自らの状態が完了を示すまで。



| 契約 | 保証する内容 | 出典（herdr-peers v2.2.0） |
| --- | --- | --- |
| 計画の登録（`herdr-peers lead claim`） | ループが見守る計画には、エポックと継承順を持つリードレコードがあります。最も高いエポックの保持者だけがそのリードとして行動します。 | `skills/herdr-peers/protocol.md` §12 |
| 人間だけが起動（`herdr-peers autopilot start --loop`） | デーモンを起動するのは、自分の言葉で指示した人間だけです。どの問い合わせ、返信、通知も、それを起動、停止したり、その動作を変えたりすることはできません。 | `skills/herdr-peers/autopilot.md` §1 |
| 催促は権限を加えない（`plan_stalled`） | 開いている計画のアイドル状態のリードには、続行を促す固定のプロンプトが一つ届きます。ゲート、停止条件、エスカレーションはこれまでどおり拘束力を持ち、進捗のないプロンプトが3回続くと計画は停滞とマークされます。 | `skills/herdr-peers/autopilot.md` §5.2–5.3 |
| 継承者へのフェイルオーバー（`herdr-peers lead takeover`） | リードがいなくなると、最初に到達可能な継承者に引き継ぎが依頼され、ヘルパーが証拠を改めて確認します。レーンがリードを引き継げるのは、人間が事前に記録した許可がある場合だけです。 | `skills/herdr-peers/autopilot.md` §5.2, §7 |
| 計画イベント（`plan-event-v1`） | 計画が停滞、ブロック、リードの喪失、キューからの開始、または完了に至ると、人間が選んだコマンドが plan-event-v1 オブジェクトを一つ受け取ります。パックにはそのための Dailybot 通知機能が同梱されています。 | `docs/schema/plan-event-v1.json` |
| フリートマップ（`plans-v1` · `fleet-v1`） | 各マシンは自分の計画を plans-v1 として報告し、デーモンはすべてのマシン、エージェント、リポジトリ、計画を網羅する fleet-v1 マップを保持します。fleet ui はそれを読み取り専用で表示します。 | `docs/schema/fleet-v1.json` |
| 計画キュー（`dwp-queue-v1`） | パックがキューを検証して書き込み、デーモンはそれを読み取って待機中の計画を続行します。 | `skills/deepworkplan/shared/queue.py` |
| リードの検証（`herdr-peers lead verify`） | マージ、タグ付け、リリースの前に、リードはすべてのマシンで自分がまだ計画を保持していることを確認します。より新しいリードがいれば拒否され、到達できないマシンがあれば、そのリスクが記録のうえで受け入れられていない限り停止します。 | `skills/herdr-peers/protocol.md` §12 |

決定ブレイン（`--brain`）とリードの任命（`--appoint`）は同じデーモンのオプトインのフラグで、それぞれ人間が有効にします。デーモンがマージ、リリース、サインイン、権限の変更を行うことはありません。

プロバイダーのトークン、コスト、ループ完結の統計は表示していません。それらを計測するタグ付きのソースがまだないため、行がありません。スクリプトが示すバイト数 ÷ 4 のトークン値はラベル付きの推定値であり、計測値ではありません。

## 得られるもの

- リポジトリのルートにある AGENTS.md。実際のスタックとコマンドから推論される。
- 分類された `docs/` とモジュールごとのドキュメント。
- `.claude` から `.agents` へのシンボリックリンクを備えた `.agents/` ディレクトリ（スキル、エージェント、コマンド）。
- すべてのエージェントのために一度インストールされる Deep Work Plan スキル。author サブスキルを含むため、リポジトリは独自のスキル、エージェント、コマンドを育てられ、dependency-upgrade や、あらゆるユーザー向けのインターフェイス面のための design-system アドオンなどのオプトイン式アドオンも備えます。
- gitignore された `.dwp/` フォルダにある、長期にわたる再開可能な計画。方法論そのものにはデーモンも外部状態も必要なく、任意のループデーモンが加えるのは継続性であり、依存関係ではありません。
- マルチエージェント委任とエコシステム 1.0 — 独立したワークツリー、ゲートで検証された証拠、固定されたエコシステムアドオンにより並行エージェントを安全に調整。

## 実行したときに起こること

1. **エージェントが [/init.md](/init.md) を開く** — オンボーディングプロンプトと、そこからリンクされた方法論、仕様、キットを読む。
2. **Deep Work Plan スキルをインストールする** — どのリポジトリでも同一のエンジン。ルーターとそのサブスキル（create、execute、refine、resume、status、verify、onboard、author、upgrade）を、Claude Code、Cursor、Codex、Gemini、Copilot 向けに。
3. **リポジトリを適応させる** — 実際のスタックを推論し（コピー＆ペーストではなく)、AGENTS.md、`docs/`、モジュールごとの README、推論にもとづく `.agents/` キット、そして gitignore された `.dwp/` を書く。リポジトリ自体がハーネスになる。
4. **計画して実行する** — 長期にわたる Deep Work Plan を、明示的な受け入れ基準と検証ゲートに照らしてステップごとに、何時間も自律的に実行する。
5. **人間がループを開始する** — 任意で、Herdr アドオンを使います。エージェントではなく、あなた自身が `herdr-peers autopilot start --loop` を実行します。リードレコードを持つすべての開いている計画が最後まで走り続け、計画が停滞、ブロック、完了したときには通知機能が知らせを受け取ります。

スキルは再利用可能なエンジンであり、どこでも同じやり方でインストールされます。適応されるのはリポジトリ側です。インストールの仕組み（Skills CLI、OpenClaw、または git clone）は、[/init.md](/init.md) プロンプトと[クイックスタート](/quickstart)に記されています。
