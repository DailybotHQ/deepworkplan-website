# Internationalization (i18n)

## Overview

The site ships 17 languages: `en`, `es`, `pt`, `zh`, `ja`, `de`, `fr`, `ko`, `ru`, `it`, `tr`, `id`, `vi`, `hi`, `pl`, `uk`, and `th`. English uses root routes; the other languages use the shared `src/pages/[lang]/` route tree and `/{lang}/` URL prefix.

The active language codes come from `src/lib/translations/*.ts` through `getActiveLanguages()` in `src/lib/i18n.ts`. The content schema derives its language enum from the i18n registry.

## Routing and shared pages

English pages use `src/pages/<route>.astro`; all non-English languages share wrappers under `src/pages/[lang]/`. Both route trees render shared page components from `src/components/pages/`, passing a `Language` value to localized UI and layouts. Do not create a separate route wrapper for each locale.

Agent-friendly Markdown pages live in `src/content/pages/{lang}/` and are emitted by `src/pages/[page].md.ts` and `src/pages/[lang]/[page].md.ts`. Methodology, spec, kit, and changelog content is localized under its collection's language directories; matching documents retain the same English slug across locales.

## Adding a language

Use the [I18N Guide](../I18N_GUIDE.md) and `/add-language` skill for the end-to-end workflow. In brief:

1. Add the locale translation module and register its language metadata and code.
2. Add translated methodology, spec, kit, changelog, and agent-friendly page content where those documents exist.
3. Keep page wrappers shared; do not copy the `[lang]` route tree into locale-specific directories.
4. Run `pnpm run i18n:check`, `pnpm run astro:check`, and the content/build gates required by the change.

All user-facing content changes must preserve parity across the active languages, including Markdown endpoints. Translate titles, descriptions, and body copy while keeping slugs, ordering, and code samples stable unless the source explicitly requires localization.
